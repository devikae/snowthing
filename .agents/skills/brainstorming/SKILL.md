# Brainstorming Ideas Into Designs

Help turn ideas into fully formed designs and specs through natural collaborative dialogue.

Start by understanding the current project context, then ask questions one at a time to refine the idea. Once you understand what you're building, present the design and get user approval.

<HARD-GATE>
Do NOT invoke any implementation skill, write any code, scaffold any project, or take any implementation action until you have presented a design and the user has approved it. This applies to EVERY project regardless of perceived simplicity.
</HARD-GATE>

## Checklist

You MUST follow these steps in order:

1. **Explore project context** — check existing code, docs (`docs/project/project.md`, `AGENTS.md`), and requirements.
2. **Ask clarifying questions** — ask ONE question at a time to understand purpose, constraints, and success criteria.
3. **Propose 2-3 approaches** — provide distinct alternatives with trade-offs, side effects, and your recommended option.
4. **Present design in sections** — show the design step-by-step and get explicit user approval.
5. **Write design doc** — save finalized specs into `docs/specs/` or `docs/study/` when requested.
6. **Transition to implementation plan** — create a structured implementation plan only after explicit user confirmation.
