# 게시판 목록과 글 상세 서버 렌더링 (IKA-67)

## 목표

비로그인으로 볼 수 있는 게시판 목록과 글 본문이 첫 HTML에 들어 있다. JS를 실행하지 않는 검색엔진과 JS를 끈 방문자도 읽을 수 있다. 로그인 사용자 화면 동작은 그대로 둔다.

## 바꾼 페이지

| 페이지 | 서버에서 받는 것 | 브라우저가 이어 받는 것 |
|---|---|---|
| `/posts` 목록 | 지금 주소의 목록 20개, 공지 3개 | 관리자 여부(공지 글쓰기 버튼, 문의 안내) |
| `/posts/[publicId]` 상세 | 비로그인 기준 글(제목, 작성자, 수치, 첨부 사진, 평문 본문) | 글 다시 받기(작성자 여부, 추천 여부, 조회수 반영), 댓글, 내 정보 |

- 목록: `page.tsx`를 서버 컴포넌트로 바꾸고 기존 화면은 `PostListClient.tsx`로 옮겼다. 주소를 API 요청으로 바꾸는 규칙은 `postListQuery.ts` 하나를 서버와 브라우저가 같이 쓴다. 서버가 받은 목록의 요청 문자열이 지금 주소와 같으면 브라우저는 목록을 다시 부르지 않는다. 게시판 탭을 눌러 화면 안에서 이동해도 서버가 새 목록을 받아 넘기므로 같다.
- 상세: 서버가 받은 글로 바로 그리고, 브라우저는 기존처럼 상세를 한 번 더 부른다. 이 요청이 로그인 사용자 전용 값과 조회수 증가를 맡는다.
- 본문: Toast UI 뷰어는 브라우저 전용이라, 뷰어가 뜨기 전까지 마크다운을 평문으로 바꾼 글자(`lib/markdownText.ts`)를 보여 준다. React가 글자로만 넣으므로 HTML이 실행되지 않는다. 뷰어가 그려지면 평문을 치운다.
- 카풀 글: 서버가 받은 글이 카풀이면 서버에서 `/carpool/{id}`로 보낸다(기존에는 브라우저가 이동).

## 결정

- 쿠키를 서버 요청에 넘기지 않는다. 넘기면 작성자 여부 같은 개인 값이 HTML에 섞이고, 나중에 캐시를 붙이면 다른 사람에게 나갈 수 있다.
- 조회수: 서버 요청에는 `viewed_posts=[글ID]` 쿠키를 붙여 백엔드가 조회수를 올리지 않게 한다(기존 `generateMetadata`와 같은 방식). 조회수는 브라우저의 상세 요청에서만 오른다. 봇은 서버 HTML만 받으므로 조회수를 올리지 않는다.
- 캐시: Next 데이터 캐시(`revalidate`)를 쓰지 않고 요청마다 받는다(`no-store`). 글을 쓰거나 고친 뒤 예전 목록이나 본문이 보이면 안 되고, `revalidate`는 실패 뒤에도 예전 성공 값을 계속 돌려준다(IKA-47에서 같은 이유로 미리보기에도 쓰지 않았다).
- 실패 처리: 서버 요청은 2초에서 끊는다. 실패(시간 초과, 5xx, 401)하면 지금처럼 브라우저가 불러온다. 상세에서 서버가 글을 그렸는데 브라우저 요청이 연결 오류나 5xx면 서버가 그린 글을 그대로 둔다. 404와 403(삭제, 임시조치)은 기존처럼 안내로 바꾼다.
- 1:1 문의 목록과 문의 글은 로그인이 필요해 서버에서 받지 않는다.
- 글 ID가 UUID 모양이 아니면 서버 요청을 하지 않는다(쿠키 헤더에 이상한 값이 들어가지 않게).
- 상대 시각(`3분`, `어제`)은 서버와 브라우저 시각이 달라 글자가 어긋날 수 있어 `suppressHydrationWarning`을 붙였다. 조회수 천 단위 표시는 `ko-KR`로 고정했다.

## 판매글은 바꾸지 않음

`/market`, `/market/[publicId]`는 이번에 서버 렌더링하지 않았다.

- 백엔드가 판매글 목록과 상세를 로그인한 사용자에게만 준다(`SecurityConfig`에서 `/api/v1/market-listings/preview`만 공개). 쿠키 없이 서버에서 부르면 항상 401이라 HTML에 넣을 내용이 없다. 운영 목록 API를 비로그인으로 한 번 불러 401(`AUTH_001`)을 확인했다.
- 지금 붙이면 판매글 화면을 열 때마다 반드시 실패하는 백엔드 요청만 하나 늘어난다. 그래서 IKA-61(#107)의 `MarketDetailClient` 구조 위에 얹지 않고 이 PR을 따로 두었다.
- 장터 페이지는 `robots: noindex`라 검색 노출 대상도 아니다.
- 열려면 판매글 조회를 비로그인에게 공개할지(판매자 연락처 노출 범위 포함) 먼저 정해야 한다. IKA-61(판매글 링크 미리보기)도 같은 401을 만나므로 함께 정하는 것이 좋다.

## 남은 것

- 상세 한 번에 백엔드 상세 조회가 서버 렌더 1번, 미리보기 1번(60초 메모리 보관), 브라우저 1번으로 늘었다. 부하가 문제면 서버 렌더와 미리보기를 한 요청으로 합칠 수 있다.
- 댓글은 브라우저에서만 받는다.
