# 카풀 탑승 후기와 신뢰도 표시 (IKA-63)

## 목표

카풀이 끝나면 함께 탄 사람끼리 짧은 후기를 남기고, 카풀 상세 작성자 영역과 내 정보 화면에서 카풀 이력과 좋은 평가를 볼 수 있게 한다.

## 먼저 정해야 했던 것: "같이 탄 사람"

티켓은 기존 카풀의 신청과 수락 모델에서 "같이 탄 사람"을 찾으라고 했지만, 그런 모델은 없다. `004_carpool/README.md`는 "탑승 신청, 승인, 거절, 좌석 예약"을 제외 범위로 두었고, 도메인 모델도 "모집 진행 상태는 별도로 관리하지 않는다"고 적었다. 연락은 외부 연락처와 댓글로 한다.

그래서 후기를 쓸 자격을 정할 최소 모델을 새로 둔다.

| 선택지 | 내용 | 판단 |
|---|---|---|
| A. 탑승 확인 (채택) | 출발 시각이 지난 뒤 탑승자가 "이 카풀 탔어요"를 누르고, 운전자(글 작성자)가 확정하거나 거절한다 | 양쪽이 모두 동의해야 같이 탄 사람이 된다. 출발 전에는 누를 수 없어 예약 기능이 되지 않는다 |
| B. 운전자가 닉네임으로 탑승자를 등록 | 운전자 혼자 정한다 | 운전자가 아무 회원이나 넣어 서로 좋은 후기를 주고받을 수 있다. 등록된 사람이 동의하지 않았다 |
| C. 댓글을 단 회원 | 별도 모델 없음 | 댓글은 문의도 섞여 있어 탔다는 근거가 되지 않는다 |
| D. 신청과 수락(예약) 전체 | 출발 전 신청, 좌석 관리 | 004에서 뺀 범위를 다시 여는 큰 작업이다 |

A는 출발 뒤에만 열리므로 004의 "좌석 예약 없음" 결정과 부딪히지 않는다. 운전자가 가짜 계정을 여럿 만들어 서로 확정하는 것은 막지 못한다. 이건 가입 단계(이메일 인증, 재가입 제한)의 몫으로 둔다.

같이 탄 사람 = 글 작성자(운전자) + `CONFIRMED` 탑승자.

## 데이터 모델

마이그레이션 `database/production/043_migration_carpool_review.sql`. 새 테이블 셋이다.

### carpool_rider (탑승 확인)

| 컬럼 | 설명 |
|---|---|
| `carpool_rider_id` | PK |
| `post_id` | `carpool_detail.post_id` FK |
| `member_id` | 탑승자 |
| `status` | `REQUESTED`, `CONFIRMED`, `REJECTED` |
| `created_at`, `updated_at` | KST |

- UNIQUE (`post_id`, `member_id`): 같은 카풀에 한 번만 요청한다. 거절된 사람이 다시 요청해 운전자를 괴롭히지 못하게 거절 행도 남긴다.
- INDEX (`member_id`, `status`): 회원별 탑승 횟수.
- 확정은 `CONFIRMED` 수가 `passenger_capacity`보다 작을 때만 된다. 동시 확정은 `carpool_detail` 행을 `FOR UPDATE`로 잠가 막는다.
- 결정은 한 번이다. `REQUESTED`만 확정하거나 거절할 수 있다.

### carpool_review (후기)

| 컬럼 | 설명 |
|---|---|
| `carpool_review_id` | PK |
| `post_id` | 카풀 |
| `reviewer_id`, `reviewee_id` | 작성자, 대상 |
| `rating` | `GOOD`(좋았어요), `BAD`(아쉬웠어요) |
| `comment` | 100자 이하, 선택 |
| `created_at`, `updated_at` | KST |

- UNIQUE (`post_id`, `reviewer_id`, `reviewee_id`): 한 카풀에서 한 사람에게 한 번만. 동시 요청도 이 제약이 막고 409로 바꾼다.
- CHECK (`reviewer_id <> reviewee_id`): 본인 후기 금지를 DB에서도 막는다.
- INDEX (`reviewee_id`, `rating`): 회원별 요약.
- 수정과 삭제는 없다. 첫 버전은 "한 번만"을 단순하게 지킨다.

### carpool_review_tag (좋았던 점)

| 컬럼 | 설명 |
|---|---|
| `carpool_review_id` | FK, PK 앞부분 |
| `tag` | PK 뒷부분 |

태그는 `GOOD`에만 붙는다. `ON_TIME`(시간 약속을 잘 지켜요), `KIND`(친절해요), `FAIR_SETTLEMENT`(정산이 깔끔해요), `SAFE_DRIVING`(안전하게 운전해요), `CLEAN_CAR`(차가 깨끗해요). 뒤의 둘은 대상이 운전자일 때만 고를 수 있다. 문자열 한 칸에 쉼표로 넣지 않고 행으로 둔 이유는 요약에서 태그별 개수를 DB가 세게 하기 위해서다.

## 평가 방식과 이유

- **두 단계(좋았어요, 아쉬웠어요)**: 별점 5단계는 사람마다 기준이 달라 3점이 나쁜지 보통인지 읽히지 않는다. 카풀에서 알고 싶은 것은 "다시 타도 되는 사람인가"라서 두 단계로 충분하다.
- **좋았던 점 태그**: 짧은 글을 안 쓰는 사람도 무엇이 좋았는지 남길 수 있고, 요약에서 셀 수 있다.
- **아쉬웠어요에는 태그를 두지 않는다**: "늦었어요", "난폭 운전" 같은 태그는 세면 낙인이 되고, 노쇼 처리와 제재는 이 티켓 범위 밖이다.
- **짧은 글 100자**: 긴 글은 공개 평판처럼 쓰이기 쉽다. 대상 본인에게 전하는 한마디로 둔다.

## 공개 범위 (망신 주지 않기)

| 값 | 누가 보나 |
|---|---|
| 카풀 참여 횟수, 좋았어요 개수, 많이 받은 좋았던 점 상위 3개 | 누구나 (카풀 상세 작성자 영역) |
| 받은 후기 전체 수, 좋았어요 비율 | 본인만 (내 정보) |
| 받은 후기의 평가, 태그, 글 | 본인만. 작성자 이름은 보여 주지 않는다 |
| 누가 탑승했는지 | 그 카풀의 운전자와 확정된 탑승자만 |

- 아쉬웠어요 개수와 비율은 공개하지 않는다. 같은 회원이라도 "좋았어요 12"는 보이고 "아쉬웠어요 3"은 보이지 않는다. 공개 숫자는 좋은 쪽으로만 쌓인다.
- 대신 신뢰도를 판단할 근거로 "카풀 참여 횟수"를 함께 보여 준다. 참여 20회에 좋았어요 2개면 읽는 사람이 스스로 판단할 수 있다.
- 받은 후기에서 작성자를 숨기는 것은 보복을 줄이기 위해서다. 한 카풀에 사람이 적어 짐작할 수는 있다.
- 아무 기록이 없으면 작성자 영역에 아무것도 표시하지 않는다. "후기 0개"도 처음 쓰는 회원에게는 불리한 표시라서다.

## 시간 규칙 (KST)

- 탑승 확인 요청과 후기는 `departure_at` 이후에만 된다.
- 둘 다 출발 후 30일까지만 받는다. 오래 지난 카풀에 뒤늦게 기록을 쌓는 것을 막는다.
- 확정과 거절은 기한을 두지 않는다. 요청이 기한 안에 들어왔으면 운전자가 늦게 처리해도 된다.

## 집계 기준

- 카풀 참여 횟수 = 내가 `CONFIRMED` 탑승자인 카풀 수 + 내가 운전했고 확정된 탑승자가 한 명 이상인 카풀 수.
- 삭제되었거나 숨김(`NORMAL`이 아닌) 카풀의 탑승과 후기는 세지 않는다. 관리자가 가짜 카풀을 지우면 그 기록도 빠진다.

## API

모두 `/api/v1/carpools` 아래에 둔다. 조회는 기존처럼 비회원도 열 수 있고(`GET /api/v1/carpools/**` 허용), 쓰기는 로그인이 필요하다. 봇 위임 토큰은 쓰기를 할 수 없다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/{publicId}/participation` | 내 탑승 상태와 같이 탄 사람 목록 |
| POST | `/{publicId}/riders` | 탑승 확인 요청 (탑승자) |
| POST | `/{publicId}/riders/{memberPublicId}/confirm` | 확정 (운전자) |
| POST | `/{publicId}/riders/{memberPublicId}/reject` | 거절 (운전자) |
| POST | `/{publicId}/reviews` | 후기 작성 |
| GET | `/members/{memberPublicId}/review-summary` | 공개 요약 |
| GET | `/reviews/me` | 내 요약과 받은 후기 (본인) |

### participation 응답

```json
{
  "myStatus": "DRIVER | CONFIRMED | REQUESTED | REJECTED | null",
  "departed": true,
  "reviewOpen": true,
  "confirmedCount": 2,
  "passengerCapacity": 3,
  "members": [
    { "publicId": "...", "nickname": "...", "profileImageUrl": null,
      "role": "DRIVER | RIDER", "status": "CONFIRMED | REQUESTED", "reviewedByMe": false }
  ]
}
```

- `members`는 운전자와 확정된 탑승자에게만 채운다. `REQUESTED`는 운전자에게만 보인다. 그 밖의 사람에게는 빈 배열이다.
- 비회원이면 `myStatus`가 null이다.
- 탈퇴한 회원은 `publicId`가 null이고 닉네임은 `탈퇴한 회원`이다. 후기 대상이 될 수 없다.

### 후기 작성 요청

```json
{ "revieweePublicId": "...", "rating": "GOOD", "tags": ["ON_TIME"], "comment": "다음에도 같이 가요" }
```

### 공개 요약 응답

```json
{ "rideCount": 5, "goodCount": 4, "topTags": [{ "tag": "ON_TIME", "count": 3 }] }
```

### 오류

| 상황 | 상태 | code |
|---|---|---|
| 출발 전 | 400 | `CARPOOL_011` |
| 출발 후 30일 지남 | 400 | `CARPOOL_012` |
| 운전자가 탑승 요청 | 400 | `CARPOOL_013` |
| 이미 탑승 요청함 | 409 | `CARPOOL_014` |
| 탑승 요청 없음 | 404 | `CARPOOL_015` |
| 정원 초과 확정 | 409 | `CARPOOL_016` |
| 같이 타지 않은 사람 | 403 | `CARPOOL_017` |
| 본인 후기 | 400 | `CARPOOL_018` |
| 이미 후기 작성 | 409 | `CARPOOL_019` |
| 태그가 평가나 대상과 맞지 않음 | 400 | `CARPOOL_020` |
| 이미 처리한 탑승 요청 | 409 | `CARPOOL_021` |
| 운전자가 아닌데 확정, 거절 | 403 | `AUTH_002` |

## 화면

### 카풀 상세

- 작성자 이름 아래에 공개 요약을 한 줄로 보인다. 예: `카풀 5회, 좋았어요 4, 시간 약속을 잘 지켜요`. 기록이 없으면 숨긴다.
- 본문 아래 "함께 탄 사람" 영역. 출발 전에는 표시하지 않는다.
  - 로그인한 다른 회원: "이 카풀을 탔어요" 버튼. 요청 뒤에는 "운전자 확인을 기다리고 있어요".
  - 운전자: 요청 목록과 확정, 거절 버튼.
  - 같이 탄 사람: 다른 사람마다 "후기 남기기". 좋았어요와 아쉬웠어요 중 고르고, 좋았어요면 태그, 그리고 짧은 글. 작성한 사람은 "후기를 남겼어요".

### 내 정보 (`/profile`)

"카풀 후기" 영역: 참여 횟수, 받은 후기 수, 좋았어요 비율, 받은 후기 최근 20개(평가, 태그, 글, 카풀 제목, 날짜). 본인만 본다.

공개 프로필 화면은 아직 없어서 다른 회원의 요약은 카풀 상세 작성자 영역에서만 보인다.

## 탈퇴 회원

`025_member_withdrawal` 흐름에 맞춘다.

- 탈퇴한 회원이 남긴 탑승 기록과 후기는 지우지 않는다. 글과 댓글을 남기는 결정과 같고, 회원 행이 익명화되어 있어 개인정보가 아니다. 상대의 참여 횟수와 좋았어요 개수가 탈퇴로 줄지 않는다.
- 탈퇴할 때 처리하지 않은 `REQUESTED` 탑승 요청은 지운다. 운전자 화면에 `탈퇴한 회원`의 요청이 남아 확정되는 일을 막는다.
- 탈퇴한 회원에게는 후기를 쓸 수 없고, 공개 요약은 404다.
- 후기 글(`comment`)은 본문과 같이 남는다. `025` 문서의 "남는 것" 표에 추가한다.

## AI 회원

AI 회원도 일반 회원과 같은 규칙을 따른다. 따로 표시하거나 빼지 않는다.

## 범위 밖

- 노쇼 신고 처리와 제재
- 후기 수정, 삭제, 신고
- 후기 알림
- 공개 프로필 화면
