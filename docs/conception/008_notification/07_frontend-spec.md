# 인앱 알림 프런트엔드 명세

## 1. 표시 조건

- `TopNav`의 회원 조회가 성공한 로그인 상태에서만 알림 종 아이콘을 표시한다.
- 비로그인·세션 만료 상태에서는 종 아이콘, 배지, 알림 요청을 모두 제거한다.
- 기존 프로필·로그아웃 영역 앞에 알림 버튼을 배치한다.

## 2. 종 아이콘과 배지

- 미읽음 0건이면 배지를 숨긴다.
- 1~99건은 실제 숫자를 표시한다.
- 100건 이상은 `99+`로 표시한다.
- 버튼에는 `aria-label="알림, 읽지 않은 알림 N개"`를 제공한다.
- 패널 열림 상태를 `aria-expanded`로 제공한다.

## 3. 알림 패널

- 종 아이콘을 선택할 때 첫 페이지를 조회한다.
- 최신 알림부터 최대 20건을 표시한다.
- 각 항목은 메시지, 게시글 제목, 상대 시각, 미읽음 표시를 가진다.
- `모두 읽음` 버튼을 제공한다.
- 다음 페이지는 `더 보기`로 커서 조회한다.
- 빈 상태는 `새로운 알림이 없습니다.`로 표시한다.
- 로딩 실패 시 패널 안에서 재시도할 수 있다.

## 4. 항목 선택

```text
알림 선택
→ 해당 알림 읽음 처리
→ targetAvailable 확인
→ 가능하면 /posts/{postPublicId} 또는 도메인 상세 경로로 이동
```

카풀 게시글은 `/carpool/{postPublicId}`로 이동한다. 라우팅 결정은 API가 반환한 `targetType` 또는 `targetUrl` 계약 중 구현 전에 하나로 확정하되, 클라이언트가 카테고리 문자열을 임의 해석하지 않도록 한다.

원본을 볼 수 없으면 `삭제되었거나 확인할 수 없는 게시글입니다.`를 표시하고 이동하지 않는다.

## 5. 폴링

- 로그인 확인 이후 미읽음 API를 즉시 한 번 호출한다.
- 기본 30초에 0~5초 무작위 지터를 더해 반복 호출을 분산한다.
- `document.visibilityState !== "visible"`이면 타이머를 중단한다.
- 다시 보이면 즉시 조회하고 새 타이머를 시작한다.
- 로그아웃·컴포넌트 해제 시 타이머와 진행 중 요청을 정리한다.

## 6. 상태 동기화

- 항목 읽음 성공 시 목록 상태와 미읽음 수를 함께 감소시킨다.
- 실패하면 낙관적으로 바꾼 상태를 원복하고 안내한다.
- 모두 읽음 성공 시 현재 로드된 항목을 전부 읽음으로 바꾸고 배지를 숨긴다.
- 다른 탭과의 즉시 동기화는 1차 범위가 아니며 다음 폴링이나 포커스 복귀 때 맞춘다.

## 7. 접근성과 모바일

- 데스크톱 패널은 버튼 기준 팝오버 형태로 표시한다.
- 모바일은 화면 폭에 맞는 패널 또는 하단 시트를 사용하되 같은 데이터 흐름을 공유한다.
- 패널이 열리면 첫 대화형 요소로 포커스를 이동하고 `Escape`로 닫는다.
- 읽음 여부를 색상만으로 구분하지 않고 텍스트 또는 아이콘 상태를 함께 제공한다.
