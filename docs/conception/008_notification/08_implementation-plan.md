# 인앱 알림 구현 계획

## 1단계. 계약과 정책 고정

- 본 설계 문서에 대한 사용자 검토와 승인
- 중고장터 제외 범위 재확인
- API가 `targetUrl`을 반환할지 `targetType`을 반환할지 결정
- ErrorCode 이름과 HTTP 상태 확정

## 2단계. 데이터베이스

- `016_migration_notification.sql` 작성
- `database/ddl.sql` 동기화
- FK, CHECK, UNIQUE, 목록·미읽음·보관 인덱스 검증 스크립트 추가
- 실제 MySQL에서 마이그레이션 적용과 역방향 호환성 확인

## 3단계. 알림 도메인

- `Notification`, `NotificationType` 추가
- Repository 목록·미읽음·소유권 읽음 처리·배치 정리 쿼리 추가
- DTO 컬렉션 방어적 복사 적용
- 문자열 예외 없이 ErrorCode와 커스텀 예외 추가

## 4단계. 댓글 사건 연결

- 댓글 생성 트랜잭션에서 루트 댓글과 대댓글을 구분
- 루트 댓글은 게시글 작성자, 대댓글은 루트 댓글 작성자만 수신자로 계산
- 자기 알림, 회원 수신자 부재, 중고장터 제외 처리
- 댓글 저장·카운트 증가·알림 저장 원자성 테스트

## 5단계. 베스트 사건 연결

- 기존 `PostReactionEvent`와 비동기 로그 리스너 역할 정리
- 실제 LIKE 생성과 잠금 후 결과 카운트 30을 함께 확인
- 게시글당 베스트 멱등 키 UNIQUE 적용
- 동시 추천과 재진입 중복 방지 테스트

## 6단계. REST API

- Controller는 인증 사용자와 DTO만 서비스에 전달
- Service가 Repository를 사용하고 Controller의 Repository 직접 접근 금지
- 목록·미읽음·한 건 읽음·전체 읽음 API 구현
- Entity 직접 반환 금지와 소유권 은닉 404 적용

## 7단계. 프런트엔드

- `NotificationBell` 컴포넌트 분리
- `SiteChrome` 로그인 상태와 연결
- 지터 포함 폴링, 비활성 탭 중단, 포커스 복귀 갱신
- 목록·읽음·모두 읽음·라우팅·오류·빈 상태 구현
- 데스크톱과 모바일 접근성 검증

## 8단계. 보관 작업

- 읽음 30일·미읽음 90일 정리 서비스 구현
- 설정 가능한 배치 크기와 실행 주기 적용
- 제한된 DELETE와 반복 실행 테스트

## 9단계. 검증

- 알림 도메인의 의미 있는 단위·통합·동시성 테스트
- 댓글·추천·카풀·중고장터 회귀 테스트
- 백엔드 전체 테스트와 Spotless
- 프런트엔드 lint와 production build
- MySQL 마이그레이션 검증
- 로그인·로그아웃·세션 만료를 포함한 브라우저 흐름 확인

## 10단계. 멀티 디바이스 작업 절차

```text
작업 시작: git pull --rebase
작업 종료: git status 확인 → commit → push
다른 장비: git pull --rebase
```

동시에 양쪽 장비에서 같은 파일을 수정하지 않는다. `.env`, 로컬 DB, 빌드 산출물은 Git 동기화 대상에 포함하지 않는다.

## 완료 조건

- 승인된 수신자 규칙과 제외 범위가 코드·DB·API·화면·테스트에서 일치한다.
- 대댓글은 루트 댓글 작성자에게만 전달된다.
- 원본과 알림 사이에 부분 커밋이 없다.
- 중복 사건에도 알림이 한 건만 남는다.
- 운영 마이그레이션과 전체 회귀 검증이 통과한다.
