# 인앱 알림 요구사항

## 1. 목적

회원이 자신에게 직접 관련된 댓글·대댓글·베스트 진입을 놓치지 않도록 서비스 내부에서 알린다. 다른 사용자끼리 이어가는 대화나 일반 추천까지 알리지 않아 알림 피로를 제한한다.

## 2. 기능 요구사항

### 2.1. 알림 종류

| 종류 | 발생 조건 | 수신자 |
|---|---|---|
| `POST_COMMENT` | 게시글에 루트 댓글이 생성됨 | 게시글 작성 회원 |
| `COMMENT_REPLY` | 루트 댓글 아래에 대댓글이 생성됨 | 루트 댓글 작성 회원 |
| `POST_BEST` | 게시글 추천 수가 최초로 30에 도달함 | 게시글 작성 회원 |

### 2.2. 댓글 알림

- 루트 댓글은 `parent_id IS NULL`인 댓글이다.
- 게시글 작성자가 회원이면 `POST_COMMENT` 알림을 생성한다.
- 회원이 익명으로 작성한 게시글도 `member_id`가 있으므로 해당 회원에게 알린다.
- 비회원 익명 게시글은 `member_id`가 없으므로 알림을 생성하지 않는다.
- 댓글 작성자와 게시글 작성자가 같으면 자기 알림을 생성하지 않는다.
- 댓글 작성자가 익명이거나 비회원이어도 게시글 작성 회원에게는 일반 문구로 알릴 수 있다.

### 2.3. 대댓글 알림

- 현재 댓글 모델은 모든 대댓글을 루트 댓글 바로 아래에 저장한다.
- 대댓글은 루트 댓글 작성 회원에게만 `COMMENT_REPLY` 알림을 생성한다.
- 게시글 작성자에게는 대댓글 알림을 보내지 않는다.
- 다른 대댓글 작성자에게도 알림을 보내지 않는다.
- 루트 댓글이 비회원 댓글이면 회원 수신자가 없으므로 알림을 생성하지 않는다.
- 대댓글 작성자와 루트 댓글 작성자가 같으면 자기 알림을 생성하지 않는다.

### 2.4. 베스트 알림

- 현재 베스트 기준인 추천 수 30개를 그대로 사용한다.
- `LIKE`가 실제로 새로 생성되어 추천 수가 29에서 30으로 바뀐 순간에만 후보가 된다.
- 추천 취소 후 다시 30에 도달해도 같은 게시글의 베스트 알림은 한 번만 생성한다.
- 게시글 작성자가 없는 비회원 익명 게시글은 알림을 생성하지 않는다.
- 게시글 작성자 본인의 추천으로 임계값에 도달해도 자기 알림은 만들지 않는 정책을 적용한다.
- 일반 추천·비추천·추천 취소는 알리지 않는다.

### 2.5. 조회와 읽음 처리

- 로그인 회원은 최신순으로 자기 알림만 조회할 수 있다.
- 목록은 커서 방식으로 조회한다.
- 미읽음 개수를 별도로 조회할 수 있다.
- 한 건 읽음 처리와 전체 읽음 처리를 지원한다.
- 다른 회원의 알림을 조회하거나 읽음 처리할 수 없다.
- 알림을 선택하면 원본 게시글로 이동한다.
- 원본이 삭제·숨김·차단 상태면 이동을 막고 확인할 수 없다는 상태를 표시한다.

## 3. 1차 지원 콘텐츠

- 일반 게시판 게시글
- 회원 익명 게시글
- 카풀 게시글
- 동호회·시즌방 등 기존 `Post` 기반 공개 게시판

중고장터는 `Post`를 확장하지만 별도 접근 정책을 사용한다. 1차 구현에서는 알림 생성 대상에서 제외하고, 거래 알림과 함께 별도 결정한다.

## 4. 제외 범위

- 이메일 발송
- 브라우저 푸시와 모바일 푸시
- 일반 추천·비추천 알림
- 댓글 수정·삭제 알림
- 카풀 상태·거래 상태 알림
- 라이브톡 메시지 알림
- 사용자별 알림 종류 설정
- 관리자 공지 알림

## 5. 비기능 요구사항

- 댓글·추천 원본은 저장됐지만 알림만 사라지는 상태를 허용하지 않는다.
- 재시도나 중복 이벤트에도 같은 원인으로 알림이 중복 생성되지 않아야 한다.
- 익명 작성자의 실제 회원 정보와 댓글 본문을 알림 응답에 노출하지 않는다.
- 미읽음 개수 조회는 회원의 전체 알림을 스캔하지 않아야 한다.
- 목록 크기는 `1~50`, 기본값은 `20`으로 제한한다.
- 읽은 알림은 30일, 읽지 않은 알림은 90일 보관 후 정리한다.

## 6. 완료 기준

- 세 알림 종류의 생성·미생성 조건이 테스트로 검증된다.
- 대댓글 알림이 루트 댓글 작성자에게만 생성된다.
- 자기 알림과 베스트 중복 알림이 생성되지 않는다.
- 목록·미읽음 개수·한 건 읽음·전체 읽음 API가 인증과 소유권을 검증한다.
- 로그인 상태에서만 헤더 종 아이콘과 알림 목록이 표시된다.
- Mac과 Windows에서 같은 `feature/notification` 브랜치를 통해 작업할 수 있다.
