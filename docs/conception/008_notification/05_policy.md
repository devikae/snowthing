# 인앱 알림 정책

## 1. 수신자 결정

### 루트 댓글

```text
recipient = post.member
```

- `post.member == null`이면 생성하지 않는다.
- 댓글 작성 회원과 수신 회원이 같으면 생성하지 않는다.

### 대댓글

```text
recipient = rootComment.member
```

- 게시글 작성자는 수신자가 아니다.
- 대댓글의 직접 대상처럼 보이는 다른 대댓글 작성자도 수신자가 아니다.
- `rootComment.member == null`이면 생성하지 않는다.
- 대댓글 작성 회원과 루트 댓글 작성 회원이 같으면 생성하지 않는다.

### 베스트

```text
recipient = post.member
condition = reaction changed AND type == LIKE AND resultingLikeCount == 30
```

- 일반 추천과 비추천은 생성하지 않는다.
- 멱등 키 UNIQUE로 게시글당 한 번만 생성한다.

## 2. 익명성

- 회원 익명 게시글의 `member_id`는 수신자 계산에만 사용한다.
- 알림 응답은 댓글 작성자의 실제 회원 ID, 닉네임, IP, 익명 비밀번호를 포함하지 않는다.
- 댓글 본문도 알림 테이블과 응답에 포함하지 않는다.
- 모든 댓글 알림 문구는 작성자 신원을 쓰지 않는 일반 문구를 사용한다.

## 3. 지원 콘텐츠 정책

- 일반 `Post`와 카풀 `Post`는 같은 댓글 이벤트를 사용한다.
- 카풀은 별도 댓글 테이블이 없으므로 중복 구현하지 않는다.
- 중고장터는 인증·연락처·접근 정책이 별도이므로 1차 알림 생성에서 제외한다.
- 향후 중고장터 알림을 추가할 때 거래 상태 알림과 댓글 알림을 함께 결정한다.

## 4. 읽음 정책

- 목록을 열었다는 이유만으로 전체 알림을 자동으로 읽음 처리하지 않는다.
- 알림 항목을 선택할 때 해당 항목을 읽음 처리한다.
- 사용자가 명시적으로 `모두 읽음`을 선택할 수 있다.
- 읽음 처리는 멱등하다.

## 5. 원본 상태 정책

- 게시글이 `NORMAL`이고 삭제되지 않았을 때만 이동 가능하다.
- 게시글이 삭제·숨김·차단되면 알림 행은 유지하고 `targetAvailable=false`로 응답한다.
- 댓글이 삭제돼도 게시글이 공개 상태면 게시글로 이동할 수 있다.
- 알림에서 삭제된 댓글의 본문이나 작성자를 복원하지 않는다.

## 6. 보관과 정리

- 읽은 알림: 생성 후 30일 보관
- 읽지 않은 알림: 생성 후 90일 보관
- 정리 작업은 한 번에 제한된 행만 삭제하고 반복 실행한다.
- 대량 DELETE로 장시간 락과 복제 지연을 만들지 않도록 배치 크기와 실행 주기를 설정으로 분리한다.

## 7. 전달 정책

1차는 REST 폴링이다.

```text
30초 기본 간격 + 0~5초 지터
비활성 탭 폴링 중단
화면 포커스 복귀 시 즉시 조회
로그아웃 시 폴링과 목록 상태 제거
```

실시간 요구가 생기면 SSE는 `NOTIFICATION_CREATED` 무효화 신호만 보낸다. 실제 목록과 읽음 상태는 계속 REST API와 DB를 원본으로 사용한다.

## 8. 동시성과 장애 대응

- 원본과 알림 INSERT는 같은 트랜잭션에 둔다.
- 멱등 키 UNIQUE 위반은 이미 생성된 성공 상태로 취급할 수 있도록 타입 기반 예외로 변환한다.
- 베스트 임계값 판단은 잠금으로 보호된 최신 추천 수를 사용한다.
- 기존 `@Async @EventListener` 로그 이벤트는 알림 저장의 신뢰 경계로 사용하지 않는다.
- 다중 서버와 독립 재시도가 필요해지면 Transactional Outbox를 도입한다.
