# 로컬 보안 점검 범위

승인된 자율 점검 범위 안에서 현재 feature/site-renewal을 대상으로 재현 가능한 결함을 수정한다. 운영 배포·DB·S3·유료 모델 호출은 수행하지 않는다. 기존 설계의 세션 인증, CSRF, 서비스 권한 검사, 회원/공개 게시글/동호회 게시글 분리 원칙을 유지한다.

## 이미지 처리

5MB 제한과 파일 시그니처만으로는 압축된 초대형 이미지의 디코딩 메모리를 제한하지 못한다. 게시글과 프로필의 공통 검증 경로에서 ImageReader로 픽셀 버퍼를 생성하기 전에 가로·세로를 읽고, 한 변 10,000px 및 총 25,000,000픽셀까지만 허용한다. 곱셈은 long으로 계산한다. JPEG/PNG/WebP 파일명·MIME·실제 디코더 형식도 일치시킨다. 제한 초과는 정적 ErrorCode로 반환하며 S3 호출 전에 끝낸다.

이 수치는 제조사 추천이나 보편적인 보안 기준이 아니라 로컬 서비스 정책이다. 25MP 이미지는 픽셀 버퍼만 약 100MB일 수 있고 동시에 여러 변환이 실행되면 추가 메모리가 필요하다. 압축 크기·해상도 검사는 한 요청의 경계이며, 별도 변환 동시성/계정 제한도 검토한다. 고해상도 사진은 사용자가 축소해야 하므로 오류에 제한을 명시한다.

Oracle [ImageReader API](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/javax/imageio/ImageReader.html)의 getWidth/getHeight와 reader 자원 해제를 사용한다. 원본 픽셀을 읽는 ImageIO.read로 사전 검사를 구현하지 않는다.

## 점검 항목

- 인증·CSRF·역할·현재 소속과 부모 리소스 검증, 공개/비공개 응답 분리.
- 업로드 형식·실제 이미지·해상도·요청 제한과 외부 저장 실패.
- 로그인 복귀 경로, 텍스트 렌더링, 작성 도중 데이터 유실, 중복·경합.
- 챗봇의 공개 답변에 개인 정보가 섞이는 경로, 읽기 허용 목록, 위임 토큰·현재 계정 상태, 호출량/큐/시간 제한.
- 가입 동의·개인정보 문서와 실제 처리 사이 차이. 확인하지 못한 운영 사실을 법적 준수 완료로 단정하지 않는다.

완료 증거와 남은 한계는 검증 문서와 docs/project/work.md에 기록한다. 이 목록만으로 전 코드의 무결점 또는 법률 준수를 보증하지 않는다.
