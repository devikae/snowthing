# 시즌 방문 기록과 결산 공유 설계 (IKA-64)

## 목표

- 회원이 리조트를 다녀온 날을 기록한다. 하루에 한 번, 리조트 하나.
- 시즌 결산(총 일수, 리조트별 횟수, 첫 날과 마지막 날, 가장 많이 간 리조트)을 본다.
- 결산을 공유 링크로 보내면 카카오톡, 인스타 등에서 미리보기 카드 이미지가 나온다.

범위 밖: 위치 인증, 랭킹, 친구 결산 비교.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 기록 단위 | (회원, 날짜) 유니크. 하루에 리조트 하나 | 결산의 기본 숫자가 "며칠 탔나"다. 하루에 두 곳을 도는 경우는 드물고, 허용하면 총 일수와 리조트 횟수의 합이 달라져 카드가 헷갈린다. 같은 날 다시 누르는 중복도 DB 제약 하나로 막힌다 |
| 리조트 | 기존 `resort` 마스터(`resort_id`) 재사용. 새 기록은 활성 리조트만 | 설질 제보, 카풀과 같은 목록을 쓴다. 채팅용 `ResortTag` enum은 화면 태그용이라 쓰지 않는다 |
| 시즌 범위 | 11월 1일부터 이듬해 4월 30일. `Season.START`, `Season.END` 상수 | 국내 리조트는 빠른 곳이 11월 중순에 열고 늦은 곳이 4월 초에 닫는다. 앞뒤로 여유를 둔다. 시즌 이름은 시작 연도 기준 `2026-27 시즌` |
| 시즌 밖 날짜 | 기록 거절 (5월부터 10월) | 실내 스키장, 해외 원정은 이번 범위 밖 |
| 미래 날짜 | KST 오늘보다 뒤면 거절 | 계획이 아니라 다녀온 기록이다 |
| 기록 가능한 과거 | 최근 시즌과 그 전 시즌까지 | 시즌 초에 지난 시즌을 뒤늦게 채우는 경우만 허용한다. 오래된 날짜를 무한정 받으면 결산이 의미가 없어진다 |
| 최근 시즌 | 오늘이 시즌 안이면 그 시즌, 5월부터 10월이면 막 끝난 시즌 | 비시즌에 들어와도 지난 결산을 바로 본다 |
| 공개 범위 | 기본 비공개. 회원이 시즌별로 공유를 켰을 때만 공개 | 방문 기록은 언제 어디에 있었는지 알려 주는 정보다. 켜지 않은 결산은 링크를 알아도 안 보인다 |
| 공유 링크 | 시즌별 무작위 공유 토큰(UUID). `/season-log/s/{token}` | 회원 `publicId`를 쓰면 공유를 끈 뒤 다시 켜도 같은 주소라 예전 링크가 되살아난다. 토큰은 끄면 지우고 켜면 새로 만들어 예전 링크가 영구히 죽는다. 다른 시즌 결산도 따로 공개된다 |
| 공개 정보 | 닉네임, 시즌 이름, 총 일수, 리조트별 횟수, 최다 리조트 | 날짜(첫 날, 마지막 날, 날짜 목록)는 공개하지 않는다. 언제 어디 있었는지 드러나기 때문이다. 본인 화면에만 보인다 |
| 공개 대상 회원 | 상태가 `ACTIVE`인 회원만. 정지, 탈퇴 회원 결산은 404 | 탈퇴 회원의 닉네임은 익명화 값이다 |
| 최다 리조트 동률 | 횟수 많은 순, 같으면 리조트 표시 순서(`display_order`), 리조트 ID 순 | 같은 데이터면 늘 같은 결과 |
| 탈퇴 | `season_visit`, `season_share` 행 삭제 | 회원 탈퇴 개인정보 처리 표(025)에 추가 |
| AI 회원 | 구분 없음 | 일반 회원과 같은 규칙 |

### 대안

- **하루 여러 리조트 허용 (회원, 날짜, 리조트 유니크)**: 투어형 라이더를 담을 수 있지만 "총 일수"를 따로 세야 하고 기록 화면이 복잡해진다. 필요해지면 유니크를 바꾸고 일수는 `COUNT(DISTINCT visit_date)`로 바꾼다.
- **공유 상태를 `member`에 컬럼으로**: 시즌 구분이 안 되고 링크 재발급이 안 된다.
- **공개 기본값을 공개로**: 공유 전환 수고는 줄지만 방문 날짜가 의도치 않게 노출될 위험이 크다.

## 데이터 모델 (마이그레이션 044)

```
season_visit
  season_visit_id BIGINT PK
  member_id       BIGINT FK member ON DELETE CASCADE
  resort_id       BIGINT FK resort
  visit_date      DATE        KST 날짜
  created_at      DATETIME(6) KST
  UNIQUE uk_season_visit_member_date (member_id, visit_date)  -- 하루 한 번, 시즌 조회 범위 검색에도 쓴다
  INDEX  idx_season_visit_resort (resort_id)                  -- FK

season_share
  season_share_id   BIGINT PK
  member_id         BIGINT FK member ON DELETE CASCADE
  season_start_year INT          2026 = 2026-27 시즌
  share_token       CHAR(36)     무작위 UUID
  created_at        DATETIME(6)
  UNIQUE uk_season_share_member_season (member_id, season_start_year)
  UNIQUE uk_season_share_token (share_token)
```

## API

| 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|
| GET | `/api/v1/season-logs/me?season=2026` | 회원 | 내 시즌 기록과 결산. `season` 없으면 최근 시즌 |
| POST | `/api/v1/season-logs/me/visits` | 회원, CSRF | `{ "visitDate": "2026-12-06", "resortId": 3 }` → 201 |
| DELETE | `/api/v1/season-logs/me/visits/{visitDate}` | 회원, CSRF | 그 날짜 기록 삭제 → 204 |
| PUT | `/api/v1/season-logs/me/shares/{seasonStartYear}` | 회원, CSRF | 공유 켜기. 이미 켜져 있으면 같은 토큰 → 200 `{ "shareToken": "..." }` |
| DELETE | `/api/v1/season-logs/me/shares/{seasonStartYear}` | 회원, CSRF | 공유 끄기. 토큰 삭제 → 204 |
| GET | `/api/v1/season-shares/{shareToken}` | 공개 | 공유된 결산. `Cache-Control: no-store` |

날짜를 경로에 쓰는 이유: (회원, 날짜)가 유일해서 내부 ID를 노출하지 않아도 기록 하나를 가리킬 수 있다.

### 오류

| 상황 | 상태 | 코드 |
|---|---|---|
| 같은 날짜 기록이 이미 있음 (동시 요청 포함) | 409 | `SEASON_001` |
| 오늘(KST) 이후 날짜 | 400 | `SEASON_002` |
| 시즌 기간 밖 날짜 | 400 | `SEASON_003` |
| 최근 시즌 이전 시즌보다 오래된 날짜 | 400 | `SEASON_004` |
| 지울 기록 없음 | 404 | `SEASON_005` |
| 조회할 수 없는 시즌 (최근 시즌보다 뒤, 2000년 이전) | 400 | `SEASON_006` |
| 공유 토큰 없음, 공유 꺼짐, 정지나 탈퇴 회원 | 404 | `SEASON_007` |
| 비활성 리조트 | 404 | `RESORT_001` |

## 화면

- `/season-log`: 시즌 선택, 오늘 기록(리조트 고르고 버튼 하나), 다른 날 기록(날짜 입력), 이번 시즌 달력(기록한 날 표시, 누르면 삭제), 결산 카드, 공유 켜기/끄기와 링크 복사.
- `/season-log/s/{token}`: 공개 결산 페이지. 검색 제외(`noindex`). `opengraph-image`가 1200x630 카드 이미지를 만든다.
- 진입점: 상단 프로필 메뉴 `내 시즌 기록`, 라이더 도구 목록 카드.

### 카드 이미지

- Next.js `ImageResponse`(`next/og`). 한글 글꼴은 Google Fonts에서 카드 글자만 담은 부분 글꼴을 받아 쓴다(`text=` 파라미터). 글꼴을 못 받으면 기본 카드 이미지로 돌린다.
- 문구는 숫자와 리조트 이름 위주로 담백하게: `2026-27 시즌`, `눈꽃보더 님은 23일 탔어요`, `가장 많이 간 곳 하이원리조트 12일`.

## 검증

- 단위: 시즌 범위 경계(10/31, 11/1, 4/30, 5/1), 최근 시즌 계산, 결산 정렬과 동률.
- 통합: 기록 추가, 같은 날 중복 409, 미래 날짜 400, 시즌 밖 400, 남의 기록 삭제 불가(본인 것만 조회), 공유 끄면 404, 비로그인 401, 공개 응답에 날짜와 이메일 없음, 탈퇴 시 행 삭제, 동시 같은 날짜 요청 하나만 성공.
