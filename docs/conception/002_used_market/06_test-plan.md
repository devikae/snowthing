# 중고장터 테스트 계획

- 문서 번호: `TEST-USED-MARKET-001`
- 상태: Draft

- 기반 문서: `01_requirements.md` ~ `05_access-and-image-policy.md`

## 1. 목적

중고장터는 기존 게시글을 확장하므로 신규 기능만 통과해서는 충분하지 않다. 판매글의 가격·상태 규칙, 회원 전용 접근, 기존 게시판 우회 차단, 댓글 재사용, 이미지 제한, 낙관적 락, 운영 마이그레이션을 함께 검증한다.

## 2. 테스트 환경

| 구분 | 환경 |
|---|---|
| 단위 테스트 | JUnit 5, Mockito |
| Repository·통합 테스트 | MySQL 8.0 Testcontainers 또는 프로젝트 MySQL 테스트 DB |
| Controller 테스트 | Spring MockMvc + Spring Security |
| 프런트엔드 | ESLint, TypeScript, React Testing Library 도입 여부 확인 |
| E2E | 실제 세션·CSRF 쿠키를 사용하는 브라우저 시나리오 |
| 마이그레이션 | `001`~`003` 적용 스키마에 `004` 적용 |

CHECK, FK, 인덱스, MySQL `LIKE`, 낙관적 락 동작은 H2로 대체하지 않는다.

## 3. 도메인 단위 테스트

### 3.1. 가격

| 시나리오 | 기대 결과 |
|---|---|
| 유료 350,000원 | 생성 성공 |
| 유료 1원 | 생성 성공 |
| 유료 0원 | `MARKET_INVALID_PRICE` |
| 유료 음수 | `MARKET_INVALID_PRICE` |
| 유료 20,000,000원 | 생성 성공 |
| 상한 초과 | `MARKET_INVALID_PRICE` |
| 무료 + 0원 | 생성 성공 |
| 무료 + 가격 생략 | 0원으로 정규화 |
| 무료 + 1원 이상 | `MARKET_INVALID_PRICE` |
| 무료 + 가격 협의 | 협의 false로 정규화 또는 입력 거부 중 API 계약대로 검증 |

### 3.2. 상품 상태

- `DAMAGED`도 별도 하자 설명 없이 생성 가능
- 모든 상품 상태에서 본문 공백 입력은 기존 게시글 검증으로 거부
- 상품 상태 Enum 외 문자열 거부

### 3.3. 연락처

- 1자와 30자 허용
- 빈 값, 공백만 입력, 31자 거부
- 앞뒤 공백 제거
- 줄바꿈·NUL 등 제어문자 거부
- 카카오톡 ID, 전화번호, 이메일 형태를 별도 정규식으로 제한하지 않음

### 3.4. 거래 상태

- 신규 판매글은 항상 `ON_SALE`
- `ON_SALE ↔ RESERVED ↔ SOLD` 전환
- 같은 상태 요청은 version 변화 없는 멱등 성공
- 알 수 없는 Enum 거부

### 3.5. DTO 불변성

- Request 생성 뒤 원본 `imageUrls` 목록을 바꿔도 DTO 값이 변하지 않음
- Response의 이미지 목록을 외부에서 수정할 수 없음
- null 이미지 목록은 빈 불변 목록으로 정규화

## 4. 서비스 테스트

### 4.1. 등록

- 로그인 회원이 정상 판매글 등록
- 비로그인 등록 거부
- 비활성 상품 분류 등록 거부
- 존재하지 않는 상품 분류 거부
- 이미지 0장 등록 성공
- 이미지 5장 등록 성공
- 이미지 6장 등록 거부
- 중복 이미지 URL 거부
- 외부 host 이미지 URL 거부
- Post 저장 실패 시 MarketListing과 이미지 롤백
- MarketListing 저장 실패 시 Post와 이미지 롤백
- 생성된 Post가 `MARKET`, 비익명, 회원 작성자인지 확인

### 4.2. 수정 권한

- 작성자 수정 성공
- 다른 회원 수정 `403`
- 관리자의 판매 정보 대리 수정 `403`
- 숨김·차단·삭제 글의 일반 수정 거부
- 비활성 분류로 변경 거부
- 기존 비활성 분류를 유지한 채 다른 값만 수정하는 정책은 구현 계약에 맞춰 검증

### 4.3. 낙관적 락

- 같은 version으로 두 요청이 경쟁하면 하나만 성공
- 실패 요청은 `409 MARKET_LISTING_UPDATE_CONFLICT`
- 충돌한 요청의 Post 제목·본문·이미지도 롤백
- 제목만 수정해도 version 증가
- 이미지만 수정해도 version 증가
- 거래 상태 변경과 전체 수정이 경쟁하면 하나만 성공
- 오래된 상세 화면에서 상태 변경 시 409
- 최신 내용을 다시 조회한 뒤 새 version으로 재요청하면 성공

동시성 통합 테스트는 두 트랜잭션이 같은 version을 읽은 뒤 동시에 커밋하도록 시작 장벽을 둔다. 단순 순차 호출로 낙관적 락을 검증했다고 판단하지 않는다.

### 4.4. 삭제와 관리자 조치

- 작성자 Soft Delete 성공
- 다른 회원 삭제 거부
- 관리자 삭제 성공
- 관리자 숨김·차단·복원 성공
- 일반 회원의 운영 상태 변경 거부
- 삭제 후 목록·검색·상세 제외
- DB의 MarketListing·Comment·PostImage 행은 보존

## 5. Repository 테스트

### 5.1. 목록 상태 행렬

| keyword | tradeStatus 필터 | 포함 상태 |
|---:|---|---|
| 없음 | 없음 | `ON_SALE`, `RESERVED` |
| 있음 | 없음 | `ON_SALE`, `RESERVED`, `SOLD` |
| 없음 | `SOLD` | `SOLD` |
| 있음 | `RESERVED` | `RESERVED` |

모든 조합에서 `HIDDEN`, `BLOCKED`, `DELETED`, `is_deleted = true`는 제외한다.

### 5.2. 필터 조합

- 상품 분류만
- 상품 상태만
- 거래 상태만
- 제목 검색만
- 분류 + 상품 상태
- 분류 + 거래 상태
- 분류 + 상태 + 제목
- 결과 0건
- 비활성 상품 분류의 기존 판매글 검색

### 5.3. 페이징

- 기본 20건
- 최대 50건
- page 1과 마지막 페이지
- page 100 허용, 101은 `MARKET_PAGE_LIMIT_EXCEEDED`로 거부
- 동일 `createdAt`에서 `marketListingId DESC` 순서 고정
- 페이지 사이 중복·누락 없음
- COUNT 쿼리와 목록 쿼리의 필터 조건 일치

### 5.4. 조회 수와 썸네일

- 첫 번째 `sortOrder` 이미지가 썸네일 원본으로 선택됨
- 이미지가 없으면 null
- 목록 조회에서 판매자와 분류 N+1이 발생하지 않음
- 목록 20건 조회의 쿼리 수가 데이터 개수에 비례해 증가하지 않음

## 6. Controller와 보안 테스트

### 6.1. 인증

- 홈 공개 미리보기는 비로그인 요청 `200`
- 공개 미리보기를 제외한 모든 중고장터 API의 비로그인 요청 `401`
- 로그인 회원 목록·상세 `200`
- 세션 만료 후 요청 `401`
- 쓰기 요청의 CSRF 누락·불일치 거부

### 6.2. 우회 경로

- 일반 게시글 생성 API의 `MARKET` 요청 거부
- 일반 게시글 수정 API로 판매글 수정 거부
- 일반 게시글 상세 API로 판매글 조회 시 `404`
- 전체글과 베스트 목록에 판매글 미노출
- 추천 PUT·DELETE 모두 `MARKET_REACTION_NOT_ALLOWED`
- 댓글 목록·대댓글 목록의 비로그인 요청 거부
- 중고장터 익명 댓글 거부

### 6.3. 응답 데이터 최소화

- 홈 공개 미리보기에는 publicId와 thumbnailImageUrl만 포함
- 목록에 연락처 없음
- 상세에 판매자 이메일·출발 지역·내부 ID 없음
- 상세 응답에 `Cache-Control: private, no-store`
- 오류 응답에 연락처·S3 내부 오류·SQL 없음

## 7. 댓글 회귀 테스트

기존 댓글 테스트 전체를 유지하면서 중고장터 조건을 추가한다.

- 루트 댓글 20개 커서 조회
- 루트별 대댓글 Top-5 프리뷰
- 대댓글 분리 API
- 2단계 평탄화
- 루트당 활성 대댓글 100개 제한
- Soft Delete placeholder
- 댓글 수정 낙관적 락
- 관리자 삭제
- 일반 게시글의 기존 비회원·익명 댓글 정책이 중고장터 변경으로 깨지지 않음

## 8. 이미지 테스트

- 기존 JPG·JPEG·PNG·WebP signature 검증
- 5MB 이하 성공, 초과 거부
- 원본과 썸네일 두 객체 생성
- 썸네일 최대 320×320과 JPEG 형식
- 허용된 CloudFront host와 prefix만 판매글 연결
- 이미지 URL 5개 제한
- 목록은 썸네일, 상세는 원본 URL 반환
- 사진 없는 글의 API null과 프런트 기본 이미지 표시
- 이미지 업로드 후 판매글 저장 실패 시 고아 객체가 남는 현재 동작을 알려진 부채로 기록

## 11. E2E 시나리오

### 정상 거래 흐름

```text
회원 로그인
→ 이미지 3장 업로드
→ 판매글 등록
→ 기본 목록에서 최신 글 확인
→ 상세와 연락처 확인
→ 다른 회원 댓글 작성
→ 판매자가 예약 중 변경
→ 판매 완료 변경
→ 기본 목록에서 사라짐
→ 제목 검색에서 판매 완료 글 확인
```

### 사진 없는 무료 나눔

```text
무료 나눔 선택
→ 가격 입력 비활성화
→ 이미지 없이 등록
→ 목록 기본 이미지와 무료 나눔 표시
```

### 충돌

```text
탭 A와 탭 B에서 version 2 조회
→ 탭 A 수정 성공, version 3
→ 탭 B 수정 요청
→ 409 응답
→ 최신 내용 조회 후 사용자가 다시 수정
```

### 권한

```text
비로그인 홈 썸네일 미리보기 200
→ 썸네일 클릭 시 로그인 화면 이동
→ 비로그인 목록 접근 401
→ 로그인
→ 다른 회원 판매글 수정 403
→ 일반 게시글 추천 API로 판매글 추천 400
→ 일반 게시글 상세 경로로 접근 404
```

## 12. 성능 확인

초기에는 기능 정확성을 우선하되 다음 데이터 규모에서 목록 쿼리를 측정한다.

| 단계 | 판매글 수 | 목적 |
|---|---:|---|
| Small | 1,000 | 기본 쿼리와 필터 확인 |
| Medium | 10,000 | COUNT·OFFSET·제목 검색 확인 |
| Large | 100,000 | 100페이지 상한과 인덱스 선택 확인 |

각 단계에서 기본 목록, 상품 분류 필터, 상품 상태 필터, 판매 완료 검색, 제목 부분 검색의 `EXPLAIN ANALYZE`와 평균/p95를 기록한다. 인덱스는 예상만으로 추가하지 않고 실행계획에서 읽은 행 수와 정렬 비용을 비교한다.
