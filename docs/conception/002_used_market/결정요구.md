- 작성일: 2026-09-28
- 최종 검토일: 2026-09-28
- 목적: 중고장터 설계 과정에서 확정한 내용과 나중에 다시 결정할 내용을 한곳에서 관리한다.

## 1. 1차 구현 확정 사항

### 1.1. 하자·수리 설명

**결정: 별도 필드를 두지 않는다.**

- 상품 상태에서 `수리·하자 있음`을 선택해도 `defectDescription` 같은 전용 필드를 추가하지 않는다.
- 판매자가 필요한 내용을 일반 본문에 작성한다.
- 서버는 본문에 하자 내용이 충분히 적혔는지 판별하지 않는다.
- 설명이 부족하면 구매 희망자가 판매자에게 다시 확인한다.

이 방식은 입력 폼과 DB 구조를 단순하게 유지한다. 대신 하자 고지의 충분함을 서비스가 보장하지 않으므로 판매자 책임이라는 점을 화면 안내에 분명히 표시한다.

### 1.2. 가격 상한

**결정: 유료 판매글은 1원 이상 20,000,000원 이하로 제한한다.**

- 무료 나눔은 가격을 0원으로 저장한다.
- 프런트엔드 입력 제한, 요청 DTO 검증, 도메인 검증, DB CHECK를 모두 같은 값으로 맞춘다.
- 20,000,000원을 넘는 요청은 서버에서 거부한다.

### 1.3. 이미지 연결 요청

**결정: 이번 구현에서는 기존 게시글과 같은 `imageUrls` 계약을 유지하고, `imageKey` 전환 여부는 나중에 결정한다.**

- 사진은 선택이며 최대 5장이라는 기존 범위는 유지한다.
- 서버는 허용한 CloudFront host와 `public/posts/originals/` prefix를 검증한다.
- 이미지 기능을 별도로 개선할 때 URL 대신 객체 키를 받는 방식과 저장 경로 분리를 함께 검토한다.

이 항목은 이미지 기능을 구현하기 전에 다시 확인한다. 현재 설계 문서는 기존 계약을 기준으로 작성하되 `imageKey`를 최종안으로 확정하지 않는다.

### 1.4. 비로그인 홈 노출

**결정: 홈에는 로그인 여부와 관계없이 상품 썸네일만 보여준다.**

- 판매 중·예약 중인 최신 글의 썸네일을 최대 4건 표시한다.
- 공개 미리보기 API는 `publicId`와 `thumbnailImageUrl`만 반환한다.
- 제목·가격·상품 상태·거래 상태·판매자·연락처는 공개하지 않는다.
- 비로그인 사용자가 썸네일을 누르면 로그인 화면으로 이동시키고 return URL을 보존한다.
- 로그인 회원이 썸네일을 누르면 판매글 상세로 이동한다.
- 목록·검색·상세 등 실제 중고장터 기능은 계속 로그인 회원에게만 공개한다.

### 1.5. 연락처

**결정: 필수 입력으로 유지하고 앞뒤 공백을 제외한 1~30자로 제한한다.**

- 전화번호, 카카오톡 ID 등 판매자가 원하는 연락 수단을 일반 문자열로 입력한다.
- 서비스가 문자열의 종류나 실제 유효성을 판별하지 않는다.
- 자동 전화 연결이나 외부 앱 링크 변환은 하지 않고 복사 기능만 제공할 수 있다.
- 쪽지 기능이 추가된 뒤에도 외부 연락처는 유지한다.

## 2. 후속 결정 — 이번 구현에서는 확정하지 않음

이 장의 항목은 지금 결정하지 않는다. 관련 기능을 확장할 때 당시 운영 상황과 데이터를 확인한 뒤 다시 논의한다.

### 2.1. 판매 완료 글 보관 기간

**임시 운영안: 자동 삭제 없이 보관**

기본 목록에서는 숨기고 제목 검색이나 판매 완료 상태 필터에서는 조회한다. 판매자 삭제 또는 관리자 삭제 시에만 일반 조회에서 제외한다.

나중에 검토할 선택지는 다음과 같다.

- 영구 보관
- 판매 완료 후 일정 기간 보관
- 일정 기간 후 연락처만 비공개 처리
- 별도 아카이브 테이블 이동

### 2.2. 관리자 조치 사유와 감사 이력

**임시 운영안: 상태 변경만 지원하고 사유·이력 저장은 관리자 도메인으로 미룸**

관리자는 숨김·차단·삭제할 수 있지만 누가 언제 왜 변경했는지를 기록하는 공통 moderation audit는 이번 범위에 포함하지 않는다. 관리자 페이지를 만들 때 게시판과 중고장터가 함께 쓰는 구조로 설계한다.

### 2.3. 고아 이미지 정리

**임시 운영안: 기존 게시글과 같은 방식 유지**

이미지를 업로드한 뒤 판매글 등록을 취소하면 S3 원본과 썸네일이 남을 수 있다. 이미지 기능을 개선할 때 임시 prefix, 업로드 확정 처리, 만료 정리를 함께 검토한다.

### 2.4. 탈퇴 회원의 판매글

**임시 운영안: 기존 회원 탈퇴 정책을 따르고 중고장터에서 별도 처리하지 않음**

회원 탈퇴 기능을 확장할 때 활성 판매글을 자동 판매 완료·숨김 처리할지, 탈퇴 전에 판매글 정리를 요구할지 결정한다. 연락처 잔존 문제도 함께 검토한다.

### 2.5. 이미지 파일까지 회원 전용으로 보호할지

**임시 운영안: 기존 게시판과 같은 공개 CloudFront 이미지 URL 사용**

중고장터 화면·API·연락처는 회원 전용이지만 이미지 URL을 아는 사용자의 파일 단독 접근은 가능하다. 사진 바이트도 회원에게만 공개해야 한다면 별도 private prefix와 Signed URL 또는 Signed Cookie를 검토한다.

## 3. 그 밖의 확정 사항

- 일반 게시글처럼 댓글과 대댓글 지원
- 추천·비추천 미지원
- 사진 선택, 최대 5장
- 상세 화면에 판매자 닉네임과 프로필 이미지 제공
- 거래 방식은 직거래·택배·모두 가능 라디오 버튼
- 거래 장소·배송비는 별도 구조화하지 않음
- 상품 분류는 DB 마스터 데이터로 관리
- 상품 분류: 스노보드, 스키, 바인딩, 부츠, 의류, 보호장비, 액세서리, 시즌권·이용권, 기타
- 상품 상태: 새 상품, 거의 새 상품, 사용감 적음, 사용감 있음, 수리·하자 있음
- 거래 상태: 판매 중, 예약 중, 판매 완료
- 가격 협의와 무료 나눔 제공
- 상품 분류·상품 상태·거래 상태 필터와 제목 검색
- 기본 목록에서 판매 완료 제외, 검색과 판매 완료 상태 필터에서는 포함
- OFFSET 페이지 방식, 기본 20건·최대 50건·100페이지 제한
- 데스크톱 목록형 기본, 앨범형 전환 가능
- 보기 방식은 localStorage 저장
- 모바일 목록형 고정
- 판매글 수정에 낙관적 락 적용
- 관리자 숨김·차단·삭제 가능
- 신고 기능 제외
- 기존 게시글 이미지 원본·썸네일 파이프라인 재사용
