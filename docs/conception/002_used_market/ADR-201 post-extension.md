# ADR-201 중고장터 게시글 1:1 확장 구조

- 상태: Accepted
- 결정일: 2026-09-28
- 대상: `Post`, `Comment`, `PostImage`, `MarketListing`, `MarketCategory`
- 관련 문서: [`01_requirements.md`](./01_requirements.md), [`02_domain-model.md`](./02_domain-model.md)

## 1. 문제

중고장터는 제목·본문·이미지·댓글이라는 게시글 성격과 가격·상품 상태·거래 상태·연락처라는 거래 성격을 함께 가진다. 기존 `Comment`와 `PostImage`는 모두 `Post`를 FK로 참조하므로 완전히 독립된 판매글 테이블을 만들면 댓글과 이미지 기능을 다시 구현하거나 기존 관계를 다형화해야 한다.

반대로 거래 필드를 `post`에 직접 넣으면 일반 게시글마다 사용하지 않는 컬럼이 생기고 `PostService`가 중고거래 규칙까지 책임지게 된다.

## 2. 후보

| 후보 | 구조 | 장점 | 대가 |
|---|---|---|---|
| A | `post`에 거래 컬럼 추가 | 구현이 가장 단순 | 게시판과 거래 규칙 결합, nullable 컬럼 증가 |
| B | 독립 `market_listing`과 전용 댓글·이미지 | 도메인 경계가 선명 | 기존 기능 중복, 개발·검증 범위 증가 |
| C | `Post` + `MarketListing` 1:1 확장 | 댓글·이미지 재사용, 거래 규칙 분리 | 두 엔티티 생명주기와 우회 API 통제 필요 |

## 3. 결정

후보 C를 선택한다.

- `Post`는 콘텐츠와 커뮤니티 기능을 담당한다.
- `MarketListing`은 중고거래 속성과 낙관적 락을 담당한다.
- `MarketCategory`는 상품 분류 마스터 데이터를 담당한다.
- `post_category`에는 내부 식별용 `MARKET` 분류를 추가한다.
- 외부에는 일반 게시글이 아니라 `/api/v1/market-listings` 자원으로 노출한다.

## 4. 동작 방식

판매글 등록 서비스가 `Post`와 `MarketListing`을 같은 트랜잭션에서 만든다. 수정도 두 엔티티를 함께 변경하며, `MarketListing.version`으로 오래된 수정 요청을 거부한다. 댓글과 이미지는 기존 `post_id` 관계를 그대로 사용한다.

일반 게시글의 전체글·베스트·카테고리 목록에서는 `MARKET`을 제외한다. `/api/v1/posts/{publicId}` 일반 상세와 추천 API도 `MARKET` 접근을 거부한다. 그렇지 않으면 회원 전용 접근이나 추천 미지원 정책을 우회할 수 있다.

홈 노출은 예외로 둔다. 공개 미리보기 API는 판매 중·예약 중인 글의 `publicId`와 썸네일만 최대 4건 반환하며 제목·가격·상태·판매자·연락처는 반환하지 않는다. 비로그인 사용자가 썸네일을 누르면 로그인 화면으로 보내고, 로그인 후 해당 상세 주소로 돌아오게 한다.

## 5. 장점

- 검증된 댓글 2단계 구조와 페이징을 그대로 사용한다.
- 원본·썸네일 이미지 관계와 정렬을 재사용한다.
- 일반 게시글 테이블에 거래 전용 컬럼을 추가하지 않는다.
- 향후 쪽지 기능에서 판매글 `publicId`를 참조하기 쉽다.
- 거래 상태와 가격 규칙을 `market` 도메인에 모을 수 있다.

## 6. 대안이 더 적합해지는 경우

독립 Aggregate는 주문, 구매자, 결제, 배송, 분쟁, 판매자 평점이 추가되어 게시글보다 상거래 생명주기가 중심이 될 때 적합하다. `post` 직접 확장은 거래 속성이 한두 개뿐이고 앞으로도 분화 가능성이 없을 때만 적합하다.

## 7. 트레이드오프와 대응

### 두 엔티티의 원자성

한쪽만 저장되면 불완전한 판매글이 된다. 생성·수정·삭제를 전용 서비스의 단일 트랜잭션으로 묶고 DB의 `UNIQUE(post_id)`와 FK로 관계를 보장한다.

### 일반 게시판 우회 노출

`MARKET`이 전체글이나 일반 상세에 섞일 수 있다. 일반 게시글 Repository의 기본 조회 조건에서 `MARKET`을 제외하고, 상세·댓글·추천 서비스에서도 대상 종류를 검증한다.

공개 미리보기 경로는 `GET /api/v1/market-listings/preview` 하나만 정확히 허용한다. 경로 패턴을 넓게 열지 않으며 응답 DTO도 상세·목록 DTO와 분리해 거래 정보가 실수로 공개되지 않게 한다.

### version 소유 위치

버전을 `Post`에 두면 일반 게시글의 추천 카운터와 조회수 변경까지 충돌 범위에 들어간다. 따라서 `MarketListing`에만 version을 둔다. 제목·본문만 수정하는 경우에는 `OPTIMISTIC_FORCE_INCREMENT`로 판매글 버전을 증가시킨다.

### 삭제 생명주기

삭제 여부는 `Post`를 원본으로 사용한다. `MarketListing`에 별도 삭제 플래그를 중복 저장하지 않는다. 물리 삭제와 이미지 객체 정리는 보관 정책이 정해진 뒤 별도로 처리한다.

### 공개 이미지 URL

이미지는 기존 게시판의 공개 CloudFront 경로를 재사용한다. 화면과 API는 회원 전용이지만 URL을 아는 사용자의 이미지 단독 접근은 막지 못한다. 이미지까지 회원 전용으로 바뀌면 prefix 분리와 Signed URL/Cookie를 새 ADR로 결정해야 한다.

## 8. 재검토 조건

- 회원 전용 이미지 바이트 접근까지 강제해야 하는 경우
- 댓글과 이미지를 게시판과 다른 정책으로 운영하는 경우
- 결제·주문·배송이 추가되는 경우
- 판매글과 `Post`의 생명주기가 독립적으로 바뀌는 경우
