# 중고장터 제품 요구사항

- 문서 번호: `REQ-USED-MARKET-001`
- 상태: Draft
- 작성일: 2026-09-28
- 대상 기능: 로그인 회원 전용 중고장터

## 1. 목적

Snowthing 회원이 스키·스노보드 장비를 등록하고 댓글과 외부 연락 수단을 이용해 거래할 수 있는 중고장터를 만든다. 서비스는 판매자와 구매자를 연결하는 게시 공간만 제공하며, 결제·배송·정산·분쟁 중재에는 관여하지 않는다.

## 2. 접근 범위

- 중고장터 목록, 상세, 작성, 수정, 삭제는 로그인 회원만 이용할 수 있다.
- 홈 화면에는 최신 판매글의 썸네일만 비로그인 사용자에게도 노출한다. 제목·가격·상태·판매자·연락처는 제공하지 않는다.
- 홈 썸네일을 클릭하면 비로그인 사용자는 로그인 화면으로, 로그인 회원은 판매글 상세로 이동한다.
- 홈 썸네일 공개 미리보기를 제외한 비로그인 요청은 화면에서 메뉴를 숨기는 데 그치지 않고 백엔드에서도 거부한다.
- 판매글은 익명으로 작성할 수 없다.
- 판매자는 회원 닉네임과 프로필 이미지로 표시한다.
- 이메일, 회원가입 정보, 출발 지역 등 다른 회원 정보는 판매글에 노출하지 않는다.

## 3. 판매글 구성

판매글은 기존 게시글의 제목·본문·댓글·이미지 구조를 사용하고, 중고거래에 필요한 정보는 별도 확장 데이터로 관리한다.

| 항목 | 필수 여부 | 규칙 |
|---|---:|---|
| 제목 | 필수 | 상품을 식별할 수 있는 판매글 제목 |
| 본문 | 필수 | 제품 설명, 하자, 직거래 장소 등 판매자가 알릴 내용 |
| 상품 분류 | 필수 | 정해진 분류 중 하나 선택 |
| 상품 상태 | 필수 | 정해진 상태 중 하나 선택 |
| 거래 방식 | 필수 | 라디오 버튼으로 하나 선택 |
| 거래 상태 | 필수 | 최초 등록 시 `판매 중` |
| 가격 | 조건부 필수 | 무료 나눔이 아닐 때 원 단위 정수 입력 |
| 가격 협의 가능 | 선택 | 체크박스로 표시 |
| 무료 나눔 | 선택 | 선택하면 가격 입력을 비활성화하고 서버에는 0원으로 저장 |
| 연락처 | 필수 | 형식을 구분하지 않는 1~30자 자유 입력값 |
| 이미지 | 선택 | 최대 5장, 표시 순서 유지 |

이미지가 없는 판매글은 등록을 허용한다. 목록과 상세 화면에서는 중고장터 기본 이미지를 대신 표시한다.

## 4. 상품 분류

상품 분류는 `market_category` 마스터 테이블로 관리한다. 화면과 API는 변경되지 않는 `code`를 식별자로 사용하고, 표시명·노출 순서·활성 여부는 DB에서 관리한다. 게시판 종류를 나타내는 `post_category`와 상품 종류를 나타내는 `market_category`는 역할이 다르므로 분리한다.

| 표시명 | 코드 후보 |
|---|---|
| 스노보드 | `SNOWBOARD` |
| 스키 | `SKI` |
| 바인딩 | `BINDING` |
| 부츠 | `BOOTS` |
| 의류 | `APPAREL` |
| 보호장비 | `PROTECTIVE_GEAR` |
| 액세서리 | `ACCESSORY` |
| 시즌권·이용권 | `PASS` |
| 기타 | `OTHER` |

`market_category`는 다음 관리 항목을 가진다.

| 항목 | 설명 |
|---|---|
| `code` | API와 내부 로직에서 사용하는 변경 불가 식별 코드 |
| `name` | 화면에 표시할 분류명 |
| `sort_order` | 작성 폼과 필터의 노출 순서 |
| `is_active` | 신규 판매글에서 선택할 수 있는지 여부 |

기존 판매글의 참조 무결성을 지키기 위해 사용 중인 분류는 물리 삭제하지 않는다. 더 이상 받지 않는 분류는 `is_active = false`로 전환하며, 기존 판매글 조회에서는 당시 분류명을 계속 보여준다.

## 5. 상품 상태

| 표시명 | 코드 후보 | 추가 규칙 |
|---|---|---|
| 새 상품 | `NEW` | 사용하지 않은 상품 |
| 거의 새 상품 | `LIKE_NEW` | 사용 흔적이 거의 없는 상품 |
| 사용감 적음 | `GOOD` | 가벼운 사용 흔적이 있는 상품 |
| 사용감 있음 | `USED` | 눈에 띄는 사용 흔적이 있는 상품 |
| 수리·하자 있음 | `DAMAGED` | 별도 입력란을 추가하지 않으며 필요한 설명은 판매자가 본문에 작성 |

`수리·하자 있음`을 선택해도 하자 설명 전용 필드는 두지 않는다. 본문은 항상 필수지만 서버가 하자 설명의 구체성까지 판단하지 않는다. 설명이 부족하면 구매 희망자가 판매자에게 다시 확인한다.

## 6. 거래 방식

작성 화면에서 다음 세 값 중 하나를 라디오 버튼으로 선택한다.

| 표시명 | 코드 후보 |
|---|---|
| 직거래 | `DIRECT` |
| 택배 | `DELIVERY` |
| 모두 가능 | `BOTH` |

거래 희망 지역, 배송비, 택배사 정보는 별도 필드로 관리하지 않는다. 필요한 조건은 판매자가 본문에 작성하고 당사자끼리 협의한다.

## 7. 거래 상태

| 표시명 | 코드 후보 | 의미 |
|---|---|---|
| 판매 중 | `ON_SALE` | 연락과 거래가 가능한 상태 |
| 예약 중 | `RESERVED` | 거래 상대와 협의 중인 상태 |
| 판매 완료 | `SOLD` | 거래가 끝난 상태 |

- 판매글을 처음 등록하면 `판매 중`으로 시작한다.
- 작성자는 상세 화면에서 거래 상태를 변경할 수 있다.
- 판매 완료 글은 삭제하지 않고 유지한다.
- 기본 목록은 `판매 중`과 `예약 중`을 보여주며, 필터를 사용하면 판매 완료 글도 조회할 수 있다.
- 예약과 판매 완료 처리는 플랫폼이 자동 판단하지 않고 판매자가 직접 변경한다.

## 8. 가격 정책

- 가격은 원 단위 정수로 관리하며 유료 판매글은 1원 이상 20,000,000원 이하로 제한한다.
- 무료 나눔이 아니면 가격을 반드시 입력한다.
- `가격 협의 가능`은 가격과 함께 선택할 수 있다.
- `무료 나눔`을 선택하면 가격은 0원으로 저장하고 가격 협의 가능 여부는 적용하지 않는다.
- 결제, 에스크로, 수수료, 할인 계산 기능은 제공하지 않는다.

## 9. 연락처 정책

- 판매자가 카카오톡 ID, 전화번호 등 원하는 연락 수단을 자유롭게 입력한다.
- 연락 수단의 종류를 별도 필드나 선택값으로 구분하지 않는다.
- 서비스는 입력된 연락처의 소유 여부나 유효성을 확인하지 않는다.
- 연락처는 중고장터 상세 화면에서 로그인 회원에게만 보여준다.
- 앞뒤 공백을 제거한 뒤 1자 이상 30자 이하만 허용한다.
- 연락처에는 HTML을 허용하지 않고 일반 문자열로만 저장·출력한다.
- 거래 희망 지역과 배송 조건은 연락처 필드에 구조화하지 않는다.

## 10. 댓글과 추천

- 기존 게시글 댓글과 대댓글 기능을 판매글에서도 사용한다.
- 댓글 작성자도 로그인 회원으로 제한한다.
- 중고장터에서는 추천과 비추천을 제공하지 않는다.
- 일반 게시글 추천 API를 통해 중고장터 글에 반응을 남기는 우회 요청도 서버에서 거부해야 한다.

## 11. 목록과 검색

- 기본 정렬은 최신 등록순이다.
- 목록은 1부터 시작하는 OFFSET 페이지 방식으로 조회한다.
- 기본 페이지 크기는 20건, 최대 크기는 50건이며 최대 100페이지까지 조회할 수 있다.
- 100페이지를 넘는 데이터 탐색은 검색과 필터를 사용한다. 운영 데이터가 늘어 OFFSET 비용이 문제가 되면 커서 API를 별도로 추가한다.
- 제목 검색을 제공한다.
- 상품 분류, 상품 상태, 거래 상태 필터를 제공한다.
- 초기 범위에는 가격 범위 검색과 가격순 정렬을 넣지 않는다.
- 목록 카드에는 최소한 이미지, 제목, 가격 또는 무료 나눔 표시, 상품 분류, 상품 상태, 거래 상태, 판매자 닉네임, 등록 시각을 보여준다.
- 검색어나 거래 상태 필터가 없는 기본 목록에서는 `판매 완료` 글을 제외한다.
- 제목 검색 결과에는 `판매 완료` 글도 포함한다. 판매 완료 표시는 결과에서 분명하게 구분한다.
- 거래 상태를 `판매 완료`로 지정한 필터 조회도 허용한다.

### 11.1. 데스크톱 보기 방식

- 데스크톱에서는 `목록형`과 `앨범형`을 토글할 수 있다.
- 보기 방식을 바꿀 때 서버에서 다시 조회하지 않는다. 같은 목록 응답을 화면에서 다르게 배치한다.
- 목록 응답에는 첫 번째 이미지의 썸네일 URL을 포함한다.
- 사진이 없는 판매글은 두 보기 방식 모두 중고장터 기본 이미지를 사용한다.
- 최초 진입의 기본 보기는 목록형이다.
- 사용자는 데스크톱에서 앨범형으로 전환할 수 있다.
- 사용자가 선택한 보기 방식은 브라우저 `localStorage`에 저장하고 다음 방문에도 적용한다.

### 11.2. 모바일 보기 방식

- 모바일에서는 목록형만 제공한다.
- 앨범형 토글은 모바일 화면에 노출하지 않는다.
- 데스크톱에서 앨범형을 저장했더라도 모바일 화면은 해당 값을 무시하고 목록형으로 고정한다.

## 12. 서비스가 관여하지 않는 범위

다음 기능은 중고장터 1차 범위에서 제외한다.

- 서비스 내부 결제와 에스크로
- 배송 접수와 배송 추적
- 직거래 장소 관리
- 배송비 계산
- 가격 제안과 경매
- 구매 확정과 정산
- 거래 후기와 판매자 평점
- 찜 기능
- 신고·분쟁 중재 자동화
- 서비스 내부 쪽지 연결

쪽지 기능을 개발한 뒤에는 판매글 연락 방식과 연결할 수 있지만, 이번 설계에서는 선행 구현하지 않는다.

## 13. 합의한 기술 방향

- 기존 `Post`가 제목, 본문, 작성자, 댓글, 이미지 생명주기를 담당한다.
- 중고거래 전용 정보는 `Post`와 1:1 관계인 별도 확장 엔티티로 관리한다.
- `Post` 테이블에 중고거래 전용 컬럼을 직접 추가하지 않는다.
- 중고장터 생성·수정·삭제는 전용 API와 서비스에서 하나의 트랜잭션으로 처리한다.
- 일반 게시글 API로 중고장터 데이터를 만들거나 정책을 우회하지 못하게 한다.
- 이미지 저장과 썸네일 생성은 기존 게시판 방식을 재사용하며, 접근 범위 차이는 아래 정책에 명시한다.

### 13.1. 이미지 재사용 범위

- 중고장터 이미지도 기존 `post_image` 관계를 사용한다.
- 파일당 최대 5MB, JPG·JPEG·PNG·WebP 허용 규칙을 그대로 적용한다.
- 원본과 최대 320×320 JPEG 썸네일을 함께 만들고, 상세에는 원본 URL, 목록에는 썸네일 URL을 반환한다.
- S3 원본은 비공개 상태를 유지하고 CloudFront URL로 조회한다.
- 별도의 Signed URL 또는 Signed Cookie는 이번 범위에 넣지 않고 기존 게시판 이미지 전달 방식을 그대로 사용한다.
- 이에 따라 중고장터 화면과 API는 로그인 회원 전용이지만, 발급된 CloudFront 이미지 URL 자체는 공개 URL이다. URL을 알고 있는 비회원의 이미지 단독 접근까지 차단하지는 않는다.

## 14. 수정 충돌 정책

판매글 수정에는 낙관적 락을 적용한다. 공동 편집 기능은 없지만 작성자가 여러 브라우저, 기기 또는 탭에서 같은 판매글을 열 수 있으므로 오래된 화면의 저장 요청이 최신 내용을 덮어쓰지 않게 한다.

- 중고거래 확장 엔티티에 `version` 필드를 둔다.
- 상세 조회 응답과 수정 요청에 현재 `version`을 포함한다.
- 요청 버전과 DB 버전이 다르면 수정을 반영하지 않고 `409 Conflict`를 반환한다.
- 제목·본문·이미지만 수정하고 중고거래 전용 값이 같더라도 버전을 증가시켜야 한다.
- 거래 상태만 변경하는 요청에도 같은 버전 검사를 적용한다.
- 충돌이 발생하면 서버가 두 변경 내용을 임의로 합치지 않는다. 클라이언트는 최신 판매글을 다시 불러오고 사용자가 내용을 확인하도록 안내한다.

## 15. 관리자 운영 권한

- `ROLE_ADMIN`은 판매글을 숨김, 차단, 삭제할 수 있다.
- 판매자가 삭제한 글과 관리자가 삭제한 글은 물리 삭제하지 않고 상태와 삭제 시각을 남긴다.
- 일반 회원은 본인이 작성한 판매글만 수정하거나 삭제할 수 있다.
- 신고 접수와 신고 처리 기능은 이번 범위에서 제외한다.
