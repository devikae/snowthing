# 중고장터 화면 설계

- 문서 번호: `UI-USED-MARKET-001`
- 상태: Draft
- 작성일: 2026-09-28
- 기반 문서: [`01_requirements.md`](./01_requirements.md), [`04_api-spec.md`](./04_api-spec.md)

## 1. 화면 원칙

중고장터는 현재 Snowthing의 카드 모서리, 테두리, 네이비·하늘색 강조, 라이트·다크 테마를 그대로 사용한다. 쇼핑몰처럼 과도한 배너와 색상을 추가하지 않고 상품 사진, 제목, 가격, 거래 상태가 먼저 보이도록 구성한다.

- 데스크톱 기본 보기는 목록형
- 사용자가 앨범형으로 전환 가능
- 모바일은 목록형 고정
- 사진이 없어도 판매글 등록 가능
- 연락처는 상세 화면에만 표시
- 추천 UI 없음
- 댓글은 기존 게시글 상세 컴포넌트를 재사용

## 2. 라우트

| 화면 | Route | 인증 |
|---|---|---|
| 목록·검색 | `/market` | 로그인 |
| 판매글 작성 | `/market/new` | 로그인 |
| 판매글 상세 | `/market/{publicId}` | 로그인 |
| 판매글 수정 | `/market/{publicId}/edit` | 작성자 |

비로그인 사용자가 URL로 직접 접근하면 로그인 화면으로 이동시키되, 로그인 후 원래 요청한 주소로 돌아올 수 있도록 return URL을 보존한다. 실제 데이터 요청은 백엔드의 401 응답으로 다시 보호한다.

## 3. 전역 메뉴와 홈

### 상단 메뉴

게시판 드롭다운과 별도로 `중고장터` 진입점을 둔다. 중고장터를 일반 게시판 카테고리처럼 `/posts` 아래에 넣지 않는다.

### 홈 중고장터 위젯

- 로그인 여부와 관계없이 최신 판매 중·예약 중 글의 썸네일만 최대 4건 표시
- 제목·가격·상태·판매자·연락처는 홈 위젯에 표시하지 않음
- 비로그인 사용자가 썸네일을 클릭하면 로그인 화면으로 이동
- 로그인 회원이 썸네일을 클릭하면 판매글 상세로 이동
- `더보기`: `/market`
- 사진이 없으면 기본 이미지
- 판매 완료 글은 홈 위젯에서 제외

현재 정적 예시 데이터는 실제 API 연결 시 제거한다.

## 4. 목록 화면

### 4.1. 상단 구조

```text
중고장터                                      판매글 등록

[제목 검색________________] [검색]
[상품 분류] [상품 상태] [거래 상태]          [목록형] [앨범형]
```

- 검색과 필터는 URL query parameter에 반영한다.
- 보기 방식만 `localStorage`에 저장하며 URL에는 넣지 않는다.
- 검색·필터 변경 시 1페이지로 이동한다.
- 필터 초기화 버튼을 제공한다.
- 최신순 고정이므로 정렬 드롭다운은 두지 않는다.

### 4.2. 목록형

한 행에 다음 정보를 표시한다.

```text
[썸네일] [판매중] 2425 데크 판매합니다
          스노보드 · 사용감 적음 · 직거래/택배
          휘팍보더 · 댓글 4 · 20분 전             350,000원 협의 가능
```

- 썸네일은 고정 비율과 크기를 사용한다.
- 제목은 한 줄 말줄임한다.
- 가격은 오른쪽에서 식별되도록 배치한다.
- 무료 나눔은 숫자 0원 대신 `무료 나눔`으로 표시한다.
- 판매 완료 검색 결과에는 흐린 처리만 하지 말고 `판매 완료` 텍스트 배지를 표시한다.
- 판매자 프로필 이미지는 목록 밀도를 해치므로 생략하고 닉네임만 표시한다.

### 4.3. 앨범형

카드는 사진을 상단에 크게 두고 아래에 상태, 제목, 가격, 판매자, 시간을 표시한다.

```text
┌─────────────────────┐
│      썸네일          │
├─────────────────────┤
│ 판매중 · 스노보드    │
│ 2425 데크 판매합니다 │
│ 350,000원            │
│ 휘팍보더 · 20분 전   │
└─────────────────────┘
```

- 데스크톱 가용 폭에 따라 3~4열
- 좁은 태블릿 구간은 2열
- 모바일 breakpoint에서는 카드 그리드를 렌더링하지 않고 목록형으로 전환
- 원본이 아니라 320px 썸네일 사용

### 4.4. 보기 방식 저장

- localStorage key: `snowthing:market:view`
- 값: `list` 또는 `album`
- 값이 없거나 손상됐으면 `list`
- 모바일에서는 저장값을 읽더라도 `list` 렌더링
- 다시 데스크톱으로 들어오면 저장된 앨범형 선택을 복원

SSR 단계에서는 브라우저 저장소를 읽을 수 없다. 초기 HTML은 목록형으로 렌더링하고 hydration 이후 데스크톱에서만 저장값을 적용한다. 레이아웃이 크게 튀지 않도록 보기 전환 영역의 크기를 고정한다.

### 4.5. 페이지 이동

- 페이지 번호, 이전, 다음 제공
- 현재 페이지 표시
- 검색·필터 query 유지
- 100페이지 이후 요청은 검색을 안내
- 빈 결과는 필터 초기화와 판매글 등록 버튼을 함께 제공

## 5. 판매글 작성·수정

### 5.1. 폼 구성

```text
중고장터 판매글 작성

상품 분류      [드롭다운]
상품 상태      [드롭다운]
거래 방식      ( ) 직거래  ( ) 택배  ( ) 모두 가능

제목           [________________________________]
가격           [____________원] [ ] 가격 협의 가능 [ ] 무료 나눔
연락처         [________________________________]

본문           [Markdown/WYSIWYG Editor]
사진           [0/5 업로드 영역]

[취소]                                          [판매글 등록]
```

### 5.2. 동작 규칙

- 무료 나눔을 선택하면 가격과 가격 협의 입력을 비활성화한다.
- 무료 나눔을 해제하면 사용자가 가격을 새로 입력하게 한다.
- 유료 가격은 1원 이상 20,000,000원 이하로 제한한다.
- 연락처는 필수이며 앞뒤 공백을 제외하고 최대 30자다.
- 상품 상태가 `수리·하자 있음`이어도 별도 설명 입력란을 추가하지 않는다. 판매자가 필요한 내용을 본문에 작성한다.
- 사진은 0~5장이고 드래그 또는 버튼으로 순서를 변경할 수 있다.
- 업로드 중에는 제출을 막는다.
- 업로드 실패 파일과 성공 파일을 구분해 다시 시도할 수 있게 한다.
- 수정 화면은 상세 응답의 `version`을 보관해 PUT 요청에 포함한다.

### 5.3. 충돌 처리

수정 요청이 `409 MARKET_LISTING_UPDATE_CONFLICT`를 받으면 자동 덮어쓰기를 하지 않는다.

```text
다른 화면에서 판매글이 먼저 수정되었습니다.
최신 내용을 다시 불러온 뒤 변경 내용을 확인해 주세요.

[작성 내용 유지] [최신 내용 불러오기]
```

사용자의 작성 내용을 즉시 버리지 않는다. 최신 내용을 불러오기 전에 현재 폼 값을 메모리에 유지해 사용자가 비교할 수 있도록 한다. 자동 병합은 하지 않는다.

## 6. 상세 화면

### 6.1. 정보 순서

1. 거래 상태와 상품 분류
2. 제목
3. 가격·가격 협의·무료 나눔
4. 이미지 갤러리
5. 상품 상태·거래 방식
6. 본문
7. 판매자 닉네임·프로필 이미지
8. 연락처
9. 댓글

판매자 연락처는 복사 버튼을 제공할 수 있지만 자동으로 전화나 외부 앱을 실행하지 않는다. 자유 입력 문자열이므로 `tel:` 또는 카카오톡 링크로 임의 변환하지 않는다.

### 6.2. 작성자 동작

- 판매 중·예약 중·판매 완료 상태 변경
- 수정
- 삭제

상태 변경은 전체 수정 화면으로 이동하지 않고 상세에서 수행한다. 변경 요청에는 현재 version을 넣고 성공 응답의 새 version으로 화면 상태를 갱신한다.

### 6.3. 이미지

- 첫 이미지 크게 표시
- 하단 썸네일 최대 5개
- 사진이 없으면 기본 이미지 한 장 표시
- 원본 비율을 유지하고 과도한 세로 이미지에는 최대 높이 적용
- 키보드와 터치로 이전·다음 이동

## 7. 상태 표시

거래 상태는 색만으로 구분하지 않는다.

| 상태 | 표시 원칙 |
|---|---|
| 판매 중 | 기본 강조색 + `판매 중` 텍스트 |
| 예약 중 | 중립 경고색 + `예약 중` 텍스트 |
| 판매 완료 | 회색 계열 + `판매 완료` 텍스트 |

상품 상태와 상품 분류는 거래 상태보다 시각적 우선순위를 낮춘다. 여러 개의 강한 색상 배지를 동시에 사용하지 않는다.

## 8. 반응형

### 데스크톱

- 필터와 보기 토글을 한 줄에 배치할 수 있음
- 목록 가격을 오른쪽 열에 정렬
- 앨범 3~4열

### 모바일

- 목록형 고정
- 검색과 필터는 접을 수 있는 영역으로 구성
- 썸네일은 제목·가격 공간을 침범하지 않는 크기
- 상세의 작성자 동작은 하단 고정 버튼보다 본문 흐름 안에 배치
- 거래 방식 라디오는 줄바꿈을 허용

## 9. 접근성

- 보기 토글은 실제 `button` 사용
- 선택 상태를 `aria-pressed`로 표현
- 거래 방식은 같은 `name`을 가진 radio group
- 필드 label과 오류 메시지를 연결
- 이미지 alt는 판매글 제목
- 상태는 색상과 텍스트를 함께 사용
- 모달을 쓰면 focus trap과 ESC 닫기 지원
- 클릭 영역 최소 36~44px 확보

## 10. 다크모드

기존 중성 차콜 계열 다크 토큰을 사용한다. 상품 이미지는 색상 필터를 적용하지 않는다. 상태 배지는 다크 배경에서도 텍스트 대비를 확보하되 채도를 과도하게 높이지 않는다.

## 11. 로딩과 오류

- 목록 로딩: 실제 카드 구조와 비슷한 skeleton
- 상세 로딩: 제목·가격·이미지 영역 skeleton
- 401: 로그인 이동
- 403: 권한 없음 안내
- 404: 없거나 볼 수 없는 판매글 안내
- 409: 최신 내용 재조회 안내
- 500: 다시 시도 버튼
- 빈 검색: 조건 초기화 버튼

이전 목록 데이터가 있는 상태에서 필터를 바꿀 때 전체 화면을 비우지 않고 목록 영역만 로딩 상태로 바꾼다.

## 12. 구현하지 않는 UI

- 추천·비추천 버튼
- 찜 버튼
- 구매하기·결제 버튼
- 배송 추적
- 판매자 평점
- 신고 버튼
- 쪽지 버튼
- 가격 제안
- 지도와 직거래 위치

쪽지와 신고는 각 도메인을 설계한 뒤 추가한다. 작동하지 않는 버튼을 미리 노출하지 않는다.
