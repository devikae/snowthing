# 카풀 자동 경로·유가 계산 설계

## 목표

사용자가 거리, 통행료, 유가를 임의로 입력하지 않아도 출발지와 리조트, 차량 정보, 모집 인원만으로 예상 비용을 계산한다. 계산 결과는 실제 정산액이 아니라 모집글 작성 시점의 예상 금액이다.

## 자동 계산 흐름

1. 사용자가 출발 장소를 검색한다.
2. 백엔드가 카카오 로컬 API로 장소 후보와 좌표를 반환한다.
3. 사용자가 후보 하나를 선택하고 목적지 리조트, 편도·왕복, 유종, 연비, 모집 인원을 입력한다.
4. 백엔드가 선택된 리조트의 DB 마스터에서 검증된 스키장 진입 좌표를 읽는다. 리조트 이름을 카카오 장소 검색에 다시 보내 첫 결과를 선택하지 않는다.
5. 백엔드가 카카오 모빌리티 자동차 길찾기 API로 출발 경로를 조회하고, 왕복이면 좌표를 뒤집어 복귀 경로도 별도로 조회한다. 카카오 장애 시 사용자가 입력한 총거리와 총 통행료를 사용한다.
6. 백엔드가 유효한 유종별 캐시를 확인하고, 없으면 오피넷 전국 평균가격 API를 조회한다. 둘 다 사용할 수 없으면 제한 범위의 사용자 유가를 받는다.
7. 왕복이면 출발·복귀 경로의 거리·시간·통행료를 각각 합산한다.
8. `연료비 = 총 거리 / 연비 × 유가`, `총비용 = 연료비 + 통행료`, `1인 비용 = 총비용 / (운전자 1명 + 모집 인원)`으로 계산한다.
9. 모집글 생성·수정 시 백엔드가 외부 값을 다시 검증하고 계산한 스냅샷을 저장한다.

## 외부 API 경계

- 카카오 REST API 키는 `SNOWTHING_KAKAO_REST_API_KEY`로 서버에만 주입한다.
- 오피넷 인증키는 `SNOWTHING_OPINET_API_KEY`로 서버에만 주입한다.
- 키와 원본 외부 응답은 브라우저, 로그, 예외 메시지에 노출하지 않는다.
- 카카오 호출은 짧은 연결·응답 제한시간을 적용한다.
- 오피넷 전국 평균은 유종별로 캐시하며, API 응답의 거래일과 실제 조회 시각을 함께 관리한다.
- 리조트 경로 기준점은 `resort.route_latitude`, `resort.route_longitude`에 소수점 7자리로 저장한다. 현재 13개 리조트의 스키장 진입 지점을 직접 확인한 값이며 변경은 운영 마이그레이션으로 추적한다.
- 각 모집글에는 계산 당시 목적지 좌표를 다시 저장해 이후 리조트 마스터 좌표 변경과 무관하게 계산 근거를 보존한다.

## 카카오 길찾기 요청 예시

다음은 천호역 좌표에서 휘닉스파크 예시 좌표까지 휘발유 차량의 추천 경로 요약을 요청하는 형태다. 실제 키는 코드나 문서에 기록하지 않고 서버 환경변수에서 읽는다.

```bash
curl --get 'https://apis-navi.kakaomobility.com/v1/directions' \
  --header "Authorization: KakaoAK ${SNOWTHING_KAKAO_REST_API_KEY}" \
  --data-urlencode 'origin=127.1234567,37.5387654' \
  --data-urlencode 'destination=128.3224144,37.5805715' \
  --data-urlencode 'priority=RECOMMEND' \
  --data-urlencode 'car_fuel=GASOLINE' \
  --data-urlencode 'summary=true'
```

서비스에서 사용하는 응답 필드는 다음과 같다.

```json
{
  "routes": [
    {
      "result_code": 0,
      "summary": {
        "distance": 190000,
        "duration": 10800,
        "fare": {
          "toll": 12000
        }
      }
    }
  ]
}
```

- `distance`: 미터 단위이므로 1,000으로 나눠 km로 변환한다.
- `duration`: 초 단위 예상 이동 시간이다.
- `fare.toll`: 원 단위 예상 통행료다.
- `result_code`: `0`이 아니면 정상 경로로 저장하지 않는다.
- 왕복은 출발지와 목적지 좌표를 바꿔 복귀 경로를 다시 조회한다. 두 경로는 교통 방향, 추천 경로와 통행료가 다를 수 있으므로 편도 결과를 두 배로 계산하지 않는다.

전체 검증 응답은 `backend/src/test/resources/fixtures/carpool/kakao-directions-success.json`에 보관한다.

## 오피넷 전국 평균 유가 요청 예시

```bash
curl --get 'https://www.opinet.co.kr/api/avgAllPrice.do' \
  --data-urlencode "code=${SNOWTHING_OPINET_API_KEY}" \
  --data-urlencode 'out=json'
```

응답의 `RESULT.OIL`에서 선택 유종의 `PRODCD`를 찾고 `PRICE`와 `TRADE_DT`를 저장한다. 검증 응답은 `backend/src/test/resources/fixtures/carpool/opinet-national-average-success.json`에 보관한다. 예시 가격은 파싱·계산 검증용 값이며 실제 현재 유가로 사용하지 않는다.

## 유종 매핑

| 서비스 유종 | 오피넷 제품 코드 |
|---|---|
| `GASOLINE` | `B027` |
| `HYBRID_GASOLINE` | `B027` |
| `DIESEL` | `D047` |
| `LPG` | `K015` |

하이브리드는 별도 연료 가격이 없으므로 휘발유 가격을 사용하고, 차이는 사용자가 입력한 실연비로 반영한다.

## 실패 처리

- 장소 검색 실패: 후보가 없다는 필드 오류를 표시한다.
- 길찾기 실패: 부분 계산값을 저장하지 않고 수동 경로 입력 UI를 연다. 출발지 문자열, 총거리 1~2,000km, 통행료 0~20,000원을 서버가 검증한다.
- 오피넷 실패: 만료되지 않은 6시간 캐시를 사용하고, 캐시도 없으면 1,000~3,000원/L 사용자 유가를 받는다.
- 수동 유가와 수동 경로는 각각 `USER_INPUT`, `MANUAL` 출처로 저장해 공식 데이터처럼 표시하지 않는다.
- 외부 API 장애를 모집글 데이터의 부분 저장으로 전파하지 않는다.
- 외부 제공자 쿼터와 비용을 보호하기 위해 장소 검색은 IP당 분당 30회, 비용 미리보기는 IP당 분당 12회로 제한한다. 현재 단일 인스턴스의 인메모리 제한이므로 서버 다중화 시 Redis 기반 공용 카운터로 교체한다.

## 대안과 선택 이유

### 전국 평균 유가

지역명 매핑이나 특정 주유소 선택 없이 같은 시점·유종에 일관된 계산값을 제공한다. 실제 주유 가격과 차이가 날 수 있으므로 예상 금액임을 표시한다.

### 출발 지역 평균 유가

전국 평균보다 현실적이지만 자유 입력 출발지를 행정구역 코드로 변환해야 한다. 초기 범위에서는 제외한다.

### 주변 최저가 주유소

실제 선택 가능한 가격에 가깝지만 주유소 선택, 영업 여부, 우회 거리까지 고려해야 한다. 카풀 모집글의 단순 예상 계산 범위를 넘으므로 제외한다.

## 검증 기준

- 하드코딩 유가가 없어야 한다.
- 외부 API 키가 브라우저 번들에 포함되지 않아야 한다.
- 동일 유종의 반복 조회는 캐시를 사용해야 한다.
- 편도는 한 번, 왕복은 방향이 다른 두 번의 길찾기 결과를 반영해야 한다.
- 목적지 좌표는 장소 검색 1위가 아니라 DB에 저장된 해당 리조트 기준 좌표와 일치해야 한다.
- 미리보기와 저장은 같은 계산 규칙을 사용해야 한다.
- 외부 API 실패 시 부분 모집글이 저장되지 않아야 한다.
- 외부 API 장애 폴백 값도 브라우저 계산 결과가 아니라 서버 계산 결과를 저장해야 한다.
- 계약 테스트에서 카카오 인증 헤더, 출발·도착 좌표, 추천 경로, 유종, 요약 요청 파라미터를 확인해야 한다.
- Spring Boot HTTP 변환기와 외부 응답 타입이 같은 Jackson 세대를 사용해야 한다.
