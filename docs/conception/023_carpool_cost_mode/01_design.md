# 카풀 비용 방식 토글과 상세 화면 정리

## 배경

- 작성자가 "인당 만원에 태워 줄게"처럼 금액만 정하고 싶어도, 지금은 지도에서 출발지를 고르고 유종과 연비를 넣어 계산을 거쳐야 등록된다. `MANUAL`을 골라도 서버가 카카오와 오피넷을 호출한다.
- 직접 입력 글의 총액이 어긋난다. 1인 금액 10,000원, 모집 3명이면 운전자까지 곱해 40,000원으로 저장되고, 화면의 연료비와 통행료 합과도 맞지 않는다.
- 카풀 상세는 옛 파란 스타일 위에 새 무채색 스타일을 덮어써서 게시글 상세와 다르게 보인다. `.carpool-detail-badges span`이 배지 안의 아이콘까지 하늘색 네모로 칠하고, `downhill_skiing` 아이콘은 장비가 아니라 스키 타는 사람 그림이다.
- 사용성 오류도 확인했다. 목록 조회가 한 번 실패하면 다시 이동해도 오류 화면이 남고, 날짜 선택 최솟값을 UTC로 계산해 KST 오전 9시 전에는 전날이 선택된다.

## 요구사항

- 글쓰기 폼에서 `자동 계산`과 `직접 입력`을 토글로 고른다. 기본값은 자동 계산이다.
- 직접 입력은 계산을 전혀 하지 않는다. 출발 지역, 집결 장소, 1인 금액만 받고 외부 API를 호출하지 않는다.
- 왕복과 장비 적재는 비용 방식과 상관없이 버튼으로 고른다.
- 카풀 상세를 게시글 상세와 같은 구성으로 맞춘다.

## 데이터

직접 입력 글의 계산 값은 NULL로 저장한다. 0으로 채우면 0km 같은 값이 실제 값처럼 쓰일 수 있고, "계산하지 않은 글"을 데이터로 구분할 수 없기 때문이다.

마이그레이션 `035_migration_carpool_manual_cost_nullable.sql`:

- NULL 허용으로 변경: `fuel_type`, `fuel_efficiency`, `fuel_price`, `fuel_price_source`, `fuel_price_observed_at`, `route_distance_km`, `route_toll_fee`, `estimated_fuel_cost`, `estimated_total_cost`, `route_source`
- 계속 필수: `estimated_cost_per_person`(목록과 상세의 금액), `destination_latitude`, `destination_longitude`(리조트 기준값), `cost_mode`
- CHECK 추가: `cost_mode`가 `AUTO`이면 위 계산 값이 모두 있어야 한다.

MySQL CHECK는 결과가 NULL이면 통과하므로 기존 CHECK 제약은 고치지 않는다.

기존 `MANUAL` 글의 값은 지우지 않는다. 응답에서 계산 값을 null로 내려 새 글과 똑같이 보이게 하고, 작성자가 수정해 저장하면 그때 NULL이 된다.

## API

`POST /api/v1/carpools`, `PUT /api/v1/carpools/{publicId}`

| 항목 | `AUTO` | `MANUAL` |
|---|---|---|
| `departureRegion`, `meetingPlace` | 필수 | 필수 |
| `manualCostPerPerson` | 무시 | 필수 |
| `fuelType`, `fuelEfficiency`, `routeSource` | 필수 | 무시 |
| 출발 좌표 | `routeSource=KAKAO`이면 필수 | 무시, NULL 저장 |
| 수동 거리, 통행료, 유가 | 장애 대비 입력일 때 사용 | 무시 |
| 외부 API | 호출 | 호출 안 함 |

- `fuelType`, `fuelEfficiency`, `routeSource`의 `@NotNull`을 없애고 서비스에서 `AUTO`일 때 검사한다. 값이 없을 때 오류는 필드 검증 오류에서 `CARPOOL_002`로 바뀐다.
- `CarpoolResponse`의 계산 필드는 `MANUAL`이면 null이다. `routeTollFee`, `estimatedFuelCost`, `estimatedTotalCost`는 `int`에서 `Integer`로 바뀐다.
- `CarpoolSummaryResponse`에 `costMode`를 추가해 목록에서 금액 라벨을 구분한다.
- `CarpoolResponse`에 `writerPublicId`, `writerProfileImageUrl`을 추가한다. 상세 작성자 영역을 게시글 상세와 맞추는 데 쓴다.
- `AUTO`의 `estimated_total_cost`는 미리보기와 같은 계산 총액을 저장한다. 지금은 올림한 1인 금액에 인원을 곱해 미리보기와 다를 수 있다.

## 화면

### 글쓰기 폼

- 제목 아래에 비용 방식 토글을 둔다. 지금의 비용 방식 선택창은 없앤다.
- 토글을 바꿔도 입력한 값은 지우지 않는다.

| 영역 | 자동 계산 | 직접 입력 |
|---|---|---|
| 출발 장소 | 카카오 지도 | 출발 지역, 집결 장소 입력 |
| 비용 | 유종, 연비, 계산 결과 | 1인 금액 입력 |

- 계산 결과는 상세 화면과 같은 줄 나열로 보여 주고 1인 비용을 강조한다. 자동 계산은 입력이 갖춰지면 스스로 돌기 때문에 계산 버튼은 장애 대비 입력일 때만 보여 준다.
- 이동 방식은 `편도`와 `왕복` 버튼이고 기본값은 편도다. 왕복이면 복귀 날짜와 시간이 나타난다.
- 장비 적재는 `가능`과 `불가` 버튼이다. 새 글은 기본값 없이 반드시 고른다. 수정할 때는 저장된 값이 선택된 상태로 열린다.
- 연락처 입력란 아래에 공개 범위 안내를 넣는다.
- 날짜 선택 최솟값은 KST 기준으로 계산한다.

### 카풀 상세

게시글 상세처럼 2단으로 배치한다. 모바일에서는 한 단으로 쌓고 금액 카드를 제목 바로 아래로 올린다.

- 왼쪽: 목록 버튼, 배지, 제목, 작성자, 경로, 모집 내용, 댓글
- 오른쪽: 금액 카드, 연락 방법 카드

세부 규칙:

- 배지에는 아이콘을 쓰지 않고 14px 글자로 크게 표시한다. 편도와 왕복은 검은 배경, `장비 적재 가능`은 진한 테두리, `장비 적재 불가`는 연한 회색 테두리다.
- 작성자는 게시글 상세처럼 프로필 사진, 닉네임, 작성일로 표시한다. 수정과 삭제 버튼은 같은 줄에 두고 삭제 버튼의 빨간색을 뺀다.
- 경로는 출발과 도착을 세로선으로 잇고, 출발 시간은 출발 정보에 한 번만 표시한다.
- 금액 카드의 비용 내역은 항목과 금액을 한 줄씩 나열한다. 글자는 최소 12px, 색은 사이트의 무채색 토큰만 쓴다.
- 직접 입력 글은 라벨을 `1인 비용`으로 쓰고 카드에는 모집 인원만 남긴다.

### 카풀 목록

- 금액 라벨을 `costMode`에 따라 `예상 1인 비용`과 `1인 비용`으로 구분한다. 메인과 게시판 사이드 위젯은 라벨 없이 금액만 보여 주므로 바꾸지 않는다.
- 목록은 페이지가 바뀌면 로딩과 오류 상태를 초기화한다.
- 시간은 상세와 같은 `11.8 (일) 오전 8:30` 형식으로 표시한다.

## 영향

- 외부 호출: 직접 입력 글은 카카오와 오피넷을 호출하지 않아 장애와 무관하게 등록할 수 있다. 자동 계산 흐름은 그대로다.
- MCP 서버: 카풀 작성 도구의 입력 스키마는 `fuelType`, `fuelEfficiency`, `routeSource`를 필수로 보내는데, 서버가 `MANUAL`에서 이 값을 무시하므로 호환이 유지된다. 응답 스키마 검증이 없어 null 응답도 깨지지 않는다. MCP에서 금액만으로 등록하는 기능은 이번 범위가 아니다.
- 배포: 앱보다 마이그레이션을 먼저 적용한다. NULL 허용으로 넓히는 변경이라 이전 버전 앱과 함께 돌아가도 문제가 없다. 되돌릴 때는 앱을 먼저 되돌리고, `MANUAL` 글에 값이 채워지지 않은 상태로 NOT NULL을 복구할 수 없으므로 컬럼은 그대로 둔다.
- 인덱스와 조회 성능: 정렬과 조회 조건 컬럼을 바꾸지 않아 영향이 없다.
- 기존 글: 기존 `MANUAL` 글의 총액과 계산 내역은 더 이상 표시하지 않는다.
