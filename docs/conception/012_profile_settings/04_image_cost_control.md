# 이미지 저장 및 비용 악용 방지

사용자 승인 기준은 프로필 변경 요청 24시간 고정 구간당 5회, 일반 사진 요청 계정별 시간당 30회다. 변경 실패·기본 사진 초기화도 요청 횟수에 포함한다. 서버를 재시작해도 유지되는 request_budget_window를 사용하며 제한 저장소 장애 시 업로드를 허용하지 않는다. 사진 전체 업로드는 시간당 300회·24시간당 1,000회 상한을 함께 검사한다. 구간 경계에서 요청이 집중될 수 있어 이미지 처리는 프로세스당 동시 2개로 제한한다.

프로필 변경은 서비스 전체에서도 24시간당 30회로 제한해 다중 계정을 통한 CDN 무효화 요청 비용을 제한한다. 사용량 증가 시 이 상한과 비용 예산을 함께 검토한다.

## 일반 사진 등록과 원자성

기존 POST /api/v1/images의 응답 imageUrl·imageKey 계약은 유지한다. POST /api/v1/images/keep-alive는 인증·CSRF를 요구하며 imageKeys 문자열 배열(최대 10개)을 JSON으로 받아 본인의 유효한 업로드를 연장하고 204를 반환한다. 계정별 시간당 60회로 제한한다. 소유권 불일치·삭제 중인 사진은 입력 오류로 거절한다.

연장 키는 빈 값·null을 허용하지 않고 각 값의 길이를 512자로 제한한다. 게시글 본문에서 찾은 자체 저장 이미지 키는 중복을 제거하며 첨부와 합쳐 최대 30개만 잠근다. 외부 사이트 이미지나 본문에 붙여넣은 이미지 개수 제한을 추가하는 정책은 아니다. 익명 글 비밀번호 검증을 통과한 수정은 기존에 연결된 사진만 소유자 비교를 생략하며, 새 사진과 삭제 상태 검증은 유지한다.

024의 post_image_upload는 image_key PK, owner_email, state, due_at 및 예정 시각 인덱스를 가진다. 이미지 저장 전에 예약을 별도 트랜잭션으로 커밋한다. 새 사진 키는 public/posts/originals/m-UUID.jpg이며 일반 업로드에서는 썸네일을 생성하지 않는다. URL 승격·복사 대신 같은 키를 유지해 글 저장과 S3 복사 사이의 실패 구간을 줄인다.

게시글·장터 저장 트랜잭션에서 업로드 행을 키 순서로 잠그고 소유자와 PENDING 상태를 검증한다. 삭제 중·삭제 완료·존재하지 않는 새 키는 연결할 수 없다. 본문에 직접 입력한 관리 대상 이미지 경로도 검사한다. 기존 파일은 보수적으로 호환하며 024는 DB에 연결된 기존 첨부를 등록한다. 기존 미참조 파일은 별도 조사 결과로만 관리한다.

## 보관과 정리

미연결 사진은 마지막 연장으로부터 1시간 뒤 정리 대상이다. 글 작성·수정 화면은 열려 있는 동안 10분마다 첨부 사진의 유효 시간을 연장한다. 임시저장 문서 기능은 추가하지 않는다. 주기 작업은 분당 최대 50행을 선택하고 DB 참조와 본문 참조를 확인한다. 삭제된 게시글도 복구 가능성을 위해 참조로 유지한다. 현재 연결된 사진은 예정 시각을 연장한다. 제거된 사진은 다음 만료 시점에 정리한다.

삭제 대상은 행 잠금 안에서 DELETING으로 전환하고 10분 임대를 기록한 뒤 DB 트랜잭션 밖에서 S3 원본·썸네일을 삭제한다. 실패하면 임대 만료 후 재시도한다. 완료는 DELETED로 남겨 오래된 작성 요청의 재연결을 거절한다. 새 m- 키의 삭제 기록은 7일 후 제거하며, 삭제 기록이 없어도 존재하지 않는 새 키의 연결은 거절한다. 기존 키의 삭제 기록은 유지한다.

S3 수명주기는 public/posts/ 전체를 만료하지 않는다. 애플리케이션이 삭제 대상으로 확정한 뒤 붙이는 snowthing-cleanup=ready 태그에만 1일 만료 규칙을 적용한다. S3 수명주기는 서버의 1시간 정리를 대체하는 즉시 실행 장치가 아니다.

## 이미지 변환과 캐시

새 일반 사진은 최대 1920×1920 범위의 JPEG 품질 0.82로 변환한다. 원본 파일을 추가 보관하지 않으며 일반 게시판은 썸네일 파일과 썸네일 URL 응답을 생성하지 않는다. 파일 특성에 따라 변환 후 바이트 수가 항상 작아지는 것은 아니다. 파일당 5MB, 한 변 10,000px·총 2,500만 픽셀 검증을 먼저 수행한다. 일반 관리 사진은 캐시 max-age=3600으로 장기 잔류를 줄인다. 이전 파일의 저장 헤더는 변경하지 않는다.

## 장터 대표 썸네일

025의 market_thumbnail은 post_public_id PK, source_key, ready_source_key, revision, due_at, lease_until을 갖는다. 장터 글 저장 트랜잭션에서 첫 사진을 작업으로 기록하며 롤백 시 작업도 롤백된다. 사진마다 썸네일을 만들지 않고 글마다 public/posts/thumbnails/market-게시글UUID.jpg 하나만 유지한다.

5초 주기 작업이 첫 사진을 최대 320×320 JPEG 품질 0.8로 변환한다. 대표 사진 변경 시 같은 파일을 갱신하고 실패는 재시도한다. 생성 전에는 목록에서 압축 사진 URL을 사용한다. 같은 대표 사진으로 재저장하면 다시 변환하지 않는다. 변경된 작업 revision이 다르면 완료로 표시하지 않고 새 사진으로 다시 처리한다. 외부 I/O는 DB 트랜잭션 밖에서 실행하고 20초 호출 제한과 5분 임대를 사용한다. 생성 횟수도 전체 시간당 300·24시간당 1,000회로 제한한다.

사진을 전부 제거하면 장터 썸네일도 삭제한다. 물리 삭제된 글의 썸네일은 시간 단위 정리 작업에서 삭제하고, 복구 가능한 소프트 삭제 글은 보관한다. 캐시는 60초이므로 대표 사진 변경은 작업 처리 및 캐시 만료만큼 지연될 수 있다. 기존 업로드의 썸네일은 호환을 유지하며 일괄 삭제하지 않는다.

프로필은 최대 320×320 JPEG 품질 0.8 하나만 보관한다. 교체·초기화 시 이전 파일을 DB 정리 작업에 기록하고 S3 삭제 및 CloudFront 무효화를 재시도한다. 프로필 경로에는 캐시 비활성 정책을 적용한다.

작은 사진은 확대하지 않는다. 변환 게이트를 통과한 뒤에만 요청 예산을 검사하고 변환을 수행한다. S3 업로드는 변환 게이트 밖에서 실행하며 업로드 및 썸네일 외부 호출은 20초 호출 제한을 사용한다.

## 운영

- 역할 권한은 프로필 및 게시글 사진 경로의 삭제·태그와 특정 CloudFront 배포 무효화로 제한한다.
- 운영에 있던 월 35 USD 예산의 50%·80%·100% 실제 비용 알림에 82snowthing@gmail.com 수신자를 추가했다. 예산은 업로드 차단 장치가 아니다.
- 공개 CDN의 모든 다운로드 비용에 대한 절대 상한을 보장하지 않는다. 업로드 상한과 비용 알림으로 통제하며, 실제 읽기 공격이 확인되면 CDN 요청 차단을 별도로 수행해야 한다.
- 배포 시 023·024·025 마이그레이션, 배포 ID 환경변수 반영과 헬스체크, 이미지 생성·교체·정리 관측이 필요하다. 이 문서는 배포 완료를 의미하지 않는다.

## PR #47 리뷰 보완 (2026-11-03)

본문에서만 참조하는 사진은 갤러리용 `post_image`에 넣지 않는다. 026의 `post_content_image_reference`가 게시글과 이미지 키의 N:M 참조를 저장한다. `post_id` FK와 `(post_id, image_key)` 유일 제약, `image_key` 조회 인덱스를 둔다. 일반 게시글·장터의 생성 및 수정 트랜잭션에서 본문 키 집합을 교체한다. 삭제 작업은 기존 업로드 행 잠금을 유지하면서 첨부 참조와 본문 참조를 모두 확인한다. 소프트 삭제는 참조를 유지하고 물리 삭제 시 FK의 CASCADE로 참조만 제거한다. 026은 기존 업로드 키를 본문에서 찾아 한 번 백필한다. 실행 중의 정리 쿼리에는 본문 전체 스캔이 없다. 갤러리 순서·hasImage·장터 대표 사진은 기존 첨부 목록을 따른다.

이미지 변환은 ImageReader로 치수를 확인하고 원본 바이트 스트림을 Thumbnailator에 전달한다. EXIF 방향을 적용한 후 JPEG로 저장하며 작은 사진을 확대하지 않는다. 정사각 경계를 사용하므로 90도 회전에도 최대 크기 제한이 유지된다.

025의 `market_thumbnail`에 `attempts INT NOT NULL DEFAULT 0`을 추가한다. 아직 운영 미적용인 025를 보완한 것이므로 이미 적용된 환경에서는 체크섬을 우회하지 말고 별도 후속 마이그레이션을 준비해야 한다. 생성 실패는 1·2·4·8분 간격으로 재시도하고 5번째 실패에 중단한다. 404·잘못된 입력·잘못된 이미지 형식 및 치수는 즉시 중단한다. 예산 거절은 실패 횟수를 올리지 않고 제한 저장소의 retryAfterSeconds를 따른다. 새로운 queue는 실패 횟수를 초기화한다. 완료·실패 모두 revision 조건으로 이전 작업이 새 작업을 덮지 않도록 한다.

고아 썸네일 삭제는 한 시간마다 한 배치만 처리하던 방식에서 20개 배치를 반복하는 방식으로 바꾸며 실행 시간은 2분으로 제한한다. 실패한 삭제에는 다음 lease를 기록한다. UUID 커서도 전진시켜 동일한 실패 작업을 한 실행에서 반복 선택하지 않는다. 삭제는 저장 누수를 막기 위해 생성의 5회 중단과 달리 실패 상한 이후에도 최대 시간당 한 번 재시도한다.

전역 비용 상한과 계정별 상한은 기존 승인 값을 유지한다. 전역 거절은 `IMAGE_GLOBAL_LIMIT` (`FILE_007`, HTTP 429)와 action·전역 버킷·재시도 초를 포함한 로그로 구분한다. 계정 이메일은 로그에 넣지 않는다. 별도 전역 예산 및 신규 계정·IP 제한은 정상 사용자 차단 범위를 바꾸므로 이번 버그 수정에서 임의 도입하지 않는다. 운영 로그 경보 연결과 실제 백필 규모·실행 계획 관측은 배포 준비 사항이며, 로컬 검증 결과를 운영 실측으로 대신하지 않는다.
