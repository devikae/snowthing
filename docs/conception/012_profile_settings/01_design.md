# 내 정보 설정 (2026-11-01)

## 승인 범위

상단 프로필 메뉴의 내 정보 수정에서 실제 계정 정보를 수정한다. 닉네임 중복 확인, 프로필 사진 변경·기본 이미지 복원, 현재 비밀번호를 확인하는 비밀번호 변경을 포함한다. 마케팅 항목은 제외한다. 기존 가입 동의·이메일 인증·소셜 로그인 정책을 보존한다.

## 데이터 및 API

- 기본 정보는 기존 member, member_resort, member_riding_style와 resort, riding_style 마스터를 사용한다. 리뷰 보완으로 프로필 파일 정리를 위한 021 profile_image_cleanup 및 공유 요청 한도를 위한 022 request_budget_window를 추가한다. 상세는 03_profile_image_lifecycle.md를 따른다.
- GET /api/v1/members/me/settings: 본인의 닉네임·이메일·사진·자기소개·출발지·리조트/성향 ID와 이름, 비밀번호 변경 가능 여부를 반환한다. Entity와 비밀번호 해시는 반환하지 않는다.
- PUT /api/v1/members/me/settings: 기존 정보 수정 DTO를 이용한다. 서버는 마스터 ID와 닉네임을 최종 검증한다. 조회 실패 시 저장을 허용하지 않는다.
- POST /api/v1/members/me/nickname-availability: 검증된 닉네임의 사용 가능 여부를 반환한다. 본인의 현재 닉네임은 사용 가능하다. 클라이언트는 확인한 문자열을 기록하고 응답 전에 입력이 바뀌면 해당 결과를 무시한다.
- PUT /api/v1/members/me/password: 현재 비밀번호를 검증한 뒤 8~20자 새 비밀번호로 변경한다. 커밋 후 컨트롤러/보안 계층에서 기존 세션과 라이브톡 연결을 만료한다. password=null인 소셜 전용 계정은 변경을 거부하고 공급자 계정에서 변경하도록 안내한다.
- POST /api/v1/images/profile: 사진은 검증 후 320px 이내 JPEG로 재인코딩하여 공개 프로필 전용 경로 `public/profiles/{UUID}.jpg`에 업로드한다. 서버가 해당 요청의 인증 회원에게 연결하며 클라이언트가 임의 URL이나 대상 회원을 지정하지 못한다. 기본 이미지 복원은 DELETE /api/v1/members/me/profile-image로 DB 참조를 null로 변경한다. 이전 파일·업로드 실패 파일은 영속 정리 작업을 통해 S3 삭제와 CDN 무효화를 재시도한다(03_profile_image_lifecycle.md).

계정별 요청 제한은 비밀번호 변경 15분 10회, 닉네임 확인 1분 30회, 프로필 사진 변경 24시간 5회다. 비밀번호와 사진은 MySQL 공유 고정 창으로 확인하고 저장소 장애 시 503으로 차단한다. 닉네임 확인은 단일 인스턴스 메모리 캐시를 유지한다. 사진 종류별 전역 예약·신규 계정·IP별 추가 한도 및 운영 경보는 04_image_cost_control.md를 따른다. 키에는 이메일·IP 원문 대신 SHA-256 값을 사용한다. 변경 요청은 회원 행을 잠가 비밀번호·프로필·사진 간 동시 갱신 유실을 방지한다. PUT 설정에서 두 선호 목록은 필수이며 생략/null은 400, 명시적 빈 배열만 전체 해제를 뜻한다.

## 화면 및 검증

기존 디자인 토큰으로 모바일·다크모드를 지원한다. 실제 데이터 로딩, 실패와 재시도, 저장 결과를 표시한다. 닉네임 중복 확인은 UX용이며 최종 유니크 충돌도 서버에서 처리한다. 수정하지 않은 N:M 값은 조회한 ID로 보존한다. 사진 미리보기의 object URL을 해제하며 저장/업로드 중 중복 요청을 막는다. 비밀번호 표시 전환과 저장하지 않은 변경 확인을 제공한다.

2026-11-01 화면 보완: 진입 시 저장된 리조트·스타일 이름을 선택 항목 위에 명시하고 해당 ID의 선택 상태를 복원한다. 저장값이 비어 있으면 미선택을 안내하며 임의 기본값을 넣지 않는다. 비밀번호 입력 폼은 처음에는 표시하지 않고 ‘비밀번호 변경’을 누르면 표시한다. ‘변경 취소’는 폼을 닫고 현재/새 비밀번호·확인값과 표시 설정을 초기화한다. 기본 정보 수정과 비밀번호 변경은 계속 별도 제출한다.

## 통합 주의

feature/profile의 회원가입·실명·성별·007 마이그레이션·인증 설정을 복사하지 않는다. DTO 컬렉션은 방어적 복사하고 서비스에서 세션을 조작하지 않는다. 비밀번호 변경은 별도 트랜잭션을 완료한 다음 세션을 만료시킨다.
