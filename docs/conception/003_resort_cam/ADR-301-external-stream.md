# ADR-301 외부 리조트 영상 연결 방식

- 상태: Accepted
- 결정일: 2026-09-28

## 문제

리조트별로 영상 형식과 제공 정책이 다르며, 여러 카메라를 동시에 보여줄 때 SnowThing 서버의 자원과 외부 서비스 장애를 격리해야 합니다.

## 후보

1. 프런트엔드 정적 URL: 단순하지만 링크 변경마다 배포가 필요합니다.
2. DB 메타데이터와 브라우저 직접 재생: 운영 변경이 쉽고 서버 영상 트래픽이 없습니다.
3. 서버 프록시·재송출: 재생 통제는 쉽지만 네트워크 비용, 장애 책임, 법적 부담이 큽니다.

## 결정

DB 메타데이터와 브라우저 직접 재생을 채택합니다. 백엔드는 활성 리조트와 카메라의 코드·이름·재생 유형·URL만 반환합니다.

## 근거

- 외부 링크 변경을 코드 배포와 분리할 수 있습니다.
- 단일 EC2가 영상 대역폭을 부담하지 않습니다.
- 리조트 하나의 장애가 SnowThing 백엔드 가용성에 직접 영향을 주지 않습니다.
- 향후 관리자 페이지로 마스터 데이터를 관리할 수 있습니다.

## 대가와 대응

- CORS·CSP·Referer 제한: 호환성 표와 `EXTERNAL_LINK` fallback으로 대응합니다.
- 여러 스트림의 브라우저 부하: 지연 생성, 가시 영역 감지, PC 최대 6개, 모바일 선택 재생으로 제한합니다.
- 외부 URL 변경: DB 활성 상태와 URL을 나중에 관리자 기능에서 수정합니다.
- 타사 서비스 의존: 원본 제공처 고지와 부분 실패 UI를 둡니다.
