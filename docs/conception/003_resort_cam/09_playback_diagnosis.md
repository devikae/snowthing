# 일부 슬로프캠 재생 실패 점검 (2026-11-01)

## 후속 공식 소스 대조 및 추가 수정

### 전체 재생 요구에 대한 재검증

추가 요청 후 남은 원본을 다시 확인했다. 지산 1~5는 공식 Origin/Referer를 넣어도 404이며, 오크밸리 ch2/6/7/9는 현재 공식 출처의 playlist 요청도 502다. 무주 02/03은 공식 팝업에서 토큰을 새로 발급받고 공식 Referer로 요청해도 404였다. 즉 옛 토큰·우리 Origin 때문에만 실패한다고 볼 증거가 없다.

에덴밸리는 공식 신규 링크뿐 아니라 DB에 있던 rtsp.me 기존 링크 두 개도 브라우저에서 직접 확인했다. 둘 다 제공처의 Streaming access is temporarily restricted 화면이며 영상 readyState=0, videoWidth=0이다(`%TEMP%/snowthing-eden-original-check-tlq8ai/`). 유료 접근 제한을 우회하거나 운영자 요금을 대신 결제하지 않는다.

엘리시안의 기존 공식 연결 채널 @11-lf8zw/live 및 /streams도 확인했다. 현재 라이브 여부가 없고 채널 목록을 반환하며, 종료된 녹화 영상을 현재 라이브로 대체하지 않았다. 정상 대체 공개 스트림은 찾지 못했다. 이 외부 조건들이 바뀌지 않은 현재 상태에서 모든 기존 카메라의 실제 라이브 재생 완료를 증명할 수 없다. 안내 화면 전환·카메라 숨김·다른 카메라 복제는 전체 재생 요구의 완료가 아니다.

사용자가 전체 수정 여부를 재확인하여 남은 카메라를 공식 자료에 대조했다. 처음의 원본 404 판정은 HTTP 응답 사실일 뿐 주소 변경 가능성까지 배제한 원인 확정이 아니었다.

- 휘닉스의 [현재 공식 카메라 API](https://phoenixhnr.co.kr/api/guide/operation/sketchMovie/pyeongchang)는 기존 파일명과 다른 yh_02_02 / ht_01_01 / bc_02_01 / yh_01_01 / mb_03_02를 공개한다. 5개 모두 HLS 200을 확인해 교체하고 bc_01은 그대로 유지했다. 현재 공식 화면 이름도 함께 적용해 계절에 따라 바뀐 촬영 방향을 옛 슬로프 이름으로 단정하지 않는다. 공식 목록에 없는 기존 도도 sp_01은 다른 영상을 대신 붙이지 않고 공식 목록 미제공 안내로 전환했다.
- [알펜시아 공식 웹캠](https://www.alpensia.com/guide/web-cam.do)의 현재 YouTube ID vvRfdby4YxI로 교체했다. 실제 임베드 화면에서 리조트 멀티뷰 라이브 영상을 확인했다.
- [에덴밸리 공식 페이지](https://www.edenvalley.co.kr/CS/cam_pop1.asp)의 현재 링크는 rtsp.ru/embed/nKGZGiRD 및 dh6R7d4k다. 브라우저에서 제공업체가 재생 접근을 제한하는 화면을 확인했다. 미등록 옛 주소와 결제 버튼이 있는 iframe을 계속 보여주는 대신 공식 링크·제공처 제한 안내로 전환했다. 외부 결제나 제한 우회는 하지 않았다.
- [엘리시안 현재 스키 페이지](https://elysian.co.kr/about-gangchon/ski)를 실제 브라우저로 확인했다. 기존 O6_8VBu4FSA는 ‘실시간 스트림 녹화를 볼 수 없습니다’였으며, 공식 웹캠 목록 응답도 점검 당시 유효한 영상 ID가 아닌 x1/x2를 반환했다. 재생 가능한 신규 영상을 임의 생성하지 않고 공식 페이지 링크·영상 미등록 안내로 전환했다.
- 지산의 현재 공식 플레이어도 기존 ant.livecity 주소를 사용하며 5개 모두 404다. 무주 2/3도 공식 팝업에서 새로 발급받은 원본 주소가 404다. 오크밸리는 현재 홈페이지 JS의 HTTP playlist 주소까지 대조했지만 4개는 HTTP/HTTPS 모두 502다. 우리 코드만으로 이 제공처의 송출을 복원할 수 없으며 재연결/공식 페이지 흐름을 유지한다.

API 응답과 fallback 모두 `sourceUpdates.ts`의 확인된 옛 URL에만 갱신을 적용한다. 운영/로컬 DB를 덮어쓰지 않으며 별도로 설정된 다른 URL은 유지한다. 이 표는 2026-11-01의 확인 상태다. 제공처가 새 영상을 공개하면 미제공/제한 표시 및 매핑을 다시 검토해야 한다. 현재 모든 카메라가 재생된다는 의미가 아니다.

경로/소스 회귀 테스트 3건·전체 프런트 린트/빌드를 통과했다. 최신 브라우저 검사에서 하이원·무주·오투·휘닉스의 실제 디코딩 해상도와 재생 시간 진행, 알펜시아 새 임베드, 미제공/제한 안내, 연결 실패 재시도, 실패 후 SPA 이동을 통과했다(`%TEMP%/snowthing-camera-check-ACZKQ7/`). 비발디 대표 카메라의 실제 영상도 별도 브라우저 화면에서 확인했다(`%TEMP%/snowthing-iframe-camera-check-8JMCr8/vivaldi.png`). iframe/YouTube의 모든 카메라를 각각 재생 완료했다고 주장하지 않는다.

## 확인한 결함과 변경

사용자는 일부 카메라만 재생되는 원인을 요청했다. 로컬 API·실제 Next 경로·원본 HLS를 읽기 전용으로 확인했다. 로컬 DB의 하이원/무주/오투 URL은 `/api/high1-stream`, `/api/muju-stream`, `/api/o2-stream`인데 현재 Next에는 `/stream-proxy/high1`, `/stream-proxy/muju`, `/stream-proxy/o2`만 있어 404였다. 동일 채널을 현재 경로로 직접 요청하면 HLS가 반환됐다.

시드와 fallback 파일은 이미 새 경로지만 로컬 초기화기는 camera가 하나라도 있으면 실행을 끝내므로 기존 DB 경로는 자동 변경되지 않는다. DB를 덮어쓰지 않고 목록 응답을 UI에 전달하는 경계에서 정확한 옛 접두사 세 개만 현재 경로로 해석한다. 외부 URL·기존 새 경로·다른 API는 바꾸지 않는다. 운영 DB는 변경하지 않는다.

플레이어가 실패한 뒤 리조트를 바꾸어 같은 CAM_01 컴포넌트를 재사용하면 failed 상태 때문에 video가 생성되지 않아 다음 영상도 재생되지 않을 수 있었다. 리조트/카메라/소스별 플레이어 key로 수명을 분리한다. 실패를 무조건 비시즌/개장 시 자동 재개로 단정하던 문구를 실제 연결 실패 안내로 바꾸고 명시적 재연결 버튼을 추가한다.

## 등록된 HLS 전체 재생 목록 점검

이 표는 해당 시점의 HTTP 응답과 #EXTM3U 여부이며 지속적인 재생 보장 또는 모든 세그먼트/iframe/YouTube 검증이 아니다. 화면 밖 영상은 기존 IntersectionObserver로 지연 로드한다.

| 휘닉스 | 7 | 1 | 6개 원본 404 |

원본 404/502만으로 비시즌, 서비스 종료, 주소 변경 중 어느 것인지 확정할 수 없다. 공식 소스가 확인되기 전 임의로 다른 카메라에 연결하거나 자동 복구를 약속하지 않는다. 비발디·에덴밸리 iframe과 엘리시안·알펜시아 YouTube는 위 HLS 검사 범위 밖이다.

## 검증

단위 테스트 2건과 프런트 전체 린트·빌드를 통과했다. 브라우저에서 하이원/무주 1920×1080, 오투 1280×720 디코딩과 재생 진행을 확인했다. 첫 외부 스트림 실행은 일시적으로 실패해 목록/하위 목록/실제 TS 조각까지 재검사했으며 후속 실행은 세 카메라 모두 통과했다. 실패 안내/재연결과 실패 후 SPA 리조트 이동 시 재생도 확인했다(`%TEMP%/snowthing-camera-check-0rswZe/`). 하이원은 별도 프레임 검사에서 재생 3.9초·36프레임·검정이 아닌 픽셀도 확인했다(`%TEMP%/snowthing-camera-frame-ammYRx/`). 정상 목록 수를 현재 건강 상태로 오해하지 않도록 화면의 ‘실시간 스트림 N개’는 ‘영상 연결 N개’로, 직접 연결만 한다는 문구는 제공 영상 안내로 수정했다.

`scripts/resort-cam.test.cjs`로 옛 경로 세 가지와 쿼리 보존·외부 주소 불변을 검증한다. `scripts/resort-cam-browser-check.cjs`로 하이원/무주/오투 대표 카메라에서 현재 프록시 요청과 video의 실제 디코딩된 해상도를 확인한다. 프론트 린트·빌드와 함께 결과를 work.md에 기록한다. 기존 외부 스트림 정책과 달리 이미 존재하는 Next 프록시는 서버를 통해 데이터를 전달하므로, 직접 연결만 한다는 운영 고지는 후속 대조가 필요하다. 이번에 프록시 재송출 기능을 새로 추가하지 않았다.
