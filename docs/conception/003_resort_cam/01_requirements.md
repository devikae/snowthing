# 리조트캠 요구사항

## 1. 목적

사용자가 여러 리조트 공식 사이트를 각각 방문하지 않고 SnowThing에서 한 리조트의 웹캠을 한 화면에 확인하도록 합니다. 리조트와 카메라를 URL로 식별하여 공유, 새로고침, 브라우저 이동을 지원합니다.

## 2. 사용자 시나리오

1. 비로그인 방문자가 리조트캠에 진입합니다.
2. 첫 번째 활성 리조트 또는 URL로 지정한 리조트가 선택됩니다.
3. 해당 리조트의 활성 카메라가 표시 순서대로 나타납니다.
4. PC에서는 화면에 진입한 카메라만 음소거 자동재생합니다.
5. 모바일에서는 사용자가 선택한 카메라만 재생합니다.
6. 카메라명을 선택하면 단일 카메라 화면으로 이동합니다.
7. 재생 실패 시 재시도하거나 원본 페이지를 새 탭으로 엽니다.

## 3. 기능 요구사항

| ID | 요구사항 |
|---|---|
| RC-F-001 | 활성 리조트와 활성 카메라 메타데이터를 공개 API로 제공합니다. |
| RC-F-002 | 리조트 선택 시 해당 리조트의 모든 카메라 카드를 표시합니다. |
| RC-F-003 | 카메라 선택 시 해당 카메라만 크게 표시합니다. |
| RC-F-004 | 리조트·카메라 선택 상태를 URL에 반영합니다. |
| RC-F-005 | HLS, YouTube, iframe, 외부 링크 유형을 구분합니다. |
| RC-F-006 | 외부 영상 오류가 다른 카메라 렌더링에 영향을 주지 않아야 합니다. |
| RC-F-007 | 재생 오류 카드에 재시도와 원본 링크를 제공합니다. |
| RC-F-008 | PC는 가시 영역 영상만 최대 6개까지 자동재생합니다. |
| RC-F-009 | 모바일은 자동재생하지 않습니다. |
| RC-F-010 | 리조트 변경과 컴포넌트 해제 시 플레이어 자원을 정리합니다. |

## 4. 비기능 요구사항

- 영상 바이트는 SnowThing 서버를 통과하지 않습니다.
- 최초 API 응답은 영상이 아닌 메타데이터만 포함합니다.
- 외부 URL 장애가 SnowThing API 장애로 전파되지 않아야 합니다.
- API DTO의 컬렉션은 `List.copyOf()`로 방어적 복사합니다.
- 서비스는 웹 세션이나 `SecurityContextHolder`를 직접 조작하지 않습니다.
- 컨트롤러는 Repository를 직접 호출하거나 Entity를 반환하지 않습니다.
- 예외는 `ErrorCode`와 `CustomException`으로 처리합니다.

## 5. 초기 리조트

`PHOENIX`, `VIVALDI`, `HIGH1`, `YONGPYONG`, `WELLI_HILLI`, `JISAN`, `KONJIAM`, `MUJU`, `EDEN_VALLEY`, `ELYSIAN`, `ALPENSIA`, `OAK_VALLEY`

## 6. 완료 조건

- 12개 리조트가 코드 기반으로 조회됩니다.
- 리조트 전체 보기와 개별 카메라 URL이 직접 접근 가능합니다.
- 비로그인 상태에서 동일하게 동작합니다.
- PC와 모바일 재생 정책이 구분됩니다.
- 운영 마이그레이션을 반복 실행해도 데이터가 중복되지 않습니다.
