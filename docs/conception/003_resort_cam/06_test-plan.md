# 리조트캠 테스트 계획

## 1. 마이그레이션

- 기존 6개 리조트의 FK와 PK가 유지되는지 검증
- 12개 리조트 코드의 누락·중복 검증
- 카메라 `(resort_id, code)` 중복 방지 검증
- 최초 적용과 재실행 결과가 동일한지 검증
- 잘못된 `source_type`, 음수 순서, 고아 FK 거부 검증

## 2. 백엔드

- 비로그인 요청 200
- 리조트와 카메라 정렬
- 비활성 리조트와 카메라 제외
- 카메라가 없는 리조트 제외
- 빈 결과는 `resorts: []`
- DTO 내부 리스트 수정 시 `UnsupportedOperationException`
- Controller → Service → Repository 계층 준수

## 3. 프런트엔드

- `/resort-cam` 기본 리다이렉트
- 리조트 전체 보기 직접 접근
- 개별 카메라 직접 접근
- 잘못된 리조트·카메라 코드의 안내 화면
- 뒤로가기·앞으로가기와 활성 메뉴 동기화
- 데스크톱 IntersectionObserver 진입·이탈
- 동시 자동재생 최대 6개
- 모바일 자동재생 금지
- HLS 인스턴스와 이벤트 정리
- HLS·YouTube·iframe·외부 링크 렌더러 분기
- 오류 카드 재시도와 원본 링크
- 다크 모드와 반응형 레이아웃

## 4. 외부 소스 호환성

초기 데이터별로 다음 결과를 기록합니다.

```text
리조트 / 카메라 / 원본 호스트 / 예상 유형 / PC / 모바일 / fallback / 확인일
```

외부 영상은 CI에서 안정적으로 재현되지 않으므로 단위 테스트에서는 플레이어 어댑터를 모킹하고, 실제 소스 검증은 별도 수동 체크리스트로 관리합니다.

## 5. 회귀 검증

- 회원가입·프로필 리조트 선택이 12개 데이터에서도 동작
- 기존 회원의 `member_resort` 관계 유지
- 라이브톡 `ResortTag` 동작 유지
- 홈과 상단 메뉴 링크 정상 이동
- 백엔드 `spotlessCheck test`, 프런트엔드 `lint build`
