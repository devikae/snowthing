# 이메일 인증 요구사항

## 1. 목표

회원가입 전에 이메일 소유권을 확인하고, 같은 이메일을 비밀번호 재설정 수단으로 사용합니다. 기존 세션 인증과 `Member` 도메인은 유지합니다.

## 2. 기능 요구사항

| ID | 요구사항 |
|---|---|
| EV-F-001 | 회원가입 화면에서 이메일 사용 가능 여부를 확인할 수 있어야 합니다. |
| EV-F-002 | 사용 가능한 이메일로 숫자 6자리 가입 인증번호를 발송해야 합니다. |
| EV-F-003 | 인증번호를 확인한 뒤 15분 동안 한 번만 사용할 수 있는 가입 토큰을 발급해야 합니다. |
| EV-F-004 | 유효한 가입 토큰이 없으면 회원을 생성하지 않아야 합니다. |
| EV-F-005 | 이메일 중복은 사전 확인, 가입 서비스 재확인, DB UNIQUE 제약조건으로 방어해야 합니다. |
| EV-F-006 | 비밀번호 재설정 요청은 계정 존재 여부와 관계없이 같은 상태 코드와 본문을 반환해야 합니다. |
| EV-F-007 | 재설정 인증 완료 후 15분 동안 한 번만 사용할 수 있는 재설정 토큰을 발급해야 합니다. |
| EV-F-008 | 비밀번호 변경과 재설정 토큰 소비는 같은 트랜잭션에서 처리해야 합니다. |
| EV-F-009 | 비밀번호 변경 후 해당 회원의 기존 로그인 세션과 라이브톡 연결을 종료해야 합니다. |
| EV-F-010 | 기존 회원의 로그인은 유지하고, 비밀번호 재설정을 완료하면 이메일 인증 시각을 기록해야 합니다. |
| EV-F-011 | 인증번호 재발송 시 이전 번호는 즉시 사용할 수 없게 해야 합니다. |
| EV-F-012 | SES가 접수한 메시지 ID와 발송 성공·실패 상태를 기록해야 합니다. |
| EV-F-013 | 이메일 주소 변경, 이메일 ID 찾기와 마케팅 메일은 제공하지 않습니다. |

## 3. 비기능 요구사항

- 인증번호 원문, 일회용 토큰 원문과 전체 이메일 주소를 애플리케이션 로그에 남기지 않습니다.
- 인증번호는 5분, 인증 완료 토큰은 15분 후 만료합니다.
- 재발송은 60초 이후 허용합니다.
- 이메일별 시간당 5회, IP별 시간당 20회로 발송을 제한합니다.
- 인증번호 입력 실패는 요청당 5회로 제한합니다.
- SES 연결·응답 시간에 상한을 두고 장애 시 `503`을 반환합니다.
- DTO의 컬렉션 필드는 방어적으로 복사하고 예외는 `ErrorCode`와 커스텀 예외로 통일합니다.
- 서비스 레이어는 `HttpSession`이나 `SecurityContextHolder`를 직접 사용하지 않습니다.

## 4. 완료 기준

- 신규 회원이 이메일 인증 없이 가입할 수 없습니다.
- 동일 이메일의 동시 가입 요청에서도 회원은 한 명만 생성됩니다.
- 존재하지 않는 계정의 비밀번호 재설정 요청으로 가입 여부를 확인할 수 없습니다.
- 만료·재사용·용도 불일치 토큰이 모두 거부됩니다.
- 비밀번호 재설정 후 기존 세션으로 보호 API를 호출할 수 없습니다.
- MySQL 8 운영 마이그레이션과 SES 실패 경로를 자동 테스트로 검증합니다.
