# 이메일 인증 테스트 계획

## 1. 정규화와 중복

- 이메일 앞뒤 공백 제거와 소문자 통일
- 점과 `+` 주소를 임의 변경하지 않음
- 이메일 사용 가능·중복 응답
- 중복 확인 후 동시 가입 경쟁에서 DB UNIQUE가 최종 차단

## 2. 가입 인증

- 6자리 번호 생성과 앞자리 0 보존
- DB에 인증번호 원문이 저장되지 않음
- 올바른 번호 확인과 15분 토큰 발급
- 잘못된 번호 5회 이후 잠금
- 5분 경계 만료
- 재발송 후 이전 번호·요청 UUID 무효화
- 가입 토큰의 이메일·용도 불일치 차단
- 가입 토큰 1회 소비와 동시 재사용 차단
- 인증 없이 `POST /api/v1/members` 호출 시 회원 미생성

## 3. 비밀번호 재설정

- 존재·미존재 이메일의 HTTP 상태와 응답 본문 동일
- 미존재 이메일에는 SES 호출 없음
- 올바른 인증번호로 재설정 토큰 발급
- 재설정 토큰 만료·재사용·용도 불일치 차단
- 새 비밀번호 BCrypt 저장과 복잡도 검증
- 비밀번호 변경과 토큰 소비의 원자성
- 기존 회원의 `email_verified_at` 기록
- 기존 로그인 세션과 라이브톡 연결 종료

## 4. 발송 제한과 동시성

- 60초 이내 재발송 차단
- 이메일별 시간당 5회 초과 차단
- IP별 시간당 20회 초과 차단
- 중복 확인 API의 IP별 슬라이딩 60초 10회 초과 차단과 60초 경계 해제
- 중복 확인 제한 초과 시 회원 조회 미실행
- 같은 이메일의 동시 재발송에서 최종 번호 하나만 유효
- 제한된 요청이 SES를 호출하지 않음

## 5. SES 어댑터

- 성공 messageId 저장
- timeout·throttling·권한 오류·미검증 Identity를 발송 실패로 매핑
- AWS 오류 본문과 인증번호가 사용자 응답·로그에 노출되지 않음
- 발신자와 Configuration Set 전달 확인

## 6. 데이터베이스와 정리

- MySQL 8에서 `013` 최초 적용과 재실행
- UNIQUE·CHECK·인덱스 검증
- 기존 회원의 `email_verified_at`이 `NULL`로 유지됨
- 종료 후 24시간이 지난 인증 행만 삭제
- 진행 중이거나 아직 유효한 토큰은 삭제하지 않음

## 7. 프런트엔드

- 중복 확인 전 인증번호 발송 차단
- 이메일 변경 시 기존 중복 확인·인증 상태 초기화
- 재발송 대기 초 표시
- 번호 만료와 실패 횟수 오류 표시
- 인증 완료 후 회원가입 제출 가능
- 로그인 화면에서 비밀번호 재설정 진입
- 계정 존재 여부를 구분하지 않는 안내 표시
- 재설정 완료 후 로그인 화면 이동

## 8. 전체 회귀

- 기존 회원가입·로그인·로그아웃·프로필 테스트 갱신
- 기존 세션 쿠키와 CSRF 정책 유지
- 라이브톡 로그아웃·세션 폐기 회귀 테스트
- 백엔드 Spotless와 전체 테스트
- 프런트엔드 ESLint와 production build
- `git diff --check`
