# 스키장 캐릭터 테스트와 관계 지도 (2026-11-06)

## 목표

처음 유입을 최대한 넓힌다. 가입 없이 테스트를 하고, 두 경로로 퍼지게 한다.

| 산출물 | 퍼지는 곳 | 보는 사람이 움직이는 이유 |
|---|---|---|
| 캐릭터 카드 | 인스타 스토리 | 나는 뭐가 나올까 |
| 관계 지도 링크 | 카톡 개인 메시지, 동호회 단톡 | 나는 이 사람들과 어떤 사이일까 |

## 사용자 결정 (고정)

1. 안쪽 바탕은 MBTI 16유형이지만 화면, API 응답, 공유 카드에 MBTI라는 말과 네 글자를 보여주지 않는다. 예외는 사용자가 확정한 이름 "대문자 P 대장님" 하나다.
2. MBTI를 입력받지 않는다. 스키장 상황을 고르면 결과가 나온다.
3. 직업 8개와 수식어로 보여주고, 안쪽은 16가지로 나뉜다.
4. 모임 링크 하나로 개인과 동호회를 모두 처리한다. 들어온 사람은 각자 자기가 가운데 있는 지도를 본다.
5. 링크 만들기는 어렵지 않아야 한다. 모임을 만드는 단계를 따로 두지 않는다.
6. 궁합은 널리 알려진 경향을 참고해 직접 작성한 16x16 표로 정한다. 정확한 궁합이라고 표현하지 않는다.
7. 지도는 내가 가운데이고 위로 갈수록 잘 맞는 사람이다.
8. 이번 단계는 로컬 작업이다. PR과 배포는 하지 않는다. 이미지는 임의로 직업마다 1장 만들어 진행한다.

## 사용자 흐름

1. `/character-test`에서 스키 또는 보드를 고른다. 타입에는 영향을 주지 않는다.
2. 질문 15개에 답한다. 순서는 섞어서 보여주고 묶음 이름은 보여주지 않는다.
3. 결과 화면: 캐릭터, 이름, 고른 답을 근거로 한 특성 설명, 스탯, 나와 찰떡인 타입. 재미로 보는 결과라고 표시한다.
4. 카드 이미지를 공유한다. 지원되는 폰은 공유 창, 안 되면 이미지 저장으로 대체한다.
5. 결과 아래에 내가 가운데 있고 주변이 빈자리인 지도를 보여준다. 버튼은 "같이 타는 사람 부르기" 하나다.
6. 처음 누를 때 닉네임만 입력한다. 모임이 자동으로 만들어지고 공유 창이 뜬다. 모임 이름은 "OO의 모임"으로 자동으로 붙는다.
7. 링크를 받은 사람은 테스트를 하고 닉네임을 넣으면 모임에 들어온다. 이 사람 화면에도 같은 버튼이 있고, 자기 모임을 또 만들 수 있다.

답변은 서버에 보내기 전까지 브라우저에만 있다. 닉네임을 넣어 모임에 들어갈 때 처음 서버에 저장한다. 카드만 만들고 떠나는 사람의 데이터는 저장하지 않는다.

## 궁합

- 5단계, 위에서 아래로: 찰떡, 같이 타요, 무난, 티격태격, 각자 타요.
- 16x16 표는 대칭이라 136개 조합이다. 표는 한 파일에 조합별로 드러나게 적어 사용자가 쉽게 고칠 수 있게 한다.
- 초안은 많이 도는 MBTI 궁합 경향을 기억에 기대어 참고했다. 출처를 검증하지 않았고 공식 자료도 아니다. 남의 설명 문장과 표 이미지는 가져오지 않고, 스키장에서 어색한 조합은 고친다.
- 궁합 점수는 16~100점이다. 궁합표 등급(찰떡 60, 같이 타요 50, 무난 40, 티격태격 28, 각자 타요 16), 습관(질문별 차이 0칸 10점, 1칸 6점, 2칸 0점, 합계 0~30), 유형 답변 일치(12개 중 같은 수를 0~10점으로 환산)를 더한다.
- 화면의 단계 이름은 궁합표 등급이 아니라 최종 점수로 정한다. 찰떡 78점 이상, 같이 타요 68점 이상, 무난 57점 이상, 티격태격 45점 이상, 나머지는 각자 타요다. 같은 등급 안에서도 사람이 갈리고 경계가 겹치게 하려는 것이다. 배점과 경계는 초안이고 무작위 답변 분포를 기준으로 잡았다.
- 같은 단계 안의 순서는 점수, 그다음 참여자 ID 순이다.
- 화면에 "재미로 보는 궁합"이라고 표시한다.

## 지도

- 내가 정중앙에 있고 가까울수록 잘 맞는 동심원 지도다. 안쪽부터 찰떡, 같이 타요, 무난, 티격태격, 각자 타요 원이고, 바탕은 눈밭과 나무이고 원은 안쪽으로 갈수록 희다. 색은 나를 표시하는 강조색 하나만 쓴다. 각 원 위쪽과 지도 옆에 단계 이름과 인원수를 표시한다.
- 전원을 얼굴만 작게 그린다. 정사각형이라 스크롤 없이 한눈에 보이고, 사람 수에 따라 지도 크기를 정한다. 겹치면 같은 원을 따라 옆으로 민다.
- 각 사람 아래에 닉네임과 점수를 함께 표시한다.
- 사람을 누르면 나와 이어지는 선과 직업, 단계, 습관 차이 한 줄을 보여준다.
- 혼자 있을 때는 내 주변에 빈자리를 흐리게 보여준다.
- 지도도 이미지로 저장할 수 있고, 닉네임을 가리는 옵션을 둔다. 맨 아래 단계의 문구는 놀림이 아니라 농담으로 쓴다.

## 그림 구조

- 카드는 저장해 둔 이미지가 아니다. 브라우저가 canvas에서 배경, 글자, 스탯을 그리고 캐릭터와 장비 그림을 겹쳐 1080x1920 PNG를 만든다.
- 그림은 직업별 캐릭터 8장, 스키 1장, 직업 의상에 맞춘 보드 8장이다. 장비는 캐릭터 옆에 겹쳐서 16장을 따로 그리지 않는다. 지도와 결과 화면도 같은 방식이다.
- 배경색은 직업마다 다르고, 캐릭터 옷과 겹치지 않는 색을 쓴다.
- 지금 그림은 코드로 그린 임시본이다(`scripts/generate-character-test-images.py`).

## 데이터

답변은 15자리 문자열, 유형은 내부 코드로 저장한다. API 응답에는 유형 코드 대신 직업 코드와 계획형, 즉흥형 구분만 내보낸다.

```
character_group
  character_group_id BIGINT PK, public_id UUID UNIQUE, name, owner_participant_id NULL,
  created_at, updated_at

character_participant
  character_participant_id BIGINT PK, public_id UUID UNIQUE, character_group_id FK,
  nickname, sport, answers CHAR(15), type_code CHAR(4), access_token_hash CHAR(64) UNIQUE,
  created_at
  UNIQUE(character_group_id, nickname), INDEX(character_group_id, character_participant_id)
```

- 마이그레이션: `036_migration_character_test.sql`. 시각은 KST `DATETIME(6)`이다.
- 회원 테이블과 연결하지 않는다. 비회원 기능이라 회원 차단, 쪽지, 프로필과 분리한다.
- IP를 테이블에 저장하지 않는다.

## API

유형 계산과 궁합 계산은 서버에서 한다. 응답 형식은 기존 `ErrorCode` 규칙을 따른다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/character-groups` | 답변과 닉네임으로 모임 생성, 만든 사람 참여, 접근 토큰 1회 반환 |
| GET | `/api/v1/character-groups/{publicId}` | 모임 이름과 인원수 등 링크 미리보기용 공개 정보 |
| POST | `/api/v1/character-groups/{publicId}/participants` | 답변과 닉네임으로 참여, 접근 토큰 1회 반환 |
| GET | `/api/v1/character-groups/{publicId}/map` | 토큰 소유자 기준 지도 |
| DELETE | `/api/v1/character-participants/me` | 본인 나가기 (행 삭제) |

- 접근 토큰은 충분히 긴 임의 값이고 서버에는 해시만 저장한다. 브라우저에 기억하고, 개인 복귀 링크는 토큰을 URL fragment에 담아 서버 로그에 남지 않게 한다.
- 토큰이 없거나 모임 소속이 아니면 지도 요청은 404다. 숨긴 리소스는 404라는 기존 규칙을 따른다.
- 공개 경로와 CSRF 처리는 기존 정책대로 메서드와 경로를 정확히 지정한다. 편의를 위해 예외를 넓히지 않는다.

## 제한과 악용 방지

- 닉네임: 회원 규칙과 같은 `^[a-zA-Z0-9가-힣]{2,10}$`, 모임 안에서만 고유하다. 금칙어 기능이 아직 없어 코드에 작은 목록을 두고, 나중에 관리 기능으로 옮긴다.
- 모임 최대 50명이다.
- `ContentWriteRateLimiter`에 생성과 참여 Action을 추가한다. 친구들이 같은 와이파이로 들어올 수 있어 IP 제한은 넉넉히 둔다.
- 7일 동안 새 참여가 없는 모임은 스케줄러가 지운다. 보관 기간 7일은 사용자가 정했다(2026-11-06).

## 공유와 검색

- 카드 이미지는 브라우저에서 만든다. 서버 이미지 변환 예산을 쓰지 않는다.
- 카카오 SDK 키는 쓰지 않는다. Web Share API와 링크 복사로 처리한다. 외부 API 키는 서버에만 두는 규칙과 충돌하지 않게 하려는 결정이다.
- `/character-test`는 검색 대상이다. 모임 페이지는 noindex이고 sitemap에서 뺀다. 링크 미리보기 문구는 모임 페이지 메타데이터에서 만든다.
- 참여 수, 후기 같은 근거 없는 숫자를 넣지 않는다. 외부 분석 SDK도 넣지 않는다.
- 라이브톡은 링크 게시를 막으므로 모임 링크 공유 경로에서 뺀다.

## 이미지

직업마다 1장, 총 8장의 임시 픽셀 그림을 코드로 만든다. 2등신의 귀여운 캐릭터를 방향으로 삼고, 특정 게임의 캐릭터나 이름은 쓰지 않는다. 파일만 바꾸면 교체되도록 경로를 고정한다. 스키와 보드 그림을 따로 만들지 않고 표시만 다르게 한다.

## 공개 전 결정 (이번 범위 밖)

- 개인정보: 지금까지 동의와 만 14세 확인은 회원가입에만 있고 처리방침도 초안이다. 비회원 닉네임과 답변 저장은 처음이라, 공개 전에 고지 문구, 보관 기간, 만 14세 처리를 확정해야 한다. 로컬 화면에는 저장 고지를 표시한다.
- MBTI는 상표이므로 대외 문구에서 쓰지 않는다. "대문자 P"는 예외로 결정되었고, 공개 전 한 번 더 볼 수 있다. 법률 검토는 하지 않았다.
- 최종 그림 8장의 제작 방식.

## 범위 밖

- 시즌권 칭호, 빙고, 스키 대 보드 대결, 시즌 결산.
- 회원 계정 연결, 친구 지도로 이동.
- 실제 공유 수 측정.

## 기존 설계와의 관계

- 라이더 도구는 서버 저장이 없었다. 이 기능은 지도를 양쪽에서 보여줘야 해서 처음으로 저장한다. 공유값을 fragment에 넣던 방식은 복귀 토큰에만 유지한다.
- 보더명함과 같이타요는 회원 기반이고 이 기능과 별개다. 나중에 결과에서 연결할 수 있다.
- 모집 게시판은 익명 작성을 막는데, 이 기능은 글쓰기가 아니고 내용이 닉네임뿐이라 예외로 둔다.

## 구현 중 추가한 것 (IKA-27)

설계에 없던 부분을 구현하며 정한 내용이다. 사용자 결정 항목은 바꾸지 않았다.

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/character-test/result` | 답변으로 결과만 계산한다. 저장하지 않는다 |

- 추가 이유: 모임에 들어가기 전 결과 화면에도 유형 판정이 필요한데, 판정은 서버에서만 한다. 답변은 계산에만 쓰이고 남지 않는다. "저장 전까지 브라우저에만 있다"는 문장은 "닉네임을 넣기 전까지 서버에 저장되지 않는다"로 읽는다.
- 쓰기 제한 없음: DB에 쓰지 않는 계산이고, 제한기를 태우면 오히려 요청마다 DB 쓰기가 생긴다.
- 접근 토큰은 전용 헤더 `X-Character-Token`으로 보낸다. `Authorization: Bearer`는 기존 API 토큰 필터가 받으므로 쓰지 않는다.
- CSRF는 예외 없이 기존 방식을 쓴다. 비회원도 `/api/v1/csrf`로 토큰을 받아 `X-XSRF-TOKEN`으로 보낸다.
- 지도 응답의 `me.answers`는 본인에게만 돌려준다. 복귀 링크로 다른 기기에서 들어와도 카드와 내 모임 만들기가 되게 하려는 것이다. 다른 사람의 답변은 내보내지 않는다.
- 결과에 `highlightQuestions`(고른 답을 근거로 보여 줄 질문 번호, 축마다 1개)를 넣었다. 축 이름 없이 근거를 보여 주기 위해서다.
- 코드: 직업 `CAPTAIN`, `RESORT_INSIDER`, `HYPE`, `MOOD_MAKER`, `GRINDER`, `HOT_PACK`, `GEAR_GEEK`, `RESORT_OUTSIDER`. 단계 `BEST`, `GOOD`, `NEUTRAL`, `BICKER`, `APART`. 오류 `CHARACTER_001`~`CHARACTER_005`.

### 나가기

- 만든 사람이 나가면 모임은 남고 `owner_participant_id`가 NULL이 된다. 권한을 넘기지 않는 이유는 비회원 모임에 넘길 기준이 없어서다.
- 마지막 사람이 나가면 모임도 지운다.
- 다른 사람을 내보내는 기능은 첫 버전에 두지 않는다 (2026-11-06 사용자 결정). 사람은 본인이 나가야만 지도에서 빠진다.
- `updated_at`은 새 참여 때만 바꾼다. 나가기로는 7일 보관 기간이 늘지 않는다.

### 제한과 표

- `CHARACTER_GROUP_CREATE`는 1초 1건, 시간당 60건. `CHARACTER_GROUP_JOIN`은 1초 1건, 시간당 300건이다. IP 단위다. 같은 와이파이에서 동시에 들어와 429가 나면 화면이 1.2초 뒤 한 번 다시 보낸다.
- 궁합표는 `backend/src/main/resources/character-test/compatibility.csv`다. 한 줄이 한 조합이고, 빠지거나 겹치면 서버가 기동하지 않는다.
- 초안 분포: 찰떡 17, 같이 타요 29, 무난 39, 티격태격 20, 각자 타요 31. 찰떡과 각자 타요는 지시받은 경향을 그대로 적었고, 나머지는 같은 쪽 성향끼리는 같이 타요, 어긋나면 티격태격에 가깝게 규칙으로 채웠다. 사용자 검수 대상이다.

### 화면

- 경로: 테스트 `/character-test`, 모임 `/character-test/g/{publicId}`, 복귀 링크 `/character-test/g/{publicId}#t={토큰}`. 복귀 링크를 열면 토큰을 저장하고 주소에서 지운다.
- 접근 토큰은 브라우저 localStorage에 둔다. XSS가 나면 읽힐 수 있지만, 비회원이라 세션이 없고 권한이 지도 하나로 좁다. HttpOnly 쿠키는 모임마다 다른 토큰을 두기 어렵다.
- 점수 때문에 다른 사람의 답을 내보내지 않는다. 지도 응답에는 점수와 습관 질문별 차이(0~2)만 담는다.
- 저장 이미지에서 닉네임을 가리면 모임 이름에 든 만든 사람 닉네임도 "우리 모임"으로 바꾼다.
- 지도는 자동으로 갱신하지 않고 새로고침 버튼을 둔다.
