# 1:1 문의 게시판

## 배경

- 지금 문의 창구는 푸터의 문의 메일(82snowthing@gmail.com)뿐이다. 회원이 남긴 문의와 답변을 서비스 안에서 이어서 볼 수 없다.
- 회원이 1:1 문의를 누르면 자기가 작성한 문의만 보고, 관리자는 그 문의에 댓글로 답변한다.

## 요구사항

- 문의 작성은 로그인 회원만 한다. 익명 작성과 익명 댓글은 허용하지 않는다.
- 회원은 자기 문의만 조회한다. 관리자는 전체 문의를 조회한다.
- 관리자 답변은 기존 댓글로 남긴다.
- 목록에 답변 대기와 답변 완료 배지를 표시한다. 답변 완료는 관리자 댓글이 하나 이상 있는 상태다.
- 알림(메일, 헤더 배지 등)은 이번 범위가 아니다. 추후 알림 설계에서 연동한다.

## 구현 방식

기존 게시글에 `INQUIRY` 카테고리를 추가하고 게시글, 이미지, 댓글 구조를 재사용한다. 공지사항(`NOTICE`)의 카테고리 추가 방식과 중고장터(`MARKET`)의 공개 목록 제외 방식을 함께 따른다.

검토한 대안은 다음과 같다.

- 별도 `inquiry` 도메인과 테이블: 처음부터 격리되어 노출 위험이 없지만 글쓰기, 이미지, 댓글 UI를 다시 만들어야 한다.
- 게시글 공개 범위 컬럼(`visibility`) 추가: 비밀글로 확장할 수 있지만 지금 필요 없는 일반화이고 마이그레이션과 쿼리 수정 범위가 크다.

선택한 방식의 위험은 공개 경로 하나를 빠뜨리면 다른 회원의 문의가 노출되는 것이다. 비공개 카테고리 기준을 한 곳에 모으고 노출 경로마다 테스트를 둔다.

## 권한 규칙

| 동작 | 비로그인 | 다른 회원 | 작성자 | 관리자 |
|---|---|---|---|---|
| 문의 작성 | 401 | 가능(본인 글) | 가능 | 가능 |
| 목록 (`categoryCode=INQUIRY`) | 401 | 본인 글만 | 본인 글만 | 전체 |
| 상세 | 404 | 404 | 가능 | 가능 |
| 수정 | 거부 | 거부 | 가능 | 거부(기존 정책) |
| 삭제 | 거부 | 거부 | 가능 | 가능 |
| 댓글 조회, 작성, 대댓글 | 404 | 404 | 가능 | 가능 |
| 반응 | 404 | 404 | 404 | 404 |

- 남의 문의는 403이 아니라 404로 응답해 글의 존재 여부를 숨긴다. `rejectMarketPost`와 같은 방식이다.
- 수정 시 카테고리 전환을 양방향 모두 막는다. `INQUIRY`에서 나가면 관리자 답변이 공개되고, `INQUIRY`로 들어오면 기존 댓글 작성자의 댓글이 숨겨진다.
- 관리자는 문의 본문을 수정하지 않고 댓글로만 답변한다.

## 노출 차단 경로

| 경로 | 현재 | 처리 |
|---|---|---|
| 게시글 목록, 스크롤 (`PostRepositoryCustomImpl`) | `MARKET`만 제외 | 비공개 카테고리 {MARKET, INQUIRY} 제외. `categoryCode=INQUIRY` 지정 조회만 작성자 조건으로 허용 |
| `PostRepository` JPQL 2곳 | `'MARKET'` 하드코딩 | 비공개 카테고리 `NOT IN`으로 변경 |
| 근거 검색, AI 답변 보조, 라이브톡 봇 (`SearchVisibilitySql.POST_VISIBLE`) | `MARKET`만 제외 | `INQUIRY` 추가 |
| AI 멤버 반응 (`AiMemberQueryRepository`) | 게시판 화이트리스트(`BOARDS`) | 변경 없음, 테스트만 추가 |
| 상세, 댓글, 반응 API | 카테고리 검사 없음 | 권한 규칙 적용 |
| 프론트 홈, 상단 게시판 메뉴, 일반 글쓰기 카테고리 | 화면에서 카테고리 나열 | `INQUIRY` 제외 |
| 사이트맵 (`sitemap.ts`) | 게시글 URL 없음 | 변경 없음 |

## API

새 엔드포인트는 없다. 기존 API의 동작만 바뀐다.

| API | 변경 |
|---|---|
| `POST /api/v1/posts` (`INQUIRY`) | 로그인 필수, 익명 거부 |
| `GET /api/v1/posts?categoryCode=INQUIRY`, `/scroll` | 비로그인 401, 회원은 `member_id = 본인`, 관리자는 전체. ID 내림차순 |
| `GET /api/v1/posts` 전체와 다른 카테고리 | `INQUIRY` 제외 |
| `GET/PUT/DELETE /posts/{publicId}`, 댓글 API | 작성자나 관리자가 아니면 404 |
| `PUT/DELETE /posts/{publicId}/reaction` | `INQUIRY`이면 404 |

- `PostListResponse`에 `answered`(Boolean)를 추가한다. `INQUIRY`일 때만 값을 채우고 다른 카테고리는 `null`이다.
- `answered`는 `ROLE_ADMIN` 회원이 작성한 삭제되지 않은 댓글이 있는지로 계산한다. 새 컬럼은 두지 않는다.
- 구현에서는 목록 쿼리의 `EXISTS` 서브쿼리 대신, 목록을 가져온 뒤 그 글 ID 묶음으로 관리자 댓글이 있는 글을 한 번 더 조회한다. 기존 목록 쿼리가 ID 선별, 본문 조회로 나뉜 구조라 서브쿼리를 넣으면 조회 결과 형태를 바꿔야 한다. 쿼리는 한 번 늘지만 N+1은 없다.
- 기존 응답 필드는 바뀌지 않는다.

## 데이터

- `database/production/031_migration_inquiry_category.sql`: `post_category`에 `1:1 문의`, `INQUIRY`를 `INSERT ... WHERE NOT EXISTS`로 추가한다.
- 로컬 `DataInitializer`에 같은 시드를 넣는다.
- 테이블, 컬럼, 인덱스 변경은 없다. 회원당 문의 수가 적어 작성자 조건 인덱스는 두지 않고 `EXPLAIN`으로 확인한다. 신규 N:M 관계는 없다.

## 화면

기존 게시판 화면을 재사용하고 `INQUIRY`일 때만 분기한다.

- 진입: 로그인 상태 프로필 메뉴의 `1:1 문의`, 푸터 문의 메일 옆 링크. 공개 게시판 메뉴에는 넣지 않는다.
- 목록 `/posts?category=INQUIRY`: "내가 남긴 문의만 보입니다" 안내, 관리자는 "전체 문의". 답변 대기와 답변 완료 배지. 비로그인은 로그인 화면으로 보낸다.
- 작성 `/posts/create?category=INQUIRY`: 카테고리 고정, 익명 체크박스 숨김.
- 상세: 반응 버튼과 공유 숨김. 댓글 UI는 그대로 쓴다.
- 일반 글쓰기 카테고리 선택지에서 `INQUIRY`를 제외한다.

## 검증

- 회원 작성 성공, 비로그인과 익명 작성 거부.
- 회원 목록은 본인 글만, 관리자 목록은 전체, 비로그인 401.
- 다른 회원의 상세, 댓글 조회, 댓글 작성, 반응이 404.
- 전체 목록, 다른 카테고리 목록, 근거 검색, AI 멤버 조회에서 문의 제외.
- 카테고리 전환 양방향 거부.
- 관리자 댓글 작성 전후 `answered` 값, 관리자 댓글 삭제 시 답변 대기로 복귀.
- 백엔드 `./gradlew spotlessCheck test`, 프론트 `npm run lint`, `npm run build`.
