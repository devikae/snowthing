# 라이브톡 운영 도구와 회원 정지 기간 (IKA-115, 2026-11-24)

## 왜

- 11/24 아침 라이브톡에 음란한 말이 올라왔다. 관리자가 할 수 있는 조치는 IP 차단(그 사람의 최근 메시지 전부 삭제)뿐이었다. 한 번 실수한 사람까지 차단하기는 과하다.
- 금칙어는 글과 댓글에만 걸리고 라이브톡에는 걸리지 않았다(`chat_policy.md` 5절 3번 미구현).
- 도배가 터졌을 때 라이브톡 전체를 닫을 방법이 없었다(같은 문서 4번 미구현).
- 관리자 메뉴의 라이브톡 화면은 IP 차단 목록뿐이라, 대화를 보고 조치하려면 메인 화면으로 가야 했다.
- 회원 정지는 무기한이고 사유를 남길 곳이 없었다.
- 비회원은 첫 메시지를 보내기 전까지 자기 익명 닉네임을 몰랐고, 새로고침하면 내 메시지 표시가 사라졌다.

## 범위

- 포함: 메시지 한 줄 가리기, 라이브톡 금칙어 보류, 라이브톡 비상 닫기, 관리자 화면의 최근 대화와 조치 버튼, 회원 정지 기간과 사유와 자동 해제, 정지 회원 로그인 안내, 비회원 닉네임 미리 보기.
- 제외: 공지 팝업, 배너 관리 개편(사용자 결정으로 미룸), 정지 회원 로그인 허용(읽기 전용 정지, 사용자가 지금 방식 유지를 선택), 라이브톡 본문 저장과 가린 메시지 복구.

## A. 메시지 가리기

- `DELETE /api/v1/admin/chat/messages/{messageId}` (관리자만). 응답 204.
- 서버 최근 대화(30개 버퍼)에서 빼고, 모든 접속 화면에 기존 `PURGE_MESSAGES` 방송을 보낸다. 화면 쪽은 이미 이 방송을 처리하므로 바뀐 것이 없다.
- 버퍼에서 밀려난 메시지도 접속 중인 화면에는 남아 있을 수 있어, 버퍼에 없어도 방송은 보낸다. 메시지 ID는 무작위 UUID라 없는 ID를 방송해도 지워지는 것은 없다.
- 조치 기록: `CHAT_MESSAGE_HIDE`, 대상 `CHAT_MESSAGE`, 대상 ID는 메시지 ID, 사유 칸에는 보낸 사람 닉네임. 라이브톡은 본문을 저장하지 않는 정책이라 본문은 남기지 않는다. 그래서 가린 메시지는 되돌릴 수 없다.
- 방송과 버퍼 삭제는 조치 기록 커밋 뒤에 한다. 기록이 롤백되면 화면도 그대로 둔다(IP 차단과 같은 순서).
- 고르지 않은 안: 가린 메시지를 "관리자가 가린 메시지입니다"로 바꿔 보이기. 무엇이 있었는지 오히려 눈에 띄고, 본문을 저장하지 않아 되돌릴 일도 없다.

## B. 라이브톡 금칙어

- 글과 댓글의 금칙어 목록을 그대로 쓴다(`ContentFilterService.inspect`). 관리자는 검사하지 않고 AI 회원은 똑같이 검사한다.
- 걸린 메시지는 거절하지 않고 보낸 사람 연결 하나에만 돌려준다(`/user/queue/chat`). 다른 사람에게 방송하지 않고, 최근 대화에도 넣지 않고, 봇에도 넘기지 않는다. 걸린 것을 알아채고 표현을 바꿔 다시 보내지 못하게 하려는 선택이고 글, 댓글의 조용한 보류와 같다.
- 보내는 방법: 사용자 이름 자리에 웹소켓 세션 ID를 넣고 같은 세션 ID 헤더를 붙여 `convertAndSendToUser`로 보낸다. Spring은 이 경우 그 세션 하나로만 보낸다. 비회원은 Principal이 없어 이 방법만 된다.
- 보낸 사람이 새로고침하면 걸린 메시지는 사라진다(최근 대화에 없어서). 라이브톡은 본문을 저장하지 않아 보류 기록도 남기지 않는다. 운영 로그에는 "보류됨, 회원 여부"만 남긴다.
- 도배 판정에는 걸린 메시지도 센다.
- 고르지 않은 안: 전송 거절. 거절 문구를 보면 표현만 바꿔 다시 보낸다.

## C. 비상 닫기

- `system_config`의 `CHAT_ENABLED`(행이 없으면 열림). 관리자 대시보드에 "라이브톡 닫기, 다시 열기" 버튼을 둔다.
- 닫히면 관리자 말고는 보낼 수 없다(`CHAT_KILL_SWITCH_ACTIVE`, 이미 있던 오류 코드). 관리자는 닫은 이유를 안내할 수 있게 남긴다. AI 회원 대화도 막힌다.
- 바꾸면 기존 `CONFIG_UPDATED` 방송으로 접속 중인 화면에 바로 안내가 뜨고 입력칸이 잠긴다. 공개 설정(`/api/v1/public/configs`)에 `chatEnabled`를 더해 새로 들어온 화면도 안다.
- 읽기는 막지 않는다. 최근 대화는 그대로 보인다.

## D. 관리자 라이브톡 화면

- 관리자 메뉴 "라이브톡, IP 차단" 화면 위에 최근 대화(서버 버퍼 30개, 새것부터)를 두고 줄마다 가리기, 차단 버튼을 둔다. 차단 기간(1, 7, 30일)은 화면 위에서 한 번 고른다.
- 실시간 연결 없이 새로고침 버튼으로 다시 읽는다. 조치할 때 잠깐 여는 화면이라 연결을 하나 더 두지 않았다.
- 메인 라이브톡에도 관리자에게 "가리기" 버튼을 "차단" 옆에 둔다.

## E. 회원 정지 기간과 사유

### 저장

- `member.suspended_until DATETIME(6) NULL`(KST, NULL이면 무기한), `member.suspend_reason VARCHAR(255) NULL`. 정지 중일 때만 값이 있고 해제하면 둘 다 지운다.
- 기존 정지 회원은 NULL이라 지금처럼 무기한으로 남는다.

### API

- `POST /api/v1/admin/members/{publicId}/suspend` 본문 `{ "days": 1~365 | null, "reason": "최대 200자" | null }`. 본문이 없으면 무기한이라 예전 화면도 그대로 동작한다.
- 이미 정지된 회원을 다시 정지하면 기간과 사유를 새 값으로 바꾼다. 상태, 기간, 사유가 바뀌었을 때만 조치 기록을 남긴다. 기록 사유는 `7일: 라이브톡 욕설`, `무기한` 형태다.
- 응답과 회원 상세에 `suspendedUntil`, `suspendReason`을 더했다.

### 자동 해제

- 5분마다 스케줄러가 기간이 끝난 정지 회원을 최대 100명 푼다(`snowthing.member.suspension-expiry-cron`). 한 명씩 행 잠금을 잡고 다시 확인한 뒤 풀어서, 그 사이 관리자가 기간을 늘렸으면 풀지 않는다. 조치 기록은 관리자 없이 `MEMBER_REINSTATE`, 사유 `정지 기간 만료`.
- 로그인 경로마다 만료를 따로 보지 않고 한 곳에서 상태를 바꾼다. 쪽지 수신, 글 목록의 작성자 표시처럼 상태를 보는 곳이 많아서다. 대신 최대 5분 늦게 풀린다. 정지가 일 단위라 문제로 보지 않았다.
- 인덱스는 두지 않았다. 정지 회원이 몇 명뿐이고 5분마다 한 번 읽는다.

### 로그인 안내

- 정지 중 로그인하면 "이용이 정지된 계정입니다. 12월 1일 15:00에 풀립니다."를 보인다. 무기한이면 시각 없이 앞 문장만. 사유는 관리자 화면에만 둔다.
- 이메일 로그인: 예전에는 정지 확인이 비밀번호 검사 전이라 정지된 본인도 "이메일 또는 비밀번호가 올바르지 않습니다"를 받았다. 정지 확인을 비밀번호 검사 뒤로 옮겼다(`DaoAuthenticationProvider`의 사전, 사후 검사). 비밀번호가 틀리면 지금처럼 없는 계정과 같은 401이라 비밀번호를 모르는 사람은 계정 상태를 알 수 없다. 탈퇴 계정은 그대로 비밀번호 검사 전에 막는다.
- 소셜 로그인: 인증을 마친 본인에게만 오는 경로라 로그인 화면으로 돌려보낼 때 `until` 값을 붙인다.

## F. 비회원 닉네임 미리 보기

- `GET /api/v1/chat/me` → `{ "guestNickname": "졸린펭귄#4821" | null }`. 회원은 null. 비회원 닉네임은 원래 IP로 정해지는 값이라 새로 드러나는 정보는 없다. IP 원문은 내보내지 않는다. 캐시 금지.
- 화면은 접속하자마자 입력칸 위에 "내 닉네임 졸린펭귄#4821"을 보이고, 내 메시지를 닉네임으로 알아본다. 새로고침해도 내 메시지가 오른쪽에 남는다.
- 같은 공유기나 회사망을 쓰는 사람은 원래 닉네임이 같아서 그 사람 메시지도 "나"로 보인다. 지금도 서로 구분할 수 없는 상태라 새로 생긴 문제는 아니다.
