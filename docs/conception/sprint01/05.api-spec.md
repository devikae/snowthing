# Snowthing REST API 명세서 (REST API Specification)

## 1. 개요 (Overview)

Snowthing 플랫폼의 백엔드와 프론트엔드 간 통신을 위한 RESTful API 명세서입니다.
REST 자원 중심(Resource-Oriented) 명사형 URL 체계, 세션 기반 인증 (`JSESSIONID`), 비회원/익명 작성 지원, 게시글 상태 관리(`status`), 멱등 추천/비추천 처리, 계층형 댓글 DTO 파싱, 그리고 글로벌 에러 응답 규격을 적용하였습니다.

* **Base URL**: `/api/v1`
* **인증 방식**: Session Cookie (`JSESSIONID`, `HttpOnly`, `Secure`, `SameSite=Lax`)
* **데이터 포맷**: `application/json`
* **권한 체계**: `GUEST` (비회원), `ROLE_USER` (일반 회원), `ROLE_ADMIN` (최고 관리자)
* **게시글 상태 (`status`)**: `NORMAL` (정상), `HIDDEN` (관리자 숨김), `DELETED` (Soft Delete), `BLOCKED` (차단)

## 3. 회원 및 인증 API 상세 명세

### 3.1. 회원가입 (`POST /api/members`)
* **설명**: 신규 회원을 생성합니다.
* **Request Body**:
```json
{
  "email": "user@example.com",
  "password": "Password123!",
  "nickname": "신나는보더",
  "departureRegion": "서울 송파구",
  "bio": "주말마다 휘팍 가는 카빙 보더입니다.",
  "resortIds": [1, 2],
  "ridingStyleIds": [1, 3]
}
```
* **Response Body (201 Created)**:
```json
{
  "publicId": "a3b2c1d4-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
  "email": "user@example.com",
  "nickname": "신나는보더",
  "createdAt": "2026-08-08T10:00:00"
}
```

### 3.2. 세션 로그인 (`POST /api/auth/login`)
* **설명**: 회원 인증 후 세션 쿠키(`JSESSIONID`)를 발급합니다.
* **Request Header**: `Idempotency-Key` (선택적)
* **Response Header**: `Set-Cookie: JSESSIONID=...; Path=/api; HttpOnly; Secure; SameSite=Lax`
* **Response Body (200 OK)**:
```json
{
  "publicId": "a3b2c1d4-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
  "nickname": "신나는보더",
  "role": "ROLE_USER"
}
```

### 3.3. 내 프로필 수정 (`PUT /api/members/me`)
* **설명**: 내 프로필 정보 및 베이스 스키장/라이딩 스타일 중계 테이블 관계를 업데이트합니다.
* **Request Body**:
```json
{
  "nickname": "휘팍카빙마스터",
  "bio": "카빙 연습 중입니다!",
  "departureRegion": "경기 성남시",
  "resortIds": [1],
  "ridingStyleIds": [1, 2]
}
```

## 4. 게시글 API 상세 명세

`GET /api/v1/posts`에서 `viewType=BEST`를 사용한 전체 베스트 조회는 자유·익명·Q&A 등 전체 카테고리에서 추천 수 30 이상인 글만 최신순으로 반환합니다. `BEST`는 정렬 방식이 아니라 조회 범위이며, 조건을 충족하는 글이 없으면 빈 목록을 반환합니다. 전체글과 개별 게시판은 `viewType`을 생략하고 최신순으로 조회합니다.

최신순의 기준은 `created_at DESC, post_id DESC`입니다. CSV 이관처럼 저장 순서와 작성 시간이 다르더라도 작성 시간이 우선하며, 동일한 작성 시간에만 ID를 비교합니다. `/api/v1/posts/scroll` 커서도 같은 작성 시간·ID 복합 조건을 사용해 페이지 사이 누락이나 중복을 방지합니다. 기존 커서 토큰의 작성 시각·ID 필드를 그대로 사용합니다.

일반 게시글 생성·수정의 `imageUrls` 첨부 목록은 최대 10개이며 순서대로 표시합니다. 수정 시 필드가 없거나 null이면 기존 첨부를 유지하고, 명시적인 빈 배열은 첨부를 모두 해제합니다. 에디터 본문에 들어간 이미지는 이 첨부 개수에 포함하지 않습니다.

### 4.1. 게시글 작성 (`POST /api/posts`)
* **설명**: 게시글을 작성합니다. (회원 작성 및 비회원 익명 작성 모두 지원)
* **Request Header (선택)**: `Idempotency-Key: {UUID}`. 같은 키로 다시 보내면 새로 저장하지 않고 처음 201 응답을 그대로 돌려줍니다. 자세한 규칙은 [7. 작성 API 멱등 처리](#7-작성-api-멱등-처리-idempotency-key)를 따릅니다.
* **Request Body (회원 작성 시)**:
```json
{
  "categoryCode": "FREE",
  "title": "주말 휘팍 설질 어떤가요?",
  "content": "내일 아침에 출발하려는데 설질 괜찮은지 궁금합니다.",
  "isAnonymous": false,
  "imageUrls": [
    "https://cdn.snowthing.com/images/1.jpg"
  ]
}
```
* **Request Body (비회원 익명 작성 시)**:
```json
{
  "categoryCode": "ANONYMOUS",
  "title": "익명 질문입니다.",
  "content": "입문용 데크 추천 부탁드립니다.",
  "isAnonymous": true,
  "anonymousPassword": "AnonPassword123!"
}
```
* **Response Body (201 Created)**:
```json
{
  "publicId": "p9o8i7u6-5y4t-3r2e-1w0q-9a8b7c6d5e4f",
  "title": "주말 휘팍 설질 어떤가요?",
  "writerName": "익명 (123.456.***.***)",
  "status": "NORMAL",
  "createdAt": "2026-08-08T10:15:00"
}
```

### 4.2. 게시글 상세 조회 (`GET /api/posts/{publicId}`)
* **설명**: 게시글 상세 정보를 조회합니다. 일반 유저는 `NORMAL` 상태인 글만 조회 가능하며, `HIDDEN`/`BLOCKED` 글 조회 시 `404 Not Found` 또는 `403 Forbidden`을 반환합니다. (관리자는 모든 상태 조회 가능)
* **Response Body (200 OK)**:
```json
{
  "publicId": "p9o8i7u6-5y4t-3r2e-1w0q-9a8b7c6d5e4f",
  "categoryName": "자유게시판",
  "title": "주말 휘팍 설질 어떤가요?",
  "content": "내일 아침에 출발하려는데 설질 괜찮은지 궁금합니다.",
  "status": "NORMAL",
  "viewCount": 42,
  "commentCount": 2,
  "likeCount": 12,
  "dislikeCount": 1,
  "writer": {
    "publicId": "a3b2c1d4-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
    "nickname": "신나는보더",
    "profileImageUrl": "https://cdn.snowthing.com/profiles/1.jpg"
  },
  "images": [
    "https://cdn.snowthing.com/images/1.jpg"
  ],
  "createdAt": "2026-08-08T10:15:00"
}
```

### 4.3. 게시글 추천/비추천 명령 (`PUT/DELETE /api/v1/posts/{publicId}/reaction`)
* **설명**: `type` query parameter로 추천(`LIKE`) 또는 비추천(`DISLIKE`) 상태를 명시적으로 생성하거나 취소합니다. 같은 PUT 또는 DELETE를 반복해도 최종 상태가 바뀌지 않습니다.
* **Request**:
```http
PUT /api/v1/posts/{publicId}/reaction?type=LIKE
DELETE /api/v1/posts/{publicId}/reaction?type=LIKE
```
* **Response Body**:
```json
{
  "active": true,
  "type": "LIKE",
  "likeCount": 12,
  "dislikeCount": 1,
  "changed": true,
  "message": "추천했습니다."
}
```

`changed=false`는 이미 요청한 최종 상태였다는 뜻이며 오류가 아닙니다. 화면의 버튼은 다시 누르면 취소되는 것처럼 동작하지만, 서버 계약은 현재 상태를 뒤집는 토글이 아니라 PUT 활성화와 DELETE 취소로 분리합니다.

## 5. 댓글 및 대댓글 계층형 API 상세 명세

### 5.1. 댓글/대댓글 계층형 목록 조회 (`GET /api/posts/{publicId}/comments`)
* **설명**: 게시글의 모든 댓글을 `Single Query`로 가져와 자바 메모리에서 부모-자식 트리 구조(`children: []`)로 재조립하여 반환합니다.
* **Response Body (200 OK)**:
```json
{
  "postId": "p9o8i7u6-5y4t-3r2e-1w0q-9a8b7c6d5e4f",
  "totalCommentCount": 3,
  "comments": [
    {
      "commentId": 101,
      "parentId": null,
      "writerName": "신나는보더",
      "content": "휘팍 오늘 팽팽하고 설질 최고입니다!",
      "isDeleted": false,
      "createdAt": "2026-08-08T10:20:00",
      "children": [
        {
          "commentId": 102,
          "parentId": 101,
          "writerName": "익명 (211.200.***.***)",
          "content": "오! 야간에도 슬로프 열려있나요?",
          "isDeleted": false,
          "createdAt": "2026-08-08T10:22:00",
          "children": []
        }
      ]
    },
    {
      "commentId": 103,
      "parentId": null,
      "writerName": "익명 (112.150.***.***)",
      "content": "삭제된 댓글입니다.",
      "isDeleted": true,
      "createdAt": "2026-08-08T10:25:00",
      "children": []
    }
  ]
}
```

### 5.2. 댓글/대댓글 작성 (`POST /api/posts/{publicId}/comments`)
* **설명**: 원댓글 또는 대댓글을 작성합니다. (대댓글 작성 시 `parentId` 지정, 비회원 작성 시 `anonymousPassword` 필수)
* **Request Header (선택)**: `Idempotency-Key: {UUID}`. 경로의 게시글 `publicId`까지 같은 요청으로 판별합니다. [7. 작성 API 멱등 처리](#7-작성-api-멱등-처리-idempotency-key) 참고.
* **Request Body (비회원 대댓글 작성 시)**:
```json
{
  "parentId": 101,
  "content": "야간에도 정설 잘 되어 있습니다!",
  "isAnonymous": true,
  "anonymousPassword": "AnonComment123!"
}
```
* **Response Body (201 Created)**:
```json
{
  "commentId": 104,
  "parentId": 101,
  "writerName": "익명 (211.200.***.***)",
  "content": "야간에도 정설 잘 되어 있습니다!",
  "createdAt": "2026-08-08T10:30:00"
}
```

### 5.3. 댓글 삭제 (`DELETE /api/comments/{commentId}`)
* **설명**: 댓글을 Soft Delete (`is_deleted = true`) 처리합니다. 비회원 댓글 삭제 시 `anonymousPassword`를 쿼리 파라미터 또는 Body로 전달합니다.
* **Request Body (비회원 삭제 시)**:
```json
{
  "anonymousPassword": "AnonComment123!"
}
```
* **Response Body (200 OK)**:
```json
{
  "message": "댓글이 정상적으로 삭제(Soft Delete) 처리되었습니다.",
  "commentId": 104
}
```

## 6. 실패 응답 규격 (Global Error Response Standard)

모든 API 에러 응답은 일관된 JSON 스키마 구조로 반환됩니다.

### 6.1. 에러 응답 JSON 포맷 (Error Response JSON)
```json
{
  "timestamp": "2026-08-08T10:20:00",
  "status": 400,
  "code": "INVALID_INPUT_VALUE",
  "message": "입력값이 유효하지 않습니다.",
  "errors": [
    {
      "field": "email",
      "value": "invalid-email-format",
      "reason": "올바른 이메일 형식이 아닙니다."
    }
  ]
}
```

### 6.2. HTTP Status Code 별 에러 코드 명세

| Status | Error Code | 설명 및 발생 조건 |
| :--- | :--- | :--- |
| **`400 Bad Request`** | `INVALID_INPUT_VALUE` | DTO 유효성 검사 실패 (이메일 형식, 비밀번호 길이 등) |
| | `DUPLICATE_EMAIL` | 이미 존재하는 이메일로 가입 시도 |
| | `DUPLICATE_NICKNAME` | 이미 존재하는 닉네임으로 가입/수정 시도 |
| **`401 Unauthorized`** | `UNAUTHORIZED` | 비로그인 유저가 회원 전용 API 호출 |
| | `INVALID_CREDENTIALS` | 로그인 시 이메일 또는 비밀번호 불일치 |
| | `LOGIN_REQUIRED` | 로그인하지 않은 채 회원 전용 API 요청 (AUTH_020, "로그인이 필요합니다.") |
| **`403 Forbidden`** | `ACCESS_DENIED` | 타인의 글/댓글 수정·삭제 시도 권한 없음 |
| | `INVALID_ANON_PASSWORD` | 비회원 글/댓글 수정·삭제 시 비밀번호 불일치 |
| **`404 Not Found`** | `RESOURCE_NOT_FOUND` | 존재하지 않거나 숨김/삭제 처리된 게시글/댓글/회원 조회 |
| **`400 Bad Request`** | `IDEMPOTENCY_001` | `Idempotency-Key` 헤더가 UUID 형식이 아님 (빈 값 포함) |
| **`409 Conflict`** | `COMMENT_UPDATE_CONFLICT` | 다른 요청에서 댓글을 먼저 수정한 경우 |
| | `IDEMPOTENCY_002` | 같은 `Idempotency-Key`로 다른 내용의 작성 요청이 이미 처리됨 |
| **`500 Internal Error`**| `INTERNAL_SERVER_ERROR` | 서버 내부 비즈니스 로직 예외 발생 |

## 7. 작성 API 멱등 처리 (Idempotency-Key)

응답이 네트워크에서 사라진 뒤 사용자가 다시 누르는 경우처럼, 같은 작성 요청이 두 번 도착해도 글이 한 번만 저장되도록 한다 (IKA-21). 설계: `docs/conception/022_write_idempotency/01_design.md`.

* **적용 API**

| API | 대상 종류 |
| :--- | :--- |
| `POST /api/v1/posts` | `POST` |
| `POST /api/v1/posts/{publicId}/comments` (대댓글 포함) | `COMMENT` |
| `POST /api/v1/resort-reports` | `RESORT_REPORT` |
| `POST /api/v1/carpools` | `CARPOOL` |
| `POST /api/v1/market-listings` | `MARKET_LISTING` |

* **헤더**: `Idempotency-Key: 3f2b8c1e-5d4a-4e7b-9c0d-1a2b3c4d5e6f`. UUID 형식(36자, 대소문자 구분 없음)만 받는다. 헤더가 없으면 예전과 똑같이 매번 새로 저장한다.
* **같은 요청 판별 범위**: 작성자(회원 ID, 비로그인은 IP) + 대상 종류 + 키. 같은 키라도 대상 종류나 작성자가 다르면 서로 다른 요청이다.
* **응답 규칙**

| 상황 | 응답 |
| :--- | :--- |
| 처음 보는 키 | 평소처럼 저장하고 `201 Created` |
| 같은 키, 같은 내용 (재전송, 동시 전송 포함) | 저장하지 않고 처음 `201 Created` 응답 본문을 그대로 |
| 같은 키, 다른 내용 (본문 또는 댓글 대상 게시글이 다름) | `409 Conflict`, `IDEMPOTENCY_002` |
| 키 형식 오류 | `400 Bad Request`, `IDEMPOTENCY_001` |
| 저장 실패 (검증 오류 등) | 원래 오류 응답. 기록도 함께 롤백되므로 같은 키로 다시 시도할 수 있다 |

* **쓰기 제한과의 순서**: 이미 처리된 키의 재전송은 작성 연타 제한(`COMMON_003`)보다 먼저 확인해 429 대신 처음 응답을 받는다. 새 키는 기존처럼 제한을 거친다.
* **보관 기간**: 24시간. 지난 기록은 매시 35분 스케줄러가 지우고, 그 뒤 같은 키는 새 요청으로 처리된다.
* **클라이언트 규칙**: 폼마다 시도할 때 UUID를 만든다. 같은 내용으로 다시 시도할 때는 같은 키를 쓰고, 성공하면 다음 글을 위해 새 키를 만든다. 내용을 고치면 새 키를 쓴다.

## 8. 스키장 캐릭터 테스트 API (비회원)

가입 없이 쓰는 기능이다 (IKA-27). 설계: `docs/conception/024_character_test/01_design.md`

| Method | Endpoint | 설명 | 토큰 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/character-test/result` | 답변으로 결과 계산. 저장하지 않음 | 없음 |
| `POST` | `/api/v1/character-groups` | 모임 생성과 만든 사람 참여 | 없음 |
| `GET` | `/api/v1/character-groups/{publicId}` | 모임 이름과 인원수 | 없음 |
| `POST` | `/api/v1/character-groups/{publicId}/participants` | 모임 참여 | 없음 |
| `GET` | `/api/v1/character-groups/{publicId}/map` | 토큰 소유자 기준 지도 | 필수 |
| `DELETE` | `/api/v1/character-participants/me` | 본인 나가기 (행 삭제) | 필수 |

* **토큰**: `X-Character-Token` 헤더. 생성과 참여 응답에서 한 번만 나가고 서버에는 SHA-256만 남는다.
* **CSRF**: 쓰기 요청은 비회원도 `X-XSRF-TOKEN`이 필요하다 (`GET /api/v1/csrf`).
* **캐시**: 응답 본문이 있는 API는 모두 `Cache-Control: no-store`다.
* **유형 코드**: 응답에 내보내지 않는다. `character`는 `{ "job": "HYPE", "planStyle": "SPONTANEOUS" }` 형식이다.

* **결과 요청과 응답**

```json
// POST /api/v1/character-test/result
{ "answers": "AAABBBAAABBBABC" }

{
  "character": { "job": "HYPE", "planStyle": "SPONTANEOUS" },
  "stats": { "social": 3, "adventure": 3, "warmth": 0, "planning": 0 },
  "highlightQuestions": [1, 4, 7, 10],
  "bestMatch": { "job": "GEAR_GEEK", "planStyle": "PLANNED" }
}
```

* **생성과 참여 요청과 응답** (`201 Created`)

```json
{ "nickname": "설원대장", "sport": "BOARD", "answers": "AAABBBAAABBBABC" }

{ "groupPublicId": "uuid", "groupName": "설원대장의 모임", "participantPublicId": "uuid", "accessToken": "한 번만 나가는 값" }
```

* **지도 응답**: `levels`는 `BEST`, `GOOD`, `NEUTRAL`, `BICKER`, `APART` 순서로 5개가 언제나 들어 있다. 단계는 최종 점수로 정하고, 같은 단계는 `score` 내림차순, 참여 순이다. `habitGaps`는 습관 질문 3개의 차이(0~2)다. `me.answers`는 본인 것만 돌려준다.

```json
{
  "groupPublicId": "uuid", "groupName": "설원대장의 모임", "participantCount": 2, "maxParticipants": 50, "owner": true,
  "me": { "participantPublicId": "uuid", "nickname": "설원대장", "sport": "BOARD", "answers": "AAABBBAAABBBABC", "result": { } },
  "levels": [ { "level": "BEST", "participants": [ { "participantPublicId": "uuid", "nickname": "조용한친구", "sport": "SKI", "character": { "job": "RESORT_OUTSIDER", "planStyle": "PLANNED" }, "score": 83, "habitGaps": [0, 1, 2] } ] } ]
}
```

* **오류**

| 코드 | 상태 | 상황 |
| :--- | :--- | :--- |
| `CHARACTER_001` | 404 | 없는 모임, 토큰 없음이나 틀림, 다른 모임 소속 |
| `CHARACTER_002` | 409 | 모임 50명 초과 |
| `CHARACTER_003` | 409 | 모임 안 닉네임 중복 (대소문자 구분 없음) |
| `CHARACTER_004` | 400 | 금칙어 닉네임 |
| `COMMON_003` | 429 | 생성 1초 1건, 시간당 60건. 참여 1초 1건, 시간당 300건 (IP 단위) |
