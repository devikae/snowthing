# Snowthing 1차 MVP 4일 개발 & 테스트 상세 일정표 (Sprint 1 Schedule)

## 1. 개요 (Overview)

Snowthing 1차 MVP의 회원/인증(Spring Session Redis), 프로필 N:M 중계, 게시판/댓글 CRUD, 비회원 익명 작성, 이미지, 비동기 추천, 글로벌 예외 처리 및 전체 테스트 세부 항목에 대한 4일 집중 개발 및 테스트 명세서입니다.

* **개발 환경 스택**: **Java 21 (LTS)**, **Spring Boot 4.x**, Redis 7.x, MySQL 8.0

* **스프린트 기간**: 2026-08-13 (목) ~ 2026-08-17 (월) (※ 8/12 수요일, 8/15 토요일 제외 / 총 4일)
* **목표**: 1차 MVP 11개 엔티티 및 REST API 구현, 쿼리 최적화 및 단위/통합/E2E 테스트 100% 완수

---

## 2. 4일 개발 & 테스트 세부 통합 일정표

### Day 1: 8월 13일 (목) - 회원가입, 세션 인증 및 프로필 도메인 개발 & 테스트

* **개발 세부 항목**:
  1. `Member` 엔티티 및 `UUID v7` 생성기 (`public_id`) 구현
  2. 회원가입 API (`POST /api/members`): 이메일/닉네임 중복 검증, BCrypt 비밀번호 암호화, OAuth2 준비 `password` NULLABLE 지원
  3. 세션 로그인 API (`POST /api/auth/login`): **Spring Session Redis** `JSESSIONID` 발급, **`changeSessionId()` 세션 고정 공격 방어** 구현
  4. 세션 로그아웃 API (`POST /api/auth/logout`): Redis 세션 키 완전 파기, `Max-Age=0` 쿠키 만료 헤더 반환
  5. 6대 쿠키 보안 속성 적용 (`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/api`, `Domain`, `No PII`)
  6. 프로필 조회/수정 API (`GET/PUT /api/members/me`): 자기소개 `bio`, 주 출발지 `departure_region`
  7. 마스터 엔티티 (`resort`, `riding_style`) 및 N:M 중계 엔티티 (`member_resort`, `member_riding_style`) 구현 (복합키 대신 **단일 대리키 `id` PK + `UNIQUE KEY`** 적용)
  8. 크루 소속 준비: `member.crew_id` FK (NULLABLE), `member.crew_role` (`OWNER`, `MANAGER`, `MEMBER`) 컬럼 추가 (1차 MVP에서는 크루 기능 Out-of-Scope)

* **테스트 세부 항목**:
  1. 회원가입 단위 테스트: 이메일/닉네임 중복 입력 시 `400 Bad Request` (`DUPLICATE_EMAIL`, `DUPLICATE_NICKNAME`) 예외 반환 검증
  2. 세션 인증 테스트: 로그인 성공 시 `JSESSIONID` 쿠키 6대 보안 속성 검증 및 Spring Session Redis 키 생성/`changeSessionId()` 동작 검증
  3. 세션 로그아웃 테스트: 로그아웃 후 Redis 세션 파기 및 쿠키 만료 헤더 검증
  4. 프로필 N:M 중계 테스트: 주 베이스/서브 베이스 스키장 및 라이딩 스타일 중계 테이블 등록/수정 DB 통합 테스트

### Day 2: 8월 14일 (금) - 게시판 CRUD, 비회원 익명 작성 구현 & 테스트

* **개발 세부 항목**:
  1. 카테고리 (`post_category`) 엔티티 및 마스터 코드 (`FREE`, `ANONYMOUS`, `QNA`, `GEAR_VS`, `FOOD`) 구현
  2. 게시글 (`post`) 엔티티 구현 (`public_id` UUID v7, 역정규화 카운트 `comment_count`, `like_count`, `dislike_count`)
  3. **게시글 상태 관리 (`status`)**: `NORMAL`(정상), `HIDDEN`(관리자 숨김), `DELETED`(유저 삭제), `BLOCKED`(차단)
  4. 게시글 목록 조회 API (`GET /api/posts` - 카테고리/상태 필터링, 페이징)
  5. 게시글 상세 조회 API (`GET /api/posts/{publicId}` - 상태별 인가 및 조회수 +1 증가)
  6. 게시글 작성/수정/삭제 API (`POST/PUT/DELETE /api/posts/{publicId}`)
  7. **비회원 & 익명 작성 지원**: `is_anonymous`, `member_id` NULLABLE, `writer_ip` (IPv4/IPv6 45자 NOT NULL), **비회원 비밀번호 (`anonymous_password` BCrypt)** 구현
  8. 익명 렌더링 규칙: `is_anonymous = true` 인 경우 닉네임 무시하고 **`익명 (IP 마스킹)`** 렌더링 처리
  9. Soft Delete: 게시글 삭제 시 DB 삭제가 아닌 `is_deleted = true` 및 `status = 'DELETED'` 처리

* **테스트 세부 항목**:
  1. 게시판 페이징/목록 테스트: Querydsl/JPQL 목록 조회 쿼리 카운트 및 카테고리 필터링 검증
  2. 비회원 익명 작성 테스트: 비회원 작성 시 `member_id = NULL` 저장 및 `anonymous_password` BCrypt 암호화 저장 검증
  3. 비회원 수정/삭제 권한 테스트: 비회원 비밀번호 일치 시 수정/삭제 허용, 불일치 시 `403 Forbidden` (`INVALID_ANON_PASSWORD`) 검증
  4. Soft Delete 테스트: 게시글 삭제 요청 시 DB 레코드 삭제 없이 `is_deleted = true` 변경 쿼리 검증

### Day 3: 8월 16일 (일) - 이미지, 추천 비동기 & 댓글 계층형 구현 & 테스트

* **개발 세부 항목**:
  1. 게시글 이미지 1:N 업로드 (`post_image`): `image_url`, `sort_order` 연동
  2. 게시글 추천/비추천 API (`POST /api/posts/{publicId}/reactions`): **`@Async` 비동기 이벤트** 발행, `post_reaction` `UNIQUE (post_id, member_id)` 제약조건 적용
  3. 댓글 (`comment`) 엔티티 구현: `parent_id` (Self-Referencing NULLABLE), `writer_ip`, `is_anonymous`, `anonymous_password` (BCrypt), `is_deleted`
  4. 댓글 작성 API (`POST /api/posts/{publicId}/comments`) 및 삭제 (Soft Delete ➔ "삭제된 댓글입니다" 표시)
  5. **`Single Query + In-Memory Tree` 댓글 계층형 조립**: `WHERE post_id = :postId` 단 1번의 JPQL DTO 직조회 + 자바 서비스 레이어 `HashMap` $O(1)$ 포인터 참조 계층 파싱
  6. 댓글 페이징: 대량 댓글 메모리 과부하 방지 1차 원댓글 단위 `Page/Slice` 페이징

* **테스트 세부 항목**:
  1. 추천 비동기 테스트: `@Async` 비동기 이벤트 발행 및 유저당 1회 중복 추천 방지 (`409 Conflict` `ALREADY_REACTED`) 검증
  2. **댓글 N+1 파괴 검증**: 댓글/대댓글 조회 시 **DB 쿼리가 무조건 단 1번만 발생하는지 쿼리 카운터 검증**
  3. 댓글 계층 파싱 테스트: 자바 In-Memory 부모-자식 댓글 트리 계층 구조 파싱 단위 테스트
  4. 비회원 댓글 삭제 테스트: 비회원 댓글 비밀번호 일치 여부 검증

### Day 4: 8월 17일 (월) - 전체 E2E 시나리오 QA & 예외 응답 종합 검증

* **개발 및 리팩토링 항목**:
  1. 전역 예외 처리기 (`@RestControllerAdvice`) 구현: 표준 에러 JSON 구조 (`timestamp`, `status`, `code`, `message`, `errors`)
  2. 전체 백엔드 코드 리팩토링 및 1차 MVP 최종 점검

* **종합 테스트 & QA 항목**:
  1. **Postman Runner E2E 전체 시나리오 테스트**:
     - 회원가입 ➔ 로그인 ➔ 프로필 N:M 중계 수정 ➔ 게시글 작성 ➔ 추천 비동기 투표 ➔ 비회원 익명 작성 ➔ 댓글/대댓글 작성 ➔ 비회원 댓글 삭제 ➔ 로그아웃 전체 흐름 검증
  2. **글로벌 에러 응답 5대 HTTP Status Code 종합 검증**:
     - `400 Bad Request` (유효성 검사 실패 / 중복 가입)
     - `401 Unauthorized` (비로그인 요청)
     - `403 Forbidden` (권한 없음 / 비회원 비밀번호 불일치)
     - `404 Not Found` (존재하지 않는 게시글/댓글)
     - `409 Conflict` (추천 중복 투표)
     - `500 Internal Server Error` (서버 예외)
