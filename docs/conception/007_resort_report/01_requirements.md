# 오늘의 설질(Resort Report) 요구사항 명세서

## 1. 배경 및 목적
- 슬로프 현장에 있는 이용자(보더/스키어)들이 당일 각 스키장의 설질 상태를 빠르고 가볍게 한 줄로 제보하고 공유할 수 있는 실시간 현장 소통 채널을 제공한다.
- 일반 게시판(`post`)처럼 긴 본문, 제목, 댓글, 리액션, 첨부 이미지가 필요하지 않으며, 오직 '리조트'와 '100자 이내의 한 줄 내용'만으로 신속하게 작성·조회되는 것을 목표로 한다.
- 메인 홈 화면의 위젯 및 전용 페이지(`/resort-reports`)에서 당일(00:00:00 KST ~ 현재) 등록된 제보를 최신순으로 제공한다.

## 2. 기능 요구사항

### 2.1 설질 제보 등록 (Create)
- **접근 권한**: 로그인 회원(`Member`) 전용 (익명 미지원)
- **입력 항목**:
  - 리조트 ID (`resortId`, 필수)
  - 한 줄 제보 내용 (`content`, 필수, 1자 이상 100자 이하, 공백 제거 후 비어있지 않아야 함)
- **검증 규칙**:
  - 리조트가 존재하고 활성(`isActive = true`) 상태여야 함. 존재하지 않으면 404 (`RESORT_NOT_FOUND`).
  - 본문이 비어있거나 100자를 초과하면 400 (`INVALID_RESORT_REPORT_CONTENT`).
- **저장 데이터**:
  - 제보 ID, 리조트 참조, 회원(작성자) 참조, 내용, 생성일시(`createdAt`)

### 2.2 오늘의 설질 제보 목록 조회 (List)
- **접근 권한**: 모든 사용자 (비로그인 허용, Public)
- **조회 기준**:
  - 당일 기준: 한국 표준시(Asia/Seoul, KST) 기준 오늘 00:00:00부터 현재 시점까지 등록된 제보만 조회
  - 정렬: 최신 등록순 (`createdAt DESC`)
  - 필터: 특정 리조트 ID(`resortId`) 필터링 지원 (옵션)
  - 페이징/제한: 메인 화면 위젯용 최신 N건 조회 또는 당일 전체 목록 조회
- **반환 항목**:
  - `reportId`: 제보 ID
  - `resortId`: 리조트 ID
  - `resortName`: 리조트 한글 이름 (예: "하이원", "휘닉스파크")
  - `resortCode`: 리조트 코드 (예: "HIGH1", "PHOENIX")
  - `authorNickname`: 작성자 닉네임
  - `content`: 제보 내용
  - `createdAt`: 제보 등록 일시 (ISO-8601 문자열)

### 2.3 비기능 요구사항
- **비즈니스 격리**: 일반 게시글(`Post`), 댓글(`Comment`), 피드와의 데이터 간섭을 없애기 위해 전용 테이블(`resort_report`)로 격리한다.
- **성능 최적화**: 당일 일자 범위 및 리조트 필터 조회를 위해 `(created_at, resort_id)` 복합 인덱스를 구성한다.
- **아키텍처 규칙 준수**:
  - DTO 컬렉션 방어적 복사 (Rule 22)
  - ErrorCode 기반 CustomException 사용 (Rule 23)
  - 계층 분리 준수 (Rule 24)
