# 오늘의 설질(Resort Report) 요구사항 명세서

## 1. 목적

- 로그인 회원이 활성 리조트의 당일 설질을 100자 이내로 빠르게 공유한다.
- 일반 게시글과 달리 제목·댓글·반응·이미지 없이 전용 `resort_report` 테이블에서 관리한다.
- 조회와 작성 날짜는 서버의 한국 표준시(`Asia/Seoul`)를 기준으로 한다.

## 2. 등록 규칙

- 로그인 회원만 등록할 수 있으며 비로그인 요청은 `401 AUTH_001`을 반환한다.
- 활성 리조트 ID와 공백 제거 후 1~100자인 내용을 받는다.
- 작성 가능 기간은 매년 11월 1일 00:00부터 다음 해 4월 30일 23:59:59.999999까지다. 5~10월에는 `403 REPORT_004`를 반환한다.
- 회원 한 명이 작성할 수 있는 제보는 KST 날짜별 최대 5개다. 삭제·숨김·차단된 제보도 도배 우회를 막기 위해 당일 한도에 포함한다.
- 별도 메모리 제한기나 카운터 테이블을 사용하지 않는다. 회원 행을 비관적 잠금한 뒤 `member_id + created_at`으로 기존 제보를 집계해 동시 요청을 직렬화한다.

## 3. 조회 규칙

- 로그인 여부와 관계없이 KST 오늘 `[00:00, 다음 날 00:00)`에 작성된 `NORMAL` 상태만 조회한다.
- `resortId` 필터와 1부터 시작하는 페이지를 지원하며 페이지 크기와 최대 페이지는 각각 100이다.
- 정렬은 `createdAt DESC, reportId DESC`로 고정해 같은 시각에도 순서가 안정적이어야 한다.
- 생성 시각은 시간대가 포함된 ISO-8601(`+09:00`)로 반환한다.
- 응답의 `canDelete`는 현재 사용자가 작성자 또는 관리자인지 서버가 계산한다.
- 리조트 선택지는 하드코딩하지 않고 활성 리조트 마스터 API를 사용한다. 마스터 조회 실패 시 작성 UI를 비활성화한다.

## 4. 삭제·운영 규칙

- 작성자와 관리자는 제보를 삭제할 수 있으며 즉시 `DELETED` 상태와 `deleted_at`을 기록하는 소프트 삭제를 수행한다.
- 관리자는 `NORMAL`, `HIDDEN`, `BLOCKED` 상태로 운영 조치할 수 있다. 삭제된 제보는 운영 상태 변경으로 복구하지 않는다.
- 매월 1일 04:40 KST에 현재 월 이전의 모든 제보를 물리 삭제한다. 따라서 DB에는 현재 월 데이터만 유지되며, 소프트 삭제 데이터도 다음 월 정리 시 제거된다.
- 월별 물리 삭제는 복구 기간이 최대 한 달뿐이라는 대가가 있다. 장기 감사 보존이 필요해지면 별도 보관소나 보존 기간 정책을 도입해야 한다.

## 5. 비기능 요구사항

- 공개 목록은 상태·시간, 리조트별 목록은 리조트·상태·시간, 일일 한도는 회원·시간 복합 인덱스를 사용한다.
- 컬렉션 응답은 방어적 복사를 수행한다.
- 예외는 `ErrorCode`와 `CustomException`으로만 표현한다.
- 컨트롤러는 Repository를 직접 호출하지 않고 웹 인증 처리와 비즈니스 로직을 분리한다.
