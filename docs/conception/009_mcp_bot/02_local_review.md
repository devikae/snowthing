# 챗봇·MCP 로컬 점검과 보완

## 범위와 구현

기존 봇은 라이브톡의 `@bot 질문`을 비동기 큐에서 MCP gateway로 전달한다. 별도 LLM 연동을 새로 만들지 않고 기존 읽기 전용 위임 경계를 점검한다. 이번 작업에서 유료 API를 실행하거나 운영 설정을 변경하지 않는다.

- 개인 프로필·관리자·쓰기·동호회 경로는 기존 위임 GET 허용 목록에 없다. 동호회 UUID를 알아도 내부 글을 봇에 위임할 수 없다.
- 카풀은 기존 BotDelegatedUserDetails 예외로 연락처/정밀 출발 위치의 작성자 관리 접근을 제한한다.
- 중고장터는 로그인 회원용 연락처가 기존 상세 DTO에 그대로 포함되어 있었다. 위임 principal에서는 contact=null, canEdit/canDelete=false로 반환한다. 실제 작성자의 일반 웹 조회에는 영향이 없다. 자유 본문에 사용자가 직접 적은 개인정보까지 구조적으로 보장할 수는 없으므로 전체 답변 필터와 입력 안내를 병행한다.
- 봇 답변은 공개 히스토리에 넣기 전에 전체 원문에 기존 URL/메신저 검사와 국내 전화번호 패턴 검사를 적용한다. 절단 경계를 걸친 연락처가 앞부분만 공개되는 것도 막는다. 이 패턴은 완전한 개인정보 탐지기가 아니며 우회 표기·해외 번호·이름/주소 등까지 완전 차단한다고 주장하지 않는다.
- 회원별 분당 1회에 더해 프로세스 전체 최초 요청 기준 1시간 60회, 24시간 200회 시도 한도를 둔다. 실패/큐 거절도 한도를 소비해 비용 폭주를 억제한다. 두 캐시가 독립적으로 만료하는 고정 창이며 달력상의 정시·자정 초기화가 아니다. 재시작하면 초기화되고 다중 인스턴스 간 공유되지 않으므로 운영 확장 시 영속 예산/Redis와 제공사 비용 제한이 필요하다.
- 기존 실행기 최대 2개·대기열 20개, gateway 읽기 timeout 15초를 유지한다. 대기열 거절/모델 오류는 공개 답변을 만들지 않는다.

## 로컬 도움말

라이브톡을 접지 않고 상단 도움말 버튼으로 시즌권·데크 도구를 안내한다. `/도움말`(`/help`), `/시즌권`, `/데크`는 정확히 일치할 때만 브라우저에서 처리하며 채팅 메시지·MCP·LLM에 보내지 않는다. 일반 대화는 기존 전송 흐름을 유지한다. 비회원도 버튼으로 도구를 열 수 있다. 계산 입력을 공개 채팅에 요청하지 않는다. 안내에 일반 대화와 봇 질문이 공개된다는 점을 표시한다. 동호회 기능은 이번 PR에서 제외하므로 메뉴·도움말 연결도 포함하지 않는다.

## 검증

전화번호·절단 경계의 URL/전화번호가 공개 히스토리에 들어가지 않는 서비스 테스트, 위임 연락처 제거와 일반 작성자 권한 보존 API 테스트, 회원별/계정 간 호출 제한 테스트를 추가한다. `scripts/chat-help-browser-check.cjs`는 실제 로그인·도움말·로컬 명령과 WebSocket SEND 부재·모바일/다크 화면을 확인한다. 실제 모델의 응답 품질이나 외부 MCP 서버의 모든 구현까지 이 저장소 테스트로 검증했다고 간주하지 않는다.
