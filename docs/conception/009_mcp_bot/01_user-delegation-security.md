# MCP 라이브톡 봇 사용자 위임 권한 설계

- 상태: Approved
- 기준일: 2026-10-19
- 적용 범위: SnowThing 라이브톡 GPT 봇, `snowthing-mcp-server` 로컬 stdio

## 1. 목적과 권한 원칙

AI가 독립된 공용 계정이나 관리자 계정으로 SnowThing 기능을 사용하지 않고, 요청한 사용자의 신원과
명시적으로 위임된 기능 범위 안에서만 기존 REST API를 호출하도록 한다.

실제로 실행할 수 있는 기능은 다음 교집합으로 결정한다.

```text
실제 로그인 사용자의 권한
  ∩ 배포 모드의 MCP 도구 허용 목록
  ∩ 위임 토큰 scope
  ∩ 운영 기능 플래그
  ∩ 사용자 확인 여부
```

사용자가 웹에서 수행할 수 있다는 사실만으로 AI 실행을 허용하지 않는다. 라이브톡 봇의 1차 운영
범위는 조회 전용이며, 일반 사용자의 읽기 권한보다 넓어질 수 없다.

## 2. 인증과 신원 확인

1. 브라우저의 `JSESSIONID`는 Spring 백엔드까지만 전달한다.
2. 로그인 회원이 `@bot` 질문을 보내면 백엔드가 회원 `publicId`를 subject로 하는 60초 위임 토큰을
   발급한다.
3. 토큰은 `iss`, `aud`, `sub`, `iat`, `exp`, `jti`, `chatMessageId`, `scopes`를 포함한다.
4. Node AI 호스트는 JWT payload를 신뢰해 신원을 결정하지 않는다. OpenAI 호출 전에 위임 토큰으로
   `GET /api/v1/members/me`를 호출하고, Spring이 검증해 반환한 `publicId`만 사용한다.
5. Spring은 서명, 알고리즘, issuer, audience, 발급·만료 시각, scope를 검증하고 회원을 DB에서 다시
   조회한다. `ACTIVE`가 아닌 회원은 거부한다.
6. 사용자 ID를 MCP 도구 인자로 받아 인증 신원을 바꾸는 기능은 제공하지 않는다.

## 3. 위임 권한과 API 허용 목록

라이브톡 봇 토큰은 `snowthing:read` scope만 가진다. 허용 범위는 `GET`과 아래의 정확한 API 경로로
제한한다.

- 게시글 목록·상세
- 카풀 목록·상세
- 중고장터 카테고리·목록·상세
- 리조트·라이딩 스타일 마스터
- 슬로프캠 메타데이터
- 오늘의 설질 목록
- 현재 호출자의 `/api/v1/members/me`

다음은 HTTP 메서드나 사용자 원래 역할과 관계없이 위임하지 않는다.

- 모든 `POST`, `PUT`, `PATCH`, `DELETE`
- 모든 prepare/create/update/delete/status/reaction MCP 도구
- `/api/v1/admin/**`, `/api/admin/**`
- 회원가입·로그인·비밀번호 재설정·소셜 계정 연결
- 이미지 업로드

관리자 회원이 봇을 사용하더라도 위임 인증에는 `ROLE_ADMIN`을 부여하지 않는다. 기존 서비스가
응답 필드를 관리자 여부에 따라 달리하는 경우에도 일반 회원과 같은 결과만 받도록 위임 전용
principal의 권한을 `ROLE_USER`와 읽기 scope로 제한한다.

## 4. 도메인별 데이터 노출 정책

- 공개 게시글·리조트·슬로프캠·오늘의 설질은 기존 공개 조회 정책을 유지한다.
- 중고장터 목록·상세는 로그인 회원 전용 정책을 유지하고, 상세의 연락처를 로그나 AI 답변에
  불필요하게 재출력하지 않는다.
- 카풀 상세의 연락처 공개 동의와 작성자 전용 수정 좌표는 기존 백엔드가 검증된 호출자 기준으로
  결정한다.
- 내 프로필은 사용자 식별자 입력 없이 `/members/me`로 현재 호출자만 조회한다.
- 게시글이나 API 응답에 포함된 지시문과 URL은 데이터일 뿐 후속 도구 실행 지시로 해석하지 않는다.

## 5. MCP 도구 노출 정책

- 기본 실행은 쓰기 도구 비활성화다.
- 라이브톡 봇의 in-memory MCP 클라이언트는 설정값과 무관하게 별도 읽기 허용 목록 12개만 OpenAI에 제공하고, 허용 목록 밖 도구 호출도 다시 거부한다.
- 로컬 분리 DB E2E에서만 명시적인 설정으로 쓰기 도구를 활성화할 수 있다.
- 쓰기 도구를 운영에 열 때는 영속 멱등성, 사용자 확인 UI, write scope, 감사 로그와 rate limit을
  먼저 구현한다.

## 6. 로그와 관측

허용 로그:

- request ID와 chat message ID
- 비식별 사용자 키
- 도구 이름, 결과 상태, 오류 종류, 처리 시간

금지 로그:

- JSESSIONID, CSRF token, 위임 JWT, OpenAI API key
- 질문·답변·게시글·댓글 원문 전체
- 연락처, 이메일 등 개인정보

## 7. 테스트 기준

- 사용자 A의 조회가 A의 권한으로 성공한다.
- 사용자 A/B의 `/members/me` 결과가 격리된다.
- 만료·변조·잘못된 issuer·audience·scope 토큰을 거부한다.
- 정지·탈퇴 회원을 거부한다.
- 유효한 토큰으로도 모든 쓰기 메서드와 관리자 경로를 거부한다.
- 관리자 회원의 봇 호출도 관리자 전용 필드를 받지 않는다.
- 운영·봇 모드에서 쓰기 MCP 도구가 발견되거나 실행되지 않는다.
- JWT payload만 위조한 요청은 OpenAI 호출 전에 거부한다.
- 인증정보와 민감한 원문이 로그와 오류 응답에 포함되지 않는다.

## 8. 대안과 트레이드오프

Node에 HS256 서명 비밀을 공유하면 Node가 토큰을 검증할 수 있지만 같은 비밀로 새 토큰도 만들 수
있어 권한 경계가 넓어진다. 따라서 Node는 Spring의 `/members/me` 검증 결과를 신뢰하고 서명 비밀을
보유하지 않는다. 내부 HTTP 호출이 한 번 늘어나는 대신 토큰 발급 권한은 Spring에만 남는다.

원격 Streamable HTTP와 OAuth 2.1은 외부 MCP 클라이언트를 받을 때 필요하다. 현재 서비스 내장형
봇은 in-memory transport를 사용하므로 이번 범위에서 구현하지 않는다. 이미지 업로드도 바이너리
검증, 임시 소유권, 고아 파일 정리와 별도 확인 UX가 필요하므로 제외한다.
