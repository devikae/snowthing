# 받은 쪽지 차단과 신고 (IKA-123)

## 배경

- 받은 쪽지 상세에는 목록, 삭제, 답장 버튼만 있다. 불쾌한 쪽지를 받아도 그 자리에서 보낸 회원을 막거나 알릴 수 없다.
- 차단은 쪽지 설계([022](../022_direct_message/01_design.md))에서 이미 만들었다. `member_block`, 차단 API, 설정 화면 차단 목록, 작성자 닉네임 메뉴의 차단이 있다. 쪽지 상세에만 버튼이 없다.
- 쪽지 신고는 022와 게시물 신고 설계([025](../025_content_report/01_design.md))에서 "신고 도메인과 함께 설계한다"며 미뤄 두었다.

## 요구사항

- 받은 쪽지 상세에서 보낸 회원을 차단하고 해제한다.
- 받은 쪽지 상세에서 쪽지를 신고한다. 신고 창에 "이 회원 차단하기"를 기본으로 켜 두고, 신고가 접수되면 차단까지 한다.
- 관리자는 신고 목록에서 신고된 쪽지 본문, 보낸 회원, 보낸 시각을 보고 처리 완료로 닫는다. 정지가 필요하면 회원 상세에서 직접 한다.

## 범위

| 넣는 것 | 빼는 것 |
|---|---|
| 받은 쪽지 상세의 차단, 차단 해제, 신고 | 보낸 쪽지 신고 |
| 관리자 신고 목록의 쪽지 표시와 처리 완료 | 쪽지를 가리거나 지우는 임시조치 |
| | 신고 결과 알림 |
| | 회원 프로필 신고, 라이브톡 신고 |

## 구현 방식

`content_report`에 대상 종류 `MESSAGE`를 더한다.

검토한 대안은 다음과 같다.

- 쪽지 전용 신고 테이블과 관리자 화면: 기존 신고 코드를 건드리지 않지만 목록, 중복 방지, 사유가 두 벌이 된다.
- 기존 조치(임시조치, 복구, 삭제)를 쪽지에도 적용: 쪽지는 1:1이라 가릴 공개 대상이 없다. 받은 회원이 이미 본 쪽지를 지워도 피해는 줄지 않는다. 관리자가 실제로 할 일은 보낸 회원 제재이고 회원 정지는 이미 있다.

관리자 처리는 "접수 기록만" 방식이다. 신고를 받아 두고 관리자가 확인한 뒤 처리 완료로 닫는다. 신고자와 보낸 회원에게 알림을 보내지 않는다.

## 데이터

- 테이블 구조는 그대로다. `target_type`이 `VARCHAR(20)`이라 새 값을 그대로 담는다.
- `target_id`는 `direct_message_id`다. 다른 대상처럼 FK를 두지 않는다.
- 마이그레이션 `database/production/070_migration_message_report.sql`은 두 컬럼의 COMMENT만 고친다. 타입이 같아 MySQL 8은 메타데이터만 바꾼다.
- 같은 회원이 같은 쪽지를 두 번 신고하지 못하는 것은 기존 UNIQUE `(target_type, target_id, reporter_id)`가 막는다.

## API

새 API는 없다. 기존 API에 대상 종류만 더한다.

| 메서드 | 경로 | 변경 |
|---|---|---|
| POST | `/api/v1/reports` | `targetType: "MESSAGE"`, `targetId`는 쪽지 ID |
| GET | `/api/v1/admin/reports` | 쪽지 신고 행에 `senderPublicId`, `senderNickname`, `messageSentAt`을 채운다. 본문은 `targetPreview`, `targetContent`에 담는다 |
| POST | `/api/v1/admin/reports/{reportId}/actions` | 쪽지 신고는 `DISMISS`만 받는다 |

## 규칙

| 상황 | 처리 |
|---|---|
| 받은 회원이 신고 | 204 |
| 비회원 | 401 `AUTH_020`. 쪽지는 비공개라 비회원이 볼 수 없다 |
| 보낸 회원, 제3자, 없는 번호, 숫자가 아닌 번호 | 404 `CONTENT_REPORT_001` (쪽지 상세처럼 존재 여부를 숨긴다) |
| 받은 회원이 내 쪽에서 지운 쪽지 | 404 |
| 대기 중인 신고가 있는데 다시 신고 | 409 `CONTENT_REPORT_002` |
| 쪽지 신고에 임시조치, 복구, 삭제 | 409 `CONTENT_REPORT_004` (기존 "상태에 맞지 않는 조치"와 같은 코드) |
| 쪽지 신고 처리 완료 | 같은 쪽지의 대기 신고를 모두 닫는다. 조치 이력과 관리자 기록은 남기고 알림은 보내지 않는다 |

- 관리자는 신고된 쪽지 본문만 본다. 022의 "쪽지 본문은 관리자 화면에 노출하지 않는다. 신고된 쪽지만 열람한다"를 따른다.
- 받은 회원이 신고 뒤 쪽지를 지워도 행은 남아 있어 관리자는 본문을 계속 본다.
- 보낸 회원이 탈퇴하면 관리자 목록에 "탈퇴한 회원"으로 나오고 회원 상세 링크는 없다.
- AI 회원이 보낸 쪽지도 같은 규칙이다. AI 회원임이 드러나는 동작은 없다.
- 오류 문구 "신고할 게시물을 찾을 수 없습니다", "이미 신고한 게시물입니다"는 쪽지에도 쓰이므로 "신고할 대상을 찾을 수 없습니다", "이미 신고했습니다"로 바꾼다. 코드는 그대로다.

## 프론트

- 받은 쪽지 상세: 보낸 회원이 탈퇴하지 않았으면 "차단"(또는 "차단 해제")과 "신고" 버튼을 둔다.
  - 차단 상태는 기존 차단 목록 API로 확인한다. 쪽지 상세 응답은 바꾸지 않는다.
  - 차단하면 답장 버튼을 숨긴다. 서버도 차단한 회원에게 보내는 쪽지를 거부한다.
- 신고 창은 기존 `ReportButton`을 쓴다. 쪽지일 때 "이 회원 차단하기" 체크(기본 켜짐)를 보이고, 신고 접수 뒤 차단 API를 부른다. 차단만 실패하면 신고는 되돌리지 않고 차단 실패를 따로 안내한다. 이미 차단한 회원이면 체크를 보이지 않는다.
- 관리자 신고 목록: 대상에 "[쪽지]", 보낸 회원(회원 상세 링크), 보낸 시각을 보인다. 쪽지 행에는 "처리 완료" 버튼만 둔다.

## 영향 범위

- 관리자 목록 응답은 필드를 더하기만 해서 기존 화면과 호환된다.
- 임시조치 만료 작업은 임시조치 행만 읽는다. 쪽지 신고에는 임시조치가 생기지 않아 영향이 없다.
- 신고 접수 제한(`ContentWriteRateLimiter.Action.CONTENT_REPORT`)은 쪽지 신고에도 그대로 적용된다.
