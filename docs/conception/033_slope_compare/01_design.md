# 슬로프 비교와 코스 맵

## 배경

- 일본으로 원정 가는 라이더는 처음 가는 리조트의 코스가 어느 정도인지 감을 잡기 어렵다. 공식 사이트는 리조트마다 난이도 기준과 표기가 달라서 "초급"이라는 말만으로는 비교가 안 된다.
- 비슷한 서비스로 올스롭스(allslopes.net)가 있다. 2026-11-19에 공개 방문 통계 API로 확인한 결과 누적 방문은 10,400회이고, 최근 한 달은 하루 평균 5회 수준이다. 슬로프 경사 값 대부분이 비어 있고, 리조트 40곳의 슬로프맵 주소는 모두 404를 반환해 맵 기능이 사실상 동작하지 않는다. 리조트와 슬로프 페이지가 sitemap에 없어 검색에도 거의 잡히지 않는다.
- 눈팅에는 슬로프 제원 데이터가 없다. IKA-66 운영 현황판(`030_slope_status`, `resort_slope_status`)은 공식 사이트에서 슬로프별 운영 여부만 하루 8번 수집하고, 슬로프 목록을 JSON 한 칸에 담는다. 길이와 경사는 없다.

## 목표

- 국내와 일본 슬로프를 공식 수치로 비교한다. 수치가 없으면 추정하지 않고 비워 둔다.
- 일본 슬로프를 고르면 경사가 비슷한 국내 슬로프를, 국내 슬로프를 고르면 비슷한 일본 슬로프를 보여 준다.
- 슬로프마다 해당 코스만 잘라낸 간략 맵을 보여 주고, 붙어 있는 주변 코스와 타는 리프트를 함께 알려 준다.

## 결정 사항

| 항목 | 결정 | 고려한 다른 선택지 |
|---|---|---|
| 핵심 가치 | 리조트 간 수치 비교, 비슷한 슬로프 찾기 | 실력별 추천은 사용자 결정으로 제외 |
| 수치 출처 | 리조트 공식 자료를 직접 정리 | OSM과 고도 데이터로 계산(30m 격자라 짧은 국내 슬로프의 경사 오차가 큼), 둘을 섞는 방식 |
| 맵 방식 | OSM 슬로프 선과 리프트 선으로 그린 배경 없는 SVG | 손으로 그린 도식 맵(21곳 작업량, 공식 맵 저작권), 지도 타일 위에 겹치기(복잡하고 타일 이용 정책 문제) |
| 일본 리조트 저장 | `resort`에 `country` 컬럼 추가 | 별도 테이블 분리 |
| 화면 경로 | 운영 현황판 `/slopes` 아래로 합친다 | `/tools/slopes`에 따로 두기(슬로프 주제가 두 곳으로 나뉨) |
| 주변 코스 관계 | 자동 계산 결과를 초안으로 두고 검수 후 저장 | 화면에서 매번 자동 계산(판정이 양쪽에서 어긋나는 경우가 있음) |

OSM은 맵의 모양에만 쓰고, 길이와 경사는 공식 수치를 쓴다. 선의 위치와 모양은 정확도가 충분하지만 경사 계산은 오차가 크기 때문이다.

## 대상 리조트

- 국내: 운영 중인 리조트 약 11곳 (기존 `resort` 데이터 기준)
- 일본 10곳. 한국인 방문객 기준의 공개 통계가 없어 직항 접근성, 한국어 여행 가이드와 패키지 노출, 일본 내 인기를 기준으로 골랐다.
  - 홋카이도: 니세코 그랑히라후, 루스츠, 키로로, 토마무, 후라노, 삿포로 테이네
  - 혼슈: 갈라유자와, 나에바, 하쿠바 핫포오네, 노자와온센
- 시가고원은 18개 구역이 이어진 규모라 2차로 미룬다. 수집 중 공식 수치가 지나치게 부족한 리조트는 같은 지역의 다른 리조트로 바꾸고 작업 기록에 남긴다.

## 데이터

### `resort` 변경

- `country` 컬럼 추가 (`KR`, `JP`). 기존 행은 `KR`.
- 일본 리조트도 기존 `code` 규칙대로 코드를 붙인다(예: `NISEKO_HIRAFU`). 화면 주소에 이 코드를 쓴다.
- 프로필의 주 리조트 선택, 카풀 목적지처럼 기존에 리조트 목록을 쓰는 API는 `KR`만 반환한다. 일본 리조트가 카풀 목적지에 나타나면 안 되기 때문이다.

### `slope` 신규

| 컬럼 | 설명 |
|---|---|
| `resort_id` | 리조트 FK |
| `name` | 리조트 공식 표기 이름 |
| `official_difficulty` | 리조트가 표기한 난이도 그대로 |
| `length_m` | 공식 길이 |
| `avg_gradient`, `max_gradient` | 공식 평균, 최대 경사(도). 미공개면 NULL |
| `width_m` | 공식 폭. 미공개면 NULL |
| `lift_id` 또는 리프트 이름 | 이 슬로프로 올라가는 리프트 |
| `osm_way_id` | 맵의 선과 연결하는 키. 선이 없으면 NULL |
| `source_url`, `checked_at` | 수치 출처와 확인 날짜 |

- 목록 정렬에는 `slope_id`를 보조 정렬 기준으로 붙인다.
- 국내 수치 출처: 리조트 공식 슬로프 안내 페이지. 휘닉스는 운영 현황 API(`030_slope_status` 출처 조사)가 시즌 밖에 제원을 내주므로 함께 확인한다.
- 운영 현황판 `slopes_json`의 슬로프 이름과 `slope.name`을 맞춰 두면 현황판에서 코스 카드로 연결할 수 있다. 이름이 다르면 별칭을 두지 않고 연결하지 않는다(범위를 늘리지 않기 위해).
- 리조트 안에서 이름은 유일하다.

### `slope_connection` 신규

- 슬로프 두 개의 관계: `MERGE`(합류), `BRANCH`(갈라짐), `CONTINUE`(도착 후 이어짐), `STARTS_FROM`(갈라져 시작), `SHARE_START`(출발점 공유), `SHARE_END`(도착점 공유), `CROSS`(교차), `PARALLEL`(나란히, 거리 m 포함)
- 한 쌍의 두 줄은 서로 맞물린다. A에서 `MERGE`면 B에서 `CONTINUE`, A에서 `BRANCH`면 B에서 `STARTS_FROM`이다. 프로토타입에서 양쪽 판정이 어긋나던 문제를 이렇게 막는다.
- 프로토타입의 자동 판정 규칙: 두 선의 최소 거리가 25m 이내면 붙어 있는 것으로 보고, 어느 끝이 닿는지로 종류를 나눈다. 90m 이내면 나란히로 본다.
- 자동 판정은 양쪽에서 어긋날 수 있다(예: 한쪽에서는 갈라짐, 반대쪽에서는 출발점 공유). 그래서 생성 스크립트 결과를 검수해 확정한 값만 저장한다.

### 맵 모양 데이터

- 리조트별 OSM 슬로프 선과 리프트 선을 스크립트로 한 번 받아 `frontend/public/slope-maps/{resort-code}.json`에 저장한다. 요청마다 OSM을 호출하지 않는다.
- GeoJSON 대신 미터 평면 좌표로 바꿔 저장한다. 정상이 위, 베이스가 아래로 오도록 미리 회전해 두어 화면은 투영 계산 없이 바로 그린다.
- 면(area)으로 그린 OSM 슬로프는 두꺼운 띠처럼 보여 뺀다.
- 니세코처럼 산 하나를 여러 리조트가 나눠 쓰면 같은 이름의 코스가 이웃 리조트에도 있다. 연결된 선들의 중심에서 먼 같은 이름 선은 버리고, 남은 선 둘레만 맵에 그린다.
- ODbL 데이터이므로 화면에 `© OpenStreetMap contributors`를 표기하고, 우리가 가공한 GeoJSON도 ODbL로 둔다.
- 2026-11-19 확인: 하이원은 OSM에 슬로프 19개(17개 이름 있음)와 리프트 9개가 있다. 나머지 리조트의 채움 정도는 수집 단계에서 확인한다. 선이 없는 리조트는 코스 맵 없이 수치만 보여 준다.

### 데이터 생성

- `scripts/slope-data/build_slope_data.py`가 `specs/`(공식 제원)와 `osm/`(Overpass 응답)로 맵 파일과 `055_migration_slope_data.sql`을 만든다. 055는 손으로 고치지 않는다.
- 공식 이름과 OSM 이름은 띄어쓰기, 로마 숫자, 괄호 설명, "코스" 같은 말을 지우고 맞춘다. 글자만 다른 경우는 스크립트의 별칭 표에 둔다(챔피온과 챔피언 등).
- 난이도 묶음: 초급은 BEGINNER, 초중급과 중급은 INTERMEDIATE, 중상급과 상급과 파크는 ADVANCED, 최상급은 EXPERT. 일본은 初級, 初中級과 中級, 上級, 最上級 순서로 같다. 색 표시에만 쓴다.
- 일본 리조트는 054에서 비활성으로 넣고 계속 비활성으로 둔다. 배포는 마이그레이션을 모두 적용한 뒤 앱을 바꾸므로, country를 모르는 이전 앱이 도는 동안에도 일본 리조트가 커뮤니티 목록에 섞이지 않는다. 슬로프 제원 화면은 "국내는 활성 리조트, 해외는 항상"(`Resort.isSlopeSpecVisible()`)으로 보여 준다.

### 코스 맵 선 채우기 (2026-11-20 사용자 결정)

- 처음 설계에서는 공식 슬로프맵을 따라 그리지 않기로 했지만, 사용자 결정으로 바꿨다. 국내 리조트는 OSM에 선이 없는 슬로프를 공식 슬로프맵을 보고 그린다.
- 순서: OSM 선 이름 맞추기 → 면으로 그린 OSM 슬로프의 가운데 선 → 공식 맵을 보고 OSM 선과 직접 짝짓기(`scripts/slope-data/manual/{CODE}.json`) → 그래도 없으면 공식 맵을 보고 그린다.
- 그리는 방법: 공식 맵과 OSM 양쪽에 있는 지점(리프트 끝 등)을 기준점으로 맞춘 1차 변환으로 맵 픽셀 좌표를 위도, 경도로 바꾼다(`_anchors`, `drawPx`). 맵 왜곡이 심한 곳(오투)은 OSM 선과 리프트 기준으로 위치를 옮겨 위도, 경도로 직접 적는다(`draw`).
- 그린 선이 있는 리조트는 맵 출처에 "일부 코스는 리조트 공식 슬로프맵을 보고 눈팅이 그림"을 덧붙인다. 공식 맵 이미지는 저장소에 넣지 않는다.
- 도구: `render_osm.py`(OSM 선 ID 그림), `grid_overlay.py`(공식 맵 좌표 격자), `verify_map.py`(결과 확인 그림).
- 결과: 국내 145개 슬로프 모두 코스 맵 있음. 일본 250개 중 227개(갈라유자와 15, 노자와 6, 후라노 1, 핫포오네 1이 남음).

## 비슷한 슬로프 찾기

- 같은 지표끼리만 비교한다. 평균 경사는 코스 전체의 기울기, 최대 경사는 가장 가파른 짧은 구간의 기울기라서 서로 섞으면 틀린 매칭이 된다.
  1. 두 슬로프 모두 평균 경사가 있으면 평균으로 비교한다.
  2. 아니면 둘 다 있는 최대 경사로 비교한다.
  3. 공통 지표가 없으면 후보에서 뺀다.
- 경사 차이를 주 기준으로 정렬하고, 차이가 비슷하면 길이가 가까운 쪽을 위로 둔다.
- 후보는 3~5개를 보여 주고, 근거 수치를 함께 표시한다. 예: `최대 32° vs 31° (차이 1°), 1,200m vs 1,050m`
- 양방향(일본에서 국내, 국내에서 일본)을 같은 계산으로 지원한다.
- 일본은 평균 경사가 빠진 경우가 많아 최대 경사 비교가 주가 된다. 국내 데이터의 최대 경사 채움률이 이 기능의 품질을 정하므로 수집 첫 단계에서 확인한다.

## 화면

운영 현황판 `/slopes` 아래로 합친다.

| 경로 | 화면 |
|---|---|
| `/slopes` | 기존 운영 현황판. 국내와 일본 리조트 제원 페이지로 가는 진입점을 더한다 |
| `/slopes/{resortCode}` | 리조트 페이지 |
| `/slopes/{resortCode}/{slopeId}` | 슬로프 상세 |

`{resortCode}`는 화면 주소용으로 소문자와 하이픈을 쓴다(`NISEKO_HIRAFU` → `niseko-hirafu`). 슬로프캠 주소와 같은 규칙이다.
| `/slopes/compare` | 리조트 비교 |

1. `/slopes`: 위쪽에 국내와 일본 제원 페이지 진입점을 두고, 제원이 있는 리조트 카드에 "슬로프 제원과 코스 맵 보기"를 붙인다. 운영 현황의 슬로프 이름에서 코스 카드로 바로 가는 연결은 이름 표기가 달라(예: 하이원 현황 "제우스 1"과 제원 "제우스 Ⅰ") 2차로 미룬다.
2. 리조트 페이지: 전체 간략 맵과 슬로프 코스 카드 목록. 정렬과 필터를 제공한다. sitemap에 올린다.
3. 슬로프 상세
   - 해당 코스만 잘라낸 맵. 본 코스는 흰 테두리와 난이도 색으로 진하게 그린다.
   - 붙어 있는 주변 코스는 자기 난이도 색과 이름 태그로, 관계없는 코스는 연한 회색으로 그린다.
   - 출발과 도착은 본 코스 색의 태그, 합류와 교차 지점은 점으로 표시한다.
   - 타는 리프트는 진한 점선과 이름 태그로 구분한다.
   - 공식 길이, 평균과 최대 경사, 공식 난이도, 출처와 확인 날짜, 주변 슬로프 목록
   - 그 아래에 비슷한 슬로프 후보를 같은 모양의 코스 카드로 나란히 둔다.
4. 리조트 비교: 2~3곳을 나란히 놓고 슬로프 수, 최장 길이, 최대 경사, 공식 난이도 분포를 비교한다.

코스 카드는 슬로프마다 축척이 다르므로 길이를 항상 함께 표시한다.

진입점과 머리 디자인 (2026-11-20 사용자 확인 후 추가)

- 슬로프캠 리조트 머리의 "슬로프 현황" 옆에 같은 모양의 "슬로프 정보" 버튼을 둔다. 제원 페이지가 있는 리조트에만 보인다.
- 리조트 페이지와 슬로프 상세의 머리는 슬로프캠 리조트 머리와 같은 카드 모양을 쓴다(지역 칩, 이름, 개장 D-DAY, 기온, 버튼). 버튼은 슬로프 현황, 슬로프캠(카메라가 있는 리조트만), 비교. 일본 리조트는 D-DAY와 기온, 슬로프 현황 없이 "일본" 칩을 단다.

프로토타입: `prototype/`의 생성 스크립트와 템플릿. 하이원 OSM 데이터로 전체 맵과 코스 카드를 만든다.

## 영향

- 운영 현황판: `/slopes` 화면과 수집기는 그대로다. 일본 리조트는 수집 대상이 아니므로 현황판 목록에 나오지 않게 한다.
- 기존 리조트 목록 API: `country` 조건이 추가된다. 조건이 빠지면 일본 리조트가 프로필과 카풀에 노출되므로 테스트로 막는다.
- 리조트 마스터 데이터: 운영 DB에 리조트 행이 추가된다. 리조트 ID를 하드코딩한 곳이 있는지 계획 단계에서 확인한다.
- 검색 노출: 리조트와 슬로프 페이지가 sitemap에 추가된다.
- 데이터 유지: 리조트가 코스를 바꾸면 직접 갱신해야 한다. `checked_at`을 화면에 표시해 최신 여부를 알린다.
- 라이선스: OSM 출처 표기 누락은 ODbL 위반이므로 맵이 나오는 모든 화면에 표기한다. 리조트 공식 슬로프맵 이미지는 쓰지도, 따라 그리지도 않는다.
- 성능: 맵 데이터는 정적 파일이라 DB 부하가 없다. 슬로프 수가 수백 개 수준이라 비슷한 슬로프 계산은 서버에서 전수 비교해도 충분하다.
