# Snowthing 실시간 라이브톡 제품 및 운영 정책서

- **문서 번호**: `POLICY-WS-LIVECHAT`
- **상태**: `Accepted`
- **최종 수정일**: 2026-09-20
- **기반 문서**: `docs/conception/live_chat/ADR-101 라이브챗 기술결정.md`, `docs/project/design/live_chat/code.html`

본 문서는 Snowthing 메인 화면에 제공되는 실시간 라이브톡(`⚡ 라이브톡`)의 채널 구조, 이용 권한, 작성 제한, UI 렌더링, 컴플라이언스 및 법적 로그 보관 정책을 정의한 공식 명세서이다.

---

## 1. 채널 구조 및 범위

1. **메인 광장 단일 채널 운용**:
   - 스키장별 분할이나 개별 방 생성 없이, 메인 화면에 **단 하나의 전체 실시간 라이브톡 채널**을 운용한다.
   - 모든 사용자는 동일한 채널(`/sub/chat/main`)을 바라보며 소통한다.
2. **입장/퇴장 알림 배제 (Silent Join/Leave)**:
   - "OOO님이 입장/퇴장하셨습니다"와 같은 시스템 알림은 브로드캐스팅하지 않는다. 대화 흐름을 방해하지 않는 정숙 입퇴장 정책을 적용한다.
3. **접속자 수 집계 유보 (YAGNI 원칙)**:
   - 실시간 세션 수 집계 및 주기적 브로드캐스트로 인한 단일 서버(2GB RAM) 자원 고갈을 방지하기 위해, 1단계에서는 접속자 숫자 표시를 제외하고 `● 실시간 스트림 연결됨` 상태등만 유지한다.
4. **향후 확장 범위 (Out of Scope)**:
   - 메인 광장 대화 참여자 간 1:1 대화 신청 및 귓속말 기능은 추후 단계로 분리하며, 현재는 단일 공용 라이브톡만 지원한다.

---

## 2. 사용자 권한 및 참여 자격

| 구분 | 대화 읽기 (수신) | 대화 쓰기 (발신) | 비고 |
| :--- | :---: | :---: | :--- |
| **로그인 회원** | **허용** | **허용** | 닉네임 표시 및 실시간 전송 |
| **비로그인 방문자** | **허용 (눈팅)** | **차단** | 하단 입력창 비활성화(disabled) 및 로그인 유도 |

- 신규 방문자가 커뮤니티의 실시간 활성도를 체감할 수 있도록 비로그인 읽기는 허용하되, 불법 광고/어뷰징 방지 및 회원가입 전환을 위해 쓰기 권한은 로그인 회원에게만 부여한다.

## 3. 메시지 작성 및 도배 방지 정책

1. **글자 수 제한**:
   - 최소 1자 이상, **최대 100자 이하**로 제한한다.
   - 고밀도 컴팩트 박스(`h-56`)의 가독성을 유지하면서도 슬로프 위치, 설질, 대기 시간을 빠짐없이 담을 수 있는 최적의 길이이다.
2. **리조트 태그 옵셔널 및 지속성 정책**:
   - **선택 시 (슬로프 제보 모드)**: 사용자가 드롭다운에서 특정 리조트(`휘닉스`, `비발디`, `하이원`, `용평`, `웰팍`, `기타`)를 선택한 경우에만 해당 스키장 컬러 뱃지가 메시지 옆에 부착된다.
   - **미선택 시 (일반 잡담 모드)**: 리조트를 선택하지 않은 경우(기본값: `선택 안 함`)는 뱃지가 없는 일반 대화로 노출되어 시각적 피로도를 없앤다.
   - **브라우저 기억 (Persistence)**: 사용자가 선택한 리조트는 브라우저 로컬 저장소(`localStorage`)에 자동 저장되어 재방문 시에도 유지된다.
3. **공백 메시지 차단**:
   - 공백 문자(스페이스, 탭, 줄바꿈)만으로 구성된 메시지는 전송할 수 없다.
4. **동일 내용 반복 전송 차단 (Duplicate Content Blocking)**:
   - 직전 메시지와 공백 및 특수문자를 제거한 정규화 텍스트가 일치하는 경우(예: 끝자리 점, 공백만 바꾼 변형 도배) 발송을 즉시 취소(거부)한다.
   - 적발 시 *"동일한 메시지를 연속으로 보낼 수 없습니다 (5초간 대기)."* 에러와 함께 5초간 전송 쿨다운을 적용한다.
5. **다중 탭 도배 우회 차단**:
   - 브라우저 탭을 여러 개 열어 도배 제한을 우회하는 행위를 막기 위해, 도배 방지 쿨다운 타이머는 웹소켓 세션이 아닌 **`member_id` 기준**으로 통합 관리한다.
6. **비정상 연타 방어 (Burst Protection)**:
   - 정상적인 짧은 대화 연타는 허용하되, 기계적 매크로 난사를 막기 위해 1초 내 5회 이상 전송 시도시 연결을 일시 제한한다.

## 4. 프론트엔드 UI 및 렌더링 정책

1. **메신저형 대화 버블(Chat Bubble) 및 좌우 분할 렌더링**:
   - **상대방 메시지 (좌측 정렬)**:
     - 좌측: 리조트 약칭 원형 아바타 (`휘팍`, `비발`, `용평` 등) 또는 기본 사용자 아바타 (잡담 시)
     - 상단: `닉네임` + `리조트 컬러 뱃지` (잡담 시 뱃지 생략)
     - 말풍선: 깔끔한 흰색 라운드 박스 (`bg-white border border-slate-200`)
     - 시간: 상대 시간 표기 (`1분 전`, `2분 전`)
   - **내 메시지 (우측 정렬)**:
     - 말풍선: 은은한 하늘색 라운드 박스 (`bg-sky-50 border border-sky-100 text-sky-950`)
     - 아바타와 닉네임은 생략하여 본인 발언임을 직관적으로 표현
     - 시간: 좌측 하단에 표기 (`방금`)
2. **화면 노출 메시지 상한 (최대 100개 유지)**:
   - 메시지가 대량으로 쏟아질 때 브라우저 렉과 메모리 누수를 방지하기 위해, 화면에는 항상 **최신 100개 메시지만 DOM에 유지**한다.
   - 100개를 초과하는 가장 오래된 메시지는 메모리에서 자동으로 제거(FIFO Pruning)한다.
3. **스크롤 고정 및 새 메시지 알림 (Scroll Anchoring)**:
   - 사용자가 이전 대화를 읽기 위해 스크롤을 위로 올린 상태에서는, 새 메시지가 도착해도 스크롤을 강제로 아래로 튕기지 않는다.
   - 화면 하단에 *"새 메시지 N개 ↓"* 플로팅 버튼을 노출하고, 클릭하거나 직접 맨 아래로 스크롤했을 때만 최신 위치로 자동 이동한다.

## 5. 보안 및 컴플라이언스 정책

1. **외부 링크 및 메신저 식별자 차단**:
   - 불법 거래, 마약, 도박 및 타 플랫폼 유도를 막기 위해 다음 패턴이 포함된 메시지는 서버 인터셉터에서 전송을 거부한다:
     - URL 프로토콜 및 도메인: `http://`, `https://`, `.com`, `.net`, `.kr`, `.io` 등
     - 외부 메신저: `t.me/`, `open.kakao.com`, `@`로 시작하는 계정 아이디 등
   - 차단 시 사용자에게 *"외부 링크 및 메신저 연락처는 전송할 수 없습니다."* 안내를 반환한다.
2. **XSS (Cross-Site Scripting) 방어**:
   - 서버는 메시지 원문을 전달하고 프론트엔드는 React JSX 텍스트 노드로만 렌더링한다. HTML Entity를 서버에서 미리 만들거나 `dangerouslySetInnerHTML`로 다시 해석하지 않는다.
3. **불법 금칙어 차단**:
   - 관리자 기능에서 DB 원본과 서버 메모리 캐시를 함께 설계할 예정이며 현재 단계에서는 미구현이다. 외부 링크·메신저 식별자 차단만 적용한다.
4. **비상 셧다운 스위치 (Kill Switch)**:
   - 관리자 기능과 함께 구현할 예정이며 현재 단계에서는 미구현이다.

## 6. 데이터 영속성 및 법적 로그 보관

1. **대화 본문 완전 휘발성 (In-Memory)**:
   - 대화 텍스트 내용은 데이터베이스에 저장하지 않는다.
   - 단일 서버 메모리에서 최근 30개만 유지하므로 새로고침·재접속 시 해당 범위는 복원된다. 서버 재시작이나 재배포 시에는 모두 사라진다.
2. **통신사실확인자료 보관 (통신비밀보호법 제15조의2, 시행령 제41조)**:
   - 운영 감사와 적법한 요청 대응을 위해 채팅 연결·종료 시 다음 메타데이터만 텍스트 감사 로그 파일(`chat_audit.log`)에 비동기 기록한다:
     - `timestamp` (접속·종료 시각)
     - `event` (`CONNECT`, `DISCONNECT`)
     - `member_id` (회원 고유 식별자)
     - `client_ip` (접속 IP)
     - `channel`, `connection_id`, `close_reason`
   - 대화 본문과 메시지별 발송 기록은 남기지 않는다. Logback은 일별·100MB 단위로 압축 회전하고 운영 정책상 3개월을 충족하도록 100일 뒤 자동 삭제하며, 디스크 보호를 위해 전체 크기를 2GB로 제한한다. 비정상적인 접속 폭주로 2GB를 먼저 넘으면 오래된 파일이 100일 전에 삭제될 수 있다. 감사 로그 비동기 큐가 가득 차도 채팅 요청은 대기시키지 않으므로 일부 로그 유실 가능성을 모니터링과 외부 보관으로 보완한다. 운영 컨테이너의 `/var/log/snowthing-chat`를 EC2 호스트에 마운트한다. EC2 손실에 대비한 CloudWatch 외부 전송은 후속 운영 작업이다.
3. **로그아웃과 기존 WebSocket 연결**:
   - 정상 로그아웃 시 HTTP 세션과 연결된 WebSocket을 즉시 종료하고 세션 ID를 폐기 목록에도 기록한다. 연결 종료가 지연되더라도 후속 발신은 인증 오류로 거부한다.
   - 현재 폐기 목록은 단일 서버 메모리에 최대 10,000개, 최장 로그인 세션(30일)보다 긴 31일 동안 유지한다. 서버를 늘릴 때는 Redis로 공유해야 한다.
4. **연결 제한**:
   - 회원 한 명은 활성 연결 1개만 유지한다. 새 연결이 성공하면 기존 연결을 종료한다.
   - 서버 전체 연결은 기본 500개로 제한하고 `SNOWTHING_CHAT_MAX_CONNECTIONS`로 조정한다.
   - EC2의 80·443은 `cloudflare-ipv4` 접두사 목록만 허용한다. Nginx는 같은 공식 대역을 신뢰해 실제 사용자 IP를 복원한 뒤 `/ws-chat`의 IP당 동시 연결을 5개, 초당 신규 요청을 3개로 제한한다.
   - Cloudflare 공식 IP 목록이 바뀌면 AWS 접두사 목록과 Nginx 목록을 같은 작업에서 갱신한다.
