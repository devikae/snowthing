# 게시물 신고와 임시조치 (IKA-32)

정보통신망법 제44조의2, 제44조의3에 대응한다. 삭제 요청을 받으면 지체 없이 조치하고 신청인과 게시자에게 알리며, 조치 사실을 공시한다. 임시조치는 30일 이내다. 자동 필터링과 사전 검열은 하지 않는다.

## 대상

- 게시글(일반, 중고장터, 카풀)과 댓글. 중고장터와 카풀은 부모 `post`의 상태를 쓴다.
- 쪽지는 제외한다.
- 신고는 로그인 회원만 한다. 비회원과 외부인의 요청은 이메일로 받고, 관리자가 해당 글에서 직접 신고해 같은 절차로 처리한다.

## 상태

| 대상 | 임시조치 | 복구 | 삭제 |
|---|---|---|---|
| 게시글 | `post.status = TEMPORARY_HOLD` | `NORMAL` | 기존 `softDelete` |
| 댓글 | `is_deleted = true`, `moderation_held = true` | 둘 다 해제 | `is_deleted = true`, `moderation_held = false` |

- 글에 새 상태값을 쓴 이유: 목록, 검색, AI 조회가 이미 `status = NORMAL`로 거르므로 조회 코드를 고치지 않아도 빠진다. 기존 `HIDDEN`은 중고장터 관리자 숨김이라 다른 뜻이고 공시 문구를 구분할 수 없다.
- 댓글에 삭제 상태를 재사용한 이유: 댓글을 읽는 경로가 많아 새 상태를 쓰면 빠뜨리기 쉽다. 표시 문구만 "임시조치된 댓글입니다."로 다르게 한다.

## API

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| POST | `/api/v1/reports` | 로그인 | 신고. 중복 409 |
| GET | `/api/v1/admin/reports?status=PENDING&page=0` | 관리자 | 신고 목록. ID 내림차순 |
| POST | `/api/v1/admin/reports/{reportId}/actions` | 관리자 | 조치. 같은 대상의 대기 신고를 모두 처리한다 |

조치 종류는 `TEMPORARY_HOLD`(1~30일), `RESTORE`, `DELETE`, `DISMISS`다. 임시조치된 글의 상세는 일반 사용자에게 403 `POST_009`와 안내 문구를 돌려줘 공시한다.

## 통지

`MODERATION_RESULT` 알림을 신고자와 작성자에게 보낸다. 작성자에게 신고자를 알리지 않는다. 비회원 글은 통지할 수 없어 게시물 자리의 안내로 갈음하며, 약관 제5조에 적었다.

## 기간 만료

매시간 만료된 임시조치를 찾아 복구하고 작성자에게 알린다. 그 사이 삭제된 대상은 복구하지 않고 해제 시각만 기록한다.

## 한계

- 관리자 조치와 정기 복구가 동시에 일어나면 나중 쪽이 이긴다. 관리자가 한 명이고 시간당 1회라 잠금을 두지 않았다.
- 작성자의 글 수정이 임시조치와 겹쳐도 상태를 덮어쓰지 않도록 `Post`는 바뀐 컬럼만 쓴다(`@DynamicUpdate`).
- 임시조치는 NORMAL 상태에서만 건다. 관리자가 숨긴 글은 복구 때 공개되면 안 되기 때문이다. 임시조치 중에는 중고장터 관리자 숨김 API를 막는다.
- 만료 시각은 상한에서 2시간을 뺀다. 복구 작업이 매시간 돌아도 30일을 넘지 않는다.
- 작성자는 임시조치 중에도 자기 글을 삭제할 수 있다. 신고 목적과 충돌하지 않는다. 대상이 사라지면 관리자는 기각으로 대기 신고를 정리하며 신고자 통지는 없다.
- 처리가 끝난 신고는 같은 회원이 다시 낼 수 있다. 같은 행을 다시 연다.
- 기존 중고장터 관리자 숨김 API는 이력을 남기지 않는다. 범위 밖이다.
- 불법촬영물은 규모 기준상 사전 조치 대상이 아닐 가능성이 높으나, 신고가 오면 임시조치가 아니라 삭제로 처리하는 운영 기준이 필요하다.
