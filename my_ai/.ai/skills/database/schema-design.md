# Database Schema Design Skill

## 기본 원칙

- 테이블은 도메인 규칙과 조회/수정 패턴을 함께 고려하여 설계한다.
- PK, FK, Unique, NOT NULL 같은 무결성 규칙을 애플리케이션 코드만으로 대체하지 않는다.
- N:M 관계는 의미 있는 중계 테이블로 명시적으로 모델링한다.
- 상태값은 의미와 확장성을 고려해 타입을 정한다.

## 컬럼 설계

- 문자열 길이를 무조건 VARCHAR(255)로 통일하지 않는다.
- 금액에 floating point 타입을 사용하지 않는다.
- 시간대가 중요한 날짜/시간은 timezone 정책을 명확히 한다.
- soft delete 사용 시 모든 조회/unique constraint/복구 정책에 미치는 영향을 검토한다.

## 정규화와 비정규화

- 기본적으로 중복과 갱신 이상을 줄이도록 정규화한다.
- 성능 때문에 비정규화하면 어떤 데이터가 원본이며 어떻게 정합성을 유지할지 정의한다.
