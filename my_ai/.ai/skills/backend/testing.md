# Backend Testing Skill

## 원칙

- 테스트는 구현 후 장식이 아니라 변경 안전망으로 취급한다.
- 단위 테스트, 슬라이스 테스트, 통합 테스트, E2E 테스트의 목적을 구분한다.
- 모든 것을 Mock으로 대체하지 않는다.
- 반대로 모든 테스트를 Spring Context 전체 로딩으로 만들지 않는다.

## 대상별 기준

- Domain: 순수 단위 테스트 우선
- Service: 비즈니스 흐름과 경계 조건 검증
- Repository: 실제 쿼리/매핑이 중요하면 DB 기반 테스트
- Controller/API: 요청 검증, 상태 코드, 응답 계약 검증
- Security: 인증 여부, 권한별 접근 가능/불가능 케이스 검증

## 반드시 포함할 케이스

- 정상 흐름
- 경계값
- 잘못된 입력
- 존재하지 않는 리소스
- 권한 없음
- 중복 요청
- 동시성 문제가 가능한 경우 경쟁 조건

## 금지

- 테스트를 통과시키기 위해 실제 요구사항을 약화하지 않는다.
- 내부 구현 세부사항만 지나치게 검증하여 리팩터링에 취약한 테스트를 만들지 않는다.
- 실제 검증하지 않은 동작을 테스트했다고 보고하지 않는다.
