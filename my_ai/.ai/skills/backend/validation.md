# Validation Skill

## 검증 계층 구분

입력 검증과 비즈니스 규칙 검증을 구분한다.

### 입력 형식 검증

Controller/Request DTO 수준에서 처리한다.

예:
- null 여부
- 문자열 길이
- 이메일 형식
- 숫자 범위
- 날짜 형식

### 비즈니스 규칙 검증

Service 또는 Domain 계층에서 처리한다.

예:
- 이미 가입한 회원인지
- 현재 상태에서 취소 가능한지
- 재고가 충분한지
- 작성자 본인인지

## 규칙

- 프론트엔드 검증만 믿지 않는다. 서버에서도 반드시 검증한다.
- Bean Validation Annotation만으로 비즈니스 정책 전체를 해결하려 하지 않는다.
- 같은 검증 규칙이 여러 곳에서 반복되면 책임 위치를 재검토한다.
- nullable 여부와 Optional 여부를 명확히 한다.
- 빈 문자열, 공백 문자열, null을 서로 다른 값으로 취급해야 하는지 정의한다.
- 숫자/금액/비율 범위를 명확히 제한한다.
- 파일 업로드 시 확장자만 믿지 않고 MIME, 크기, 실제 처리 가능 형식 등을 함께 검토한다.
