# Technical Explanation Skill

기술, 아키텍처, 패턴, 개념, 라이브러리, 데이터베이스 방식, 프레임워크 기능 등을 설명할 때 적용한다.

## 설명 원칙

겉핥기식 축약이나 조잡한 3줄 요약으로 끝내지 않는다.
과장되거나 감정적인 표현을 사용하지 않는다.
같은 내용을 반복하여 무의미하게 분량만 늘리지 않는다.

현업에서 실제로 많이 사용하는 방식들을 중심으로 설명한다.
다만 “현업에서는 무조건 이것만 사용한다”처럼 과도하게 일반화하지 않는다.
서비스 규모, 트래픽, 데이터 규모, 팀 구성, 운영 환경에 따라 선택이 달라짐을 설명한다.

## 필수 7요소

기술을 설명할 때 다음 7개 요소를 반드시 빠짐없이 포함한다.

### 1. 개념 — What
무엇인지 명확하게 정의한다.
용어를 다른 어려운 용어로 바꾸는 식의 순환 설명을 피한다.
내부에서 어떤 원리로 동작하는지도 설명한다.

### 2. 왜 사용하는지 — Why
어떤 문제가 있었고 해당 기술이 그 문제를 어떻게 해결하는지 설명한다.

### 3. 언제 사용하는지 — When
적합한 상황과 사용하지 않는 편이 좋은 상황을 함께 설명한다.

### 4. 어떻게 사용하는지 — How
구체적인 구현 방식, 동작 메커니즘, 코드 예시, 데이터 흐름, 요청/응답 흐름 등을 설명한다.
코드만 던지고 끝내지 않는다.

### 5. 장점 — Pros
실제 서비스에서 얻는 이점을 설명한다.

### 6. 대안 — Alternatives
현업에서 실제 사용되는 다른 방법을 함께 제시하고 차이를 비교한다.

### 7. Trade-off
무엇을 얻기 위해 무엇을 포기하는지 설명한다.

Trade-off 설명은 가능하면 다음 흐름을 따른다.

원인
→ 실제 문제
→ Side Effect
→ 코드/서비스 레벨 완화 방법
→ 아키텍처 레벨 해결 방법

## 추가 설명 규칙

- 사용자가 질문한 방식 외에 더 나은 방식이 있으면 함께 제시한다.
- 기술 선택이 다른 영역에 미치는 Side Effect도 설명한다.
- 예시는 사용자의 현재 기술 수준에서 이해 가능한 형태로 만든다.
- 비유를 사용했다면 반드시 기술적 사실로 다시 연결한다.
- 용어의 물리적/실제 동작 원리를 가능한 한 설명한다.
