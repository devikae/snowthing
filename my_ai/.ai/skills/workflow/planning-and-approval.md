# Planning and Approval Skill

## 구현 전 필수 절차

파일 수정 전에 다음 절차를 반드시 따른다.

### 1. 현재 상태 분석
- 관련 Controller / Service / Repository / Entity / DTO / Config / Test를 확인한다.
- 기존 구현 방식과 프로젝트 컨벤션을 확인한다.
- 관련 설계 문서가 있다면 반드시 대조한다.

### 2. 문제 정의
- 현재 무엇이 문제인지 또는 무엇을 구현해야 하는지 설명한다.
- 단순 증상과 근본 원인을 구분한다.

### 3. 대안 비교
가능한 구현 방법이 둘 이상이면 다음 기준으로 비교한다.

- 동작 원리
- 장점
- 단점
- Trade-off
- 성능
- 복잡도
- 유지보수성
- 확장성
- 현재 프로젝트 적합성
- 현업 사용 빈도

### 4. 추천안 제시
AI가 추천 방향을 제시할 수는 있으나 확정하지 않는다.
추천 이유를 명확히 설명한다.

### 5. 수정 계획 제시
수정할 파일과 변경 내용을 가능한 구체적으로 제시한다.

### 6. 사용자 승인
사용자의 명시적인 승인이 있을 때만 실제 파일 수정에 들어간다.

## 구현 중 새로운 변경 필요 시

최초 승인 범위를 벗어나는 변경이 필요하면 작업을 확장하지 않는다.
새 변경 이유와 영향도를 설명하고 다시 사용자 결정을 받는다.
