# Study Memory Skill

## 목적

개발 중 사용자가 나중에 따로 공부하고 싶은 내용을 기억해 두었다가, 요청 시 학습 문서로 정리한다.

## 기억 대상

사용자가 다음과 같은 표현을 하면 학습 백로그에 반드시 누적한다.

- 기억해둬
- 나중에 공부할 거야
- 이것도 정리할 때 넣어
- 나중에 설명해줘
- 나중에 공부자료 만들 때 포함해

사용자가 기억을 요청한 내용은 임의로 일부만 선택하거나 버리지 않는다.

## 정리 명령

사용자가 다음과 같은 요청을 하면 누적된 학습 항목을 정리한다.

- 아까 기억하라고 한 것들 정리해줘
- 공부자료로 만들어줘
- 노션에 붙여넣게 정리해줘
- 학습 문서로 만들어줘

## 저장 위치

학습 문서는 `docs/` 내부에 저장한다.
프로젝트에서 별도의 학습 문서 경로가 정해져 있다면 그 프로젝트 규칙을 우선한다.

기본 권장 경로:

`docs/study/`

## 파일명 규칙

파일명은 반드시 다음 형식을 사용한다.

`study{YYMMDD}-{메인토픽}-{서브토픽}.md`

예시:

- `study260824-JPA-페이징.md`
- `study260824-스프링시큐리티-필터체인.md`
- `study260824-데이터베이스-인덱스.md`
- `study260824-JPA-N플러스1.md`

### 파일명 세부 규칙

1. 날짜는 `YYMMDD` 형식으로 사용한다.
2. 메인토픽과 서브토픽은 가능한 한 한글을 우선 사용한다.
3. 공식 기술명 또는 영문 약어를 한글로 바꾸면 오히려 의미가 불명확해지는 경우 원래 표기를 사용한다.
   - JPA
   - JWT
   - DTO
   - API
   - SQL
   - Redis
4. 공백은 사용하지 않고 `-`로 구분한다.
5. 너무 많은 키워드를 파일명에 넣지 않는다.
6. 하나의 학습 문서가 여러 주제를 포함하더라도 가장 대표적인 메인토픽과 서브토픽을 선택한다.

## 문서 작성 규칙

사용자가 질문한 내용만 기계적으로 모으지 않는다.

각 주제별로 다음을 포함한다.

1. 개념
2. 왜 사용하는지
3. 언제 사용하는지
4. 어떻게 동작하고 사용하는지
5. 코드 또는 구체적인 예시
6. 장점
7. 대안
8. Trade-off
9. Side Effect
10. 현업에서 주로 사용하는 방식
11. 현재 프로젝트와 연결되는 포인트
12. 추가로 공부하면 좋은 내용

노션에 그대로 붙여넣어도 읽기 좋은 Markdown 문서로 만든다.
