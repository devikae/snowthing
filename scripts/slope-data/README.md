# 슬로프 제원과 코스 맵 데이터

슬로프맵(`/slopes`) 화면이 쓰는 데이터를 만드는 곳이다. 리조트 공식 제원과 OpenStreetMap(OSM) 선을 합쳐 두 가지를 만든다.

| 결과 | 위치 | 쓰는 곳 |
|---|---|---|
| 슬로프 제원, 슬로프 사이 관계 | `database/production/055_migration_slope_data.sql` | `slope`, `slope_connection` 표 |
| 리조트별 코스 맵 선 | `frontend/public/slope-maps/{resort-code}.json` | 코스 카드, 전체 맵 |

두 결과 파일은 손으로 고치지 않는다. 아래 입력을 고친 뒤 스크립트로 다시 만든다. 설계와 결정 이유는 `docs/conception/033_slope_compare/01_design.md`에 있다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `specs/kr_*.json`, `specs/jp_*.json` | 리조트 공식 사이트에서 정리한 제원. 파일 이름이 `jp_`로 시작하면 일본 리조트 |
| `osm/{RESORT_CODE}.json` | Overpass API 응답(슬로프 선, 리프트 선) |
| `manual/{RESORT_CODE}.json` | 공식 슬로프맵을 보고 OSM 선과 직접 짝지은 표, 직접 그린 선 |
| `build_slope_data.py` | 생성 스크립트 |
| `render_osm.py` | OSM 선에 ID를 붙인 확인용 그림 |
| `grid_overlay.py` | 공식 슬로프맵 위에 좌표 격자를 겹친 그림 |
| `verify_map.py` | 만들어진 코스 맵을 슬로프 이름과 함께 그린 확인용 그림 |

## 다시 만들기

```bash
python -X utf8 scripts/slope-data/build_slope_data.py
```

- 저장소 루트에서 실행한다. 리조트마다 `슬로프 수, OSM 연결 수, 맵 있음`을 출력한다.
- 모든 리조트를 다 만든 뒤에만 파일을 쓴다. 중간에 실패하면 기존 맵과 SQL은 그대로 남는다.
- 맵을 만들지 못한 리조트의 예전 맵 파일은 지운다.
- 055가 운영에 적용된 뒤에는 이 파일을 고칠 수 없다(마이그레이션 실행기가 파일 체크섬을 기록한다). 그 뒤에 데이터를 바꾸려면 새 번호 마이그레이션을 만든다.

## 제원(specs) 규칙

슬로프 한 건의 모양:

```json
{
  "resortCode": "HIGH1",
  "name": "제우스 Ⅰ",
  "nameLocal": null,
  "officialDifficulty": "초급",
  "lengthM": 2328,
  "avgGradient": 9.48,
  "maxGradient": 13.6,
  "widthM": 41.3,
  "liftName": null,
  "sourceUrl": "https://www.high1.com/ski/slopeView.do?key=748&mode=p",
  "note": "확인할 점이나 원래 표기"
}
```

- 숫자는 리조트 공식 사이트나 공식 사이트가 부르는 API에서만 가져온다. 블로그, 여행사, 위키는 쓰지 않는다.
- 공식 값이 없으면 `null`로 두고 추정하지 않는다. 화면은 "미공개"로 보인다.
- 경사는 도(°) 단위다. 공식이 %로만 공개하면 `avgGradientPercent`, `maxGradientPercent`에 넣는다. 스크립트가 각도 = atan(% / 100)로 바꾼다. 공개 %가 그 슬로프의 표고차, 길이와 크게 어긋나면(예: 알펜시아) % 칸을 두지 않는다.
- 평균인지 최대인지 표기가 없는 경사(예: 지산 "경사도")는 넣지 않는다. 비슷한 슬로프 찾기가 같은 지표끼리만 비교하기 때문이다.
- 공식 평균이 최대보다 크면 오타로 보고 평균을 비운다.
- 리프트는 공식 사이트가 그 슬로프의 리프트라고 밝힌 경우에만 넣는다. 이름으로 짐작하지 않는다.
- 난이도 묶음(초급, 중급, 상급, 최상급)은 `officialDifficulty`에서 스크립트가 정한다. 새 표기가 나오면 `DIFFICULTY` 표에 더한다. 모르는 표기가 있으면 스크립트가 멈춘다.
- 다른 리조트 쪽 코스나 연결 통로처럼 넣지 않을 슬로프는 `EXCLUDE`에 적는다.

## OSM 선 받기

리조트 범위(남, 서, 북, 동)를 정해 Overpass API에서 받는다.

```
[out:json][timeout:90];
(way["piste:type"="downhill"](37.17,128.78,37.24,128.87);
 way["aerialway"](37.17,128.78,37.24,128.87););
out geom tags;
```

- 결과를 `osm/{RESORT_CODE}.json`으로 저장한다. 리조트가 여러 산에 걸치면(루스츠) 범위를 넉넉히 잡는다.
- 이웃 리조트와 산을 나눠 쓰면(니세코) 같은 이름의 코스가 섞인다. 연결된 선의 중심에서 먼 선은 버리는데, 그 반경은 `CLUSTER_RADIUS_M`에서 리조트별로 정한다.
- OSM 데이터는 ODbL이다. 맵이 나오는 모든 화면에 출처를 표기한다(맵 파일의 `attribution`).

## 공식 이름과 OSM 선 맞추기

스크립트는 아래 순서로 슬로프마다 선을 찾는다.

1. `manual/{CODE}.json`에 적힌 짝이 있으면 그것을 쓴다.
2. 이름 맞추기: 띄어쓰기, 로마 숫자(Ⅰ→1), 전각 문자, 괄호 설명, "코스" 같은 말, 앞에 붙은 코스 번호(나에바 `D1`)를 지우고 비교한다. 글자만 다른 경우는 `ALIASES`에 적는다.
3. 숏컷, 우회처럼 다른 코스를 뜻하는 말(`SEPARATE_COURSE_WORDS`)이 OSM 이름에만 있으면 같은 코스로 보지 않는다.
4. 선으로 그린 슬로프가 없으면 면(area)으로 그린 슬로프의 가운데 선을 쓴다. 가운데 선의 ID는 음수 OSM ID다. 모양이 애매한 면(U자 등)은 가운데 선을 만들지 않는다.

### manual 파일

값은 형식을 보여 주는 예시다.

```json
{
  "_source": "짝짓기에 쓴 공식 슬로프맵 주소",
  "_unresolved": {"슬로프 이름": "선을 찾지 못한 이유"},
  "제우스 Ⅱ": [535760428],
  "델타 D+": [-1036240371],
  "그램(구 하늬)": {"drawPx": [[1745, 1068], [1530, 1210]]},
  "제우스 Ⅲ-1": {"draw": [[37.2032, 128.8311], [37.1985, 128.8302]]},
  "_anchors": [{"px": [1100, 470], "lat": 37.3361, "lon": 127.2921, "what": "익시오 리프트 하단"}]
}
```

- `_`로 시작하는 키는 설명이라 스크립트가 읽지 않는다(`_anchors`, `_lifts`만 예외).
- way ID 목록은 그 리조트 OSM 파일에 있는 ID여야 한다. 없는 ID가 있으면 스크립트가 멈춘다.
- OSM에 선이 없는 슬로프는 공식 슬로프맵을 보고 그린다(국내 리조트, 사용자 결정). 그린 선이 있는 리조트는 맵 출처에 "일부 코스는 리조트 공식 슬로프맵을 보고 눈팅이 그림"이 붙는다.
  - `drawPx`: 공식 맵 픽셀 좌표로 정상에서 베이스 방향으로 찍는다. `_anchors`(공식 맵과 OSM 양쪽에 있는 지점, 3개 이상, 한 직선 위에 있으면 안 됨)로 맞춘 1차 변환이 위도, 경도로 바꾼다.
  - `draw`: 위도, 경도를 직접 적는다. 맵 왜곡이 심해 기준점 변환이 맞지 않을 때 OSM 선과 리프트를 기준으로 옮겨 적는다.
- 공식 맵 이미지는 저장소에 넣지 않는다. 좌표만 남긴다.

### 리프트 이름과 이용 리프트

맵은 슬로프를 누르면 타는 리프트와 타는 곳(리프트 선의 첫 점, OSM은 아래에서 위로 그린다)을 보여 준다. 슬로프의 `liftName`과 맵 리프트 이름을 글자로 맞춘다(괄호 설명, "리프트", 띄어쓰기는 빼고 비교하고, "곤도라"는 "곤돌라"로 본다).

- `manual/{CODE}.json`의 `"_lifts": {"OSM 리프트 way ID": "공식 리프트 이름"}`가 OSM 리프트 이름을 덮어쓴다. 값이 `null`이면 리프트가 아닌 선(탑승장 면, 역 건물)이라 맵에서 뺀다. 출처는 `_lifts_source`에 적는다.
- 리프트 이름은 공식 리프트 안내나 공식 슬로프맵에서만 가져온다. 어느 OSM 선인지는 공식 맵의 위치와 공식 길이로 맞춘다. 확인할 수 없으면 적지 않는다(이름 없이 타는 곳 표시만 나온다).
- 슬로프의 `liftName`은 공식 안내의 이용 리프트를 먼저 쓰고, 안내가 없으면 공식 슬로프맵에서 슬로프 출발점에 닿는 리프트를 읽는다. 어느 쪽인지 `note`에 적는다.
- 맵에 선이 없는 리프트(예: 용평 뉴옐로우, 오투 애플)도 공식 이용 리프트면 `liftName`에 남긴다. 안내 줄에는 나오고 맵 강조만 없다.

### 확인 도구

```bash
# OSM 선과 ID 보기 (보라 점선은 면 슬로프 가운데 선, ID는 음수)
python -X utf8 scripts/slope-data/render_osm.py KONJIAM /tmp/konjiam.html

# 공식 맵에 좌표 격자 겹치기 (PDF면 150dpi로 바꾼 <출력>.base.png 좌표를 쓴다)
python -X utf8 scripts/slope-data/grid_overlay.py konjiam_map.jpg /tmp/grid.png 50 0,0,1000,800

# 결과 확인 (파랑: OSM 선, 주황: 그린 선, 회색: 짝없는 선)
python -X utf8 scripts/slope-data/verify_map.py KONJIAM /tmp/verify.png
```

## 슬로프 사이 관계

슬로프 선끼리 거리로 자동 판정한다. 25m 안이면 붙어 있는 것으로 보고 어느 끝이 닿는지로 합류, 갈라짐, 이어짐, 갈라져 시작, 출발점 공유, 도착점 공유, 교차를 나눈다. 90m 안이면 나란히(거리 포함)다. 한 쌍은 양쪽 줄이 서로 맞물리게 함께 만든다(합류와 이어짐, 갈라짐과 갈라져 시작). 자동 판정이라 사람의 검수가 남아 있다.

## 리조트 추가 순서

1. `054` 이후 새 마이그레이션으로 `resort`에 리조트를 넣는다(일본은 `country='JP'`, `is_active=FALSE`).
2. 공식 제원을 `specs/`에 넣는다.
3. OSM 선을 받아 `osm/`에 넣는다.
4. 스크립트를 돌리고 `OSM 연결` 수를 본다. 빠진 슬로프는 `render_osm.py`와 공식 맵으로 `manual/`에 짝을 적고, 선이 없으면 그린다.
5. `verify_map.py`로 공식 맵과 비교한다.
6. 055가 운영에 적용된 뒤라면 바뀐 부분을 새 번호 마이그레이션으로 옮긴다.
